# Project Guardrails

## Semantic Anchors
- **UI mirrors HW (1:1 alignment, HIGH PRIORITY)**: the UI must render hardware components at the same positions as on the physical modules — the user performs live mixes and must be able to grab the SAME button in the UI and on the hardware at any moment without abstraction. The goal is **recognizability, not reproduction**: keep 100% of the geometric arrangement (relative positions, ordering, adjacency, grid structure — which control sits where relative to its neighbors, which panel is where), but simplify the visual representation (existing glyphs, labels, colors — never a literal copy of the physical part). Grids are fixed to hardware geometry per controller (never terminal-width-derived), panels follow physical rack positions, and each element's built-in LED is joined positionally to its element (L1.1 bound to B1.1). "Built-in" means the controller's physical design, not what the patch happens to declare. The `kitty-gfx` Cargo feature (default since 2026-09, the graph-surface renderer) is the escape hatch to bring more UI in if terminal stacking cannot deliver the mirror.
- **YAGNI**: every type, variant, derive, and trait in `src/` must have a current consumer — dead code is deleted on sight, not preserved for "future" use. Speculative features (persistence, hardware bridge) are deferred ideas; introducing them requires an OpenSpec change.
- **DRY**: one source of truth per fact. Generated docs (ARCHITECTURE.md, DESIGN.md, guardrails) are derived artifacts — edit code and regenerate via `/make-*`, never hand-edit generated docs. The circuit schema (`ext/droid-lsp/droid-lsp/src/circuits.json`) and the rack layout (`rack_geometry.json`) are single-source build-time inputs — never fork a copy inside `src/`.
- **CodeAsDoc**: names carry DROID domain meaning; doc comments explain non-obvious invariants and reasons, never restate code (AGENTS.md); OpenSpec specs are the behavior contract, code is the executable spec.
- **TDD London** (mockist, outside-in): test through public entry points (`handle_event`, `render`, `validate_patch`, `diff_patches`); use real fixtures for cheap deterministic collaborators (filesystem, terminal); mock only genuinely costly or unreliable boundaries — none today. Keep the renderer→handler geometry handoff (`component_rects` + `graph_node_rects`/`graph_cluster_rects` + `physical_skeleton_rects`/`physical_rack_size`) collaboration tested.

## Design System
- Semantic colors (ANSI 16, terminal-dependent): component kinds — button/switch white, knob/encoder magenta, CV-in cyan, CV-out green, LED red; shift groups — 1 yellow, 2 cyan, 3 magenta, 4 green; accents — blue (header/picker/sidebar borders), dark-gray (muted/content/minimap/status background); source view — occurrences yellow, boolean/transitive modifier highlights cyan, exact-value modifier highlights magenta, current occurrence reversed. Graph surface dim tokens: `graph_node_dim` (gray classic / black mono) and `graph_edge_dim` (dark-gray classic/mono) render disabled circuits dim; `switch` token keeps switches tellable apart from buttons (dark-gray in mono, white in classic). The `dim` modifier is also the global paused-panel treatment (`processing_paused`).
- Latency ramp: `graph_edge_latency_0`–`_4` (classic blue→cyan→green→yellow→red; mono grayscale `white`→`gray`→`dark-gray`→`black`→`black`; terminal all `Reset`) + `graph_edge_latency_legend` (blue classic, gray mono) — edge color precedence when diff/latency/topology compete is `graph_edge_error` red > diff colors > latency ramp > `CableKind` inference > dim; latency toggle `c` on the graph surface replaces kind color for non-error, non-diff cables. Status appends `latency avg X / max Y (1 loop ≈ 190µs) | N back edge(s)` and hovering a back-edge sink shows `reads _X 1 loop behind`.

## Domain-Specific: DROID
- Hardware tokens: `B` button, `L` LED, `P` pot, `O` CV out, `I` CV in, `E` encoder, `S` switch, `G` gate, `M` fader (mapped to `Knob` kind), each followed by a digit address (e.g. `B1.1`, `P1.1`, `M1.1`). Controllers: P2B8, Faderbank, Notebuttons, Encoder, Pot, Unusedfaders, etc. — component grouping mirrors physical panels; `module_types`/`needs_by_type`/`master_requirement` expose rack-recognition for validation.
- Controllers: P2B8, Faderbank, Notebuttons, Encoder, Pot, Unusedfaders, etc. — component grouping mirrors physical panels. Physical controller geometry lives in `controller_geometry.json` with fallback width + warn (physical D6).
- Authoritative circuit schema: `ext/droid-lsp/droid-lsp/src/circuits.json` (vendored git submodule, embedded at build time via `schema.rs`) — the single source of truth for circuit names, params, jacks, presets, and RAM sizes; the validation checks are ported 1:1 from `ext/droid-lsp/droid-lsp/src/diagnostics.ts`. Run `git submodule update --init` before building; do not commit the checkout. `circuit-plugin-system` extends it at runtime via XDG TOML plugins (see below) without editing the submodule or rebuilding.
- Rack geometry: `rack_geometry.json` at the repo root describes the physical rack (Rack/ControllerSlot layout); wiring-outlier detection is a learned decision table (`WiringOutlierScorer` over `BindingFeatures` from `corpus/features.csv` via `tools/fit_outlier_model.py`) plus an `InfluenceStats` z-score second opinion (per-token `influence_subtree` size vs per-kind corpus mean/std, band 3.0) — each `Warning` reuses `graph_edge_error` red without gating the load. Invariant guards (adjacent / co-located / via-cable) stay at the call site before the scorer; threshold fallback (`8.0`) is preserved on table miss.
- Physical rack: `RackSpec`/`RackLayout` (`he`/`hp` rows, `top_mount_te`/`side_mount_te`, per-module `assign` overrides) packs the 1:1 mm view (`physical.rs`); controller faceplate geometry in `controller_geometry.json` maps hardware grids to mm; `ScreenMapping` (aspect-compensated) → screen cells with pan/zoom; fold bars at row boundaries; full and skeleton presentations share the same `ScreenMapping` (5.1 coincidence proof).
- Circuit plugins: `$XDG_CONFIG_HOME/droid-tui/plugins/*.toml` (or `[plugins] dir` override) — each `[[circuit]]` declares `name` (case-insensitive), `category`, required `ramsize`, optional `title`/`description`/`cable_kind` (`control`/`audio`/`midi`/`unknown`) / `color` (ThemeColor token), and `inputs`/`outputs` with `prefix`/`count`/`start_at` expansion; files load in sorted-filename order, insert-or-override on collision (warn-once shadow per file), malformed/missing-ramsize files skipped with one warning (never aborts startup); `schema::merge_plugins` applies the overlay deterministically; rendering consults declared `cable_kind`/`color` first, substring inference as fallback.
- DROID reference skills: `droid-patch-format` (token grammar, RAM sizes, circuit catalog), `droid-circuit-reference`, `droid-patch-cookbook` (global), `droid-knowledge-base` (RAGFlow manual search, 1013 chunks, search app `bfc81d86a28911f19d893d24d8da86cf` on nuc25).
- Virtual cables: signal wiring runs over named cables starting with `_` (e.g. `_PULSARCLOCK`); a circuit produces one via `output = _NAME`, any number of other circuits consume it via params like `input = _NAME`. Valid topology: 1 source feeds n sinks; n sources into one sink is invalid (the graph's topology validation flags it `Error`; dangling sink is `Warning`; unused production is fine). Direct token references (`out1 = B1.1`) are valid but rare. Cable attribution is by section name (first-instance resolution); instance-accurate attribution is the topology pass's concern.
- Forward-loop latency: each edge's latency in loop units is the source circuit's `AVG` (ramsize-proportional via `CostModel`, overridable per circuit in `[latency] per_circuit`) when the sink runs after the source, else `AVG × N` (back edge = hottest); the latency ramp (`graph_edge_latency_0`–`_4`) visualizes it, toggle `c` on the graph surface. Optimizer proposes reorderings minimizing `Sum((t-s) mod N)*AVG` (weighted linear arrangement) with banner-preserving vs global vs min-max candidates.
- Kit protocol (kitty graphics): the graph surface's anti-aliased image path uses raw `\x1b_G` escapes (base64 + zlib, `f=32` RGBA, chunked ≤ 4096 bytes) with terminal capability detection (`KITTY_WINDOW_ID` + DA1/`i=31`); `kitty-gfx` is a default feature so kitty is the default renderer, box-drawing the fallback. Rasterizer deps are unconditional; only the emit is gated. Every pixel color derives from theme tokens via `Theme::rgb` with the existing precedence.
