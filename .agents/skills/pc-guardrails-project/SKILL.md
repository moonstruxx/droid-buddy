# Project Guardrails

> Auto-generated by `/make-guardrails`. Regenerate with the same command when architecture or conventions change significantly.

## Semantic Anchors
- **UI mirrors HW (1:1 alignment, HIGH PRIORITY)**: the module UI renders hardware components at the same positions as on the physical modules — the user mixes live and must be able to grab the SAME button in the UI and on the hardware at any moment without abstraction. The goal is **recognizability, not reproduction**: keep 100% of the geometric arrangement (relative positions, ordering, adjacency, grid structure — which control sits where relative to its neighbours, which panel is where) and simplify the representation (glyphs, labels, semantic colours — never a literal copy of a physical part). Grids come from embedded per-controller geometry, never from window width; panels follow physical rack positions; an element's built-in LED is joined to it positionally (`L1.1` with `B1.1`), "built-in" meaning the controller's physical design, not what the patch happens to declare. The chain it draws is the rack's own contents — the configured module inventory — with the patch distributed onto it, so a patch that stays silent can never hide hardware that is physically there. The egui window is the only rendering surface; there is no terminal fallback.
- **YAGNI**: every type, variant, derive and trait in `src/` must have a current consumer — dead code is deleted on sight, not kept for "future" use. Speculative features (persistence, hardware *receive*/firmware flows, terminal fallback) are deferred ideas; introducing one requires an OpenSpec change (the one-way SysEx send arrived that way via `midi-upload`).
- **DRY**: one source of truth per fact. Generated docs (`ARCHITECTURE.md`, `DESIGN.md`, this skill) are derived artifacts — edit code and regenerate via `/make-*`, never hand-edit them. The circuit schema (`ext/droid-lsp/droid-lsp/src/circuits.json`) and the geometry data (`rack_geometry.json`, `controller_geometry.json`) are single-source build-time inputs — never fork a copy inside `src/`.
- **CodeAsDoc**: names carry DROID domain meaning; doc comments explain non-obvious invariants and reasons, never restate code; OpenSpec specs are the behaviour contract and code is the executable spec.
- **TDD London** (mockist, outside-in): test through public entry points (`handle_event`, `validate_patch`, `diff_patches`, the gui spec/paint builders); use real fixtures for cheap deterministic collaborators (the filesystem); mock only genuinely costly or unreliable boundaries — there are none today. The one true collaboration contract to keep tested is the renderer→handler geometry handoff: `component_rects`, `pane_hit_rects`, `graph_canvas_px` (the graph hit-tests world-space through its camera instead of publishing rects).

## Architecture Constraints
- **Stack and entry**: Rust 2021, one binary crate `droid_tui` (no `[features]`); native winit 0.30 + egui 0.36 + wgpu 30. `src/main.rs` owns the single `EventLoop` through `AppHandler: ApplicationHandler` and is the only place that opens the window (`queue_startup_window_open`); a startup open failure, or a loop that ends without a window, is a non-zero exit. There is no async runtime, no network and no terminal/crossterm stack.
- **Dependency direction is one-way**: `gui` and `handler` depend on `app`, `patch` and the pure models; `app` depends on `patch`, `rack`, `graph`, `layout`, `latency`, `optimize`, `panes`, `physical`, `plugin`, `schema`, `validation`, `diff`, `geometry`, `events`, `graph_render`, `store`, `config`, `platform`; `graph` depends on `patch`, `geometry`, `latency`; `layout` on `graph`; `rack` on `patch` + `schema`; `store`/`platform`/`panes`/`expression`/`help`/`sysex`/`performance` are standalone. `patch` must not import `app`, `handler`, `gui`, `graph`, `layout`, `events`, `validation`, `schema`, `diff`, `geometry`, `latency`, `optimize`, `panes`, `performance`, `sysex`, `physical`, `plugin`, `graph_render`, `platform`, `rack`, `store`. A new module is wired in `src/lib.rs` and stays pure unless it is a `gui/` surface.
- **Pure means pure**: `graph`, `graph_anim`, `layout`, `events`, `expression`, `help`, `validation`, `schema`, `diff`, `geometry`, `latency`, `optimize`, `panes`, `performance`, `sysex`, `physical`, `rendermetrics`, `plugin`, `rack`, `store` have **no window dependency, no runtime I/O and no `App` parameter**. Schema and geometry data enter through `include_str!` at compile time (`circuits.json`, `rack_geometry.json`, `controller_geometry.json`, `tools/outlier_artifact.txt`, `tools/influence_stats.txt`, `tools/render_artifact.txt`); their regression tests reject `CARGO_MANIFEST_DIR` and `std::fs` in the production half. Never add an `egui`/`winit` import or an `App` argument to a pure module.
- **One source of truth per fact (the seams)**: `platform::config_dir*` for every user-data path (config, labels, favourites, plugins — no fourth XDG copy, no per-module `cfg(windows)`); `store` for the TOML rules (read/atomic write/canonical key); `App::master_model()` for the master model; `RackSpec::module_keys` for the rack inventory (the only reader of `RackRow.modules`); `App::pane_geometry` for pane rects; `rack::resolve` for master fit; `Patch::folded_led_for_element` for LED binding; `Patch::display_label`/`circuit_label` for labels; `layout::estimated_widths` for node world widths; `gui::drawn_world_sizes` for drawn/hit graph widths; `theme::active()` for colours. Add a field that mirrors one of these and the two will drift.
- **Renderer→handler geometry**: the painters publish per frame — `component_rects` (module-UI cells, cleared and refilled by `paint_panes`), `pane_hit_rects` (from `App::pane_geometry`), `graph_canvas_px` (the graph pane's visible size) and the module-UI pane rect (`note_physical_pane_rect`). The graph publishes **no** rect list: its nodes are hit-tested in world space through `GraphCamera`. A pane that is not drawn publishes nothing, so a stale rect can never hit-test. Every frame report is applied by the layer holding `&mut App` (`handle_physical_frame`, `handle_viewer_frame`, `handle_picker_frame`) — a discarded report is a silently dead input path.
- **Pane layout**: `App.layout: PaneLayout` (`src/panes.rs`) is the only representation of what is open and focused. `ViewType` = Graph | SourceViewer | Physical | Optimizer, each with a `PaneClass` (Big/Small); the band is a left big pane plus a right half that is one big pane or two stacked small panes. `Tab`/`Shift+Tab` cycle focus in tree order, `r` rotates a pane's class carousel, `z` maximizes (non-latching), `Alt+b`/`Alt+s` swap same-class panes, `Esc` closes the focused view (maximize first). Do not reintroduce a mirror (`tile_stack`, `FocusSlot`, `showing_graph`/`showing_viewer`, `pane_rects`) — all were deleted.
- **Patch parsing is hand-rolled** (the `ini` crate was removed): repeated section names are preserved, the token scanner is boundary-aware (an internal variable like `_ENV1_DECAY_POT` is not a hardware token), and `IniSection` keeps verbatim `raw_lines` plus 0-based `header_span`/`EntrySpan` spans captured **before lowercasing**. The validation modal's jump-to-source depends on original-case byte offsets: never replace them with post-lowercase indices. `Patch` builds the occurrence index, the cycle-safe `select`/`selectat` modifier index, the `cable_index` (each schema-declared output param registers a source; preamble cable maps are excluded) and the `banner_groups` (implicit unnamed group first).
- **Validation gates the load**: `App::load_patch` runs `validation::validate_patch`; **any `Error`-severity finding rejects the patch** (`patch = None`, failure modal, `clear_validation`), while `Warning`/`Hint` findings still load and report `Loaded <name> — N warnings/hints — press 'e' to view` without auto-opening the modal. There are **12 checks**: `unknown_circuit`, `duplicate_param`, `unknown_param`, `invalid_jack`, `missing_required` (with the documented-alternatives table; ranged params are skipped), `undefined_cable`, `duplicate_cable`, `unused_cable`, `ram_overflow`, `invalid_expression`, `master_conflict` (Warning), `no_master_fits` (Error). `ram_overflow` is judged against the **resolved** master's budget only. Never relax Error-gating, never let validation depend on `App` state, and keep `ValidationIssue{span, severity, code, message}` sorted by (line, col).
- **Master resolution is one pure step**: `rack::resolve(&Patch, &Schema) -> MasterPlan { model, source, conflicts, satisfiable }` — the patch's `# LABELS: master=16|18` declaration wins, else the single hosting model, else MASTER; capability rules are `I3..I8` and non-gate-typed `I1`/`I2` → MASTER, `vcotuner`/`sinfonionlink` → MASTER18. `MasterModel` is the only vocabulary (`geometry_key()`/`ram_key()`/`label()`); the three spellings never appear as literals elsewhere. `PhysicalLayout::build(Option<&Patch>, MasterModel, &[ModuleKey])` takes all three — a painter must never infer the model, and never derive the chain shape itself.
- **The rack inventory owns the chain**: `[physical.rack] rows[*].modules` is a configured inventory, not a probe and not a patch derivative. Keys are `"{controller} {instance}"` with a 1-based instance; a bare controller means instance 1; `master`/`master18`/`CV I/O` all name the master slot, so one inventory serves either master model. `RackSpec::module_keys` is the only reader (row order, then list order); it skips a malformed entry silently and an unknown controller with one process-wide warning per name, and never draws a guessed fallback faceplate. `config.rs` canonicalises every entry on load **and** save (the alias is written back as `master 1`), so load→save→load is a fixed point. `build` places inventory modules first, appends every patch module the inventory does not name (a forgotten entry must never hide patched hardware), gives an unaddressed module its declared cells with an empty component list, and accepts `None` for the patch. An empty inventory reproduces the pre-inventory chain byte for byte — that compatibility path is the thing to keep unchanged, and `inventory_driven` is its only switch. A row's `modules` list wins over `assign`; `assign` places only unlisted modules; `RackSpec::default_case` derives its width from the chain, never from a patch.
- **Element identity is data, the label is the fallback**: geometry cells carry optional `element`/`kind_letter`/`addressable`; a declared value wins over the label parse (`cell_identity`), because the label does not always name a token (`Gin1`, `serial in`, `USB`, `SD reload`). `addressable: false` renders but never resolves a token and never enters the token index — that is how the R2M/R2C serial jacks and MASTER18's gate column can both exist. `controller_geometry.json` is generated output: change `tools/acquire_geometry.py` and re-run it, never hand-edit the JSON.
- **The graph is a pure model plus a camera**: `Graph::build_from_patch(patch, clusters, cost, options)` produces nodes/edges/clusters and topology findings; three arrangements exist and `SolveKnobs` is the determinism key (same patch + machine + knobs → identical positions). Column is the default; `h` cycles the modes, `a` cycles Column-Strict → Column-Barycenter → Force → Sections. Pins are `NodeId`-keyed fixed anchors; node bodies are world-sized and zoom-projected (never fixed pixel frames); the open settle is display-only. Findings travel with the graph and never block building or viewing.
- **The module UI is a millimetre model**: one isotropic factor (`PHYSICAL_POINTS_PER_MM` 3.779 527 559, i.e. 100 % = 1:1), supported zoom 25–400 %, labels fit (`f`, the default: the greater of rack fit and the zoom every written label needs) and rack fit (`Shift+F`), both named in the pane title. Labels come from the 10 → 6 pt monospace ladder (`physical::label_layout`), annotation is `off`/`auto`/`on` (`a`), and the in-cell state marker is a top-right corner glyph clamped to 6–9 pt, painted **last** with the label text clipped short of its column. An unaddressed rotary position draws a ring plus a centre dot; every other unaddressed element keeps the dim dot and publishes no hit rect. Unaddressed emission has one owner, `unaddressed_cells(module, chain.inventory_driven)`: the chain flag decides it, never the controller name, and an empty inventory keeps the old `CV I/O` suppression so an existing rack renders byte-identically. No unaddressed cell is ever hit-testable.
- **Labels are edit-in-place, never `.ini` writes**: `LabelStore` buckets by canonicalized absolute patch path (`hw` per token per shift layer, `circuits` per `NodeId`), resolution is `store[layer] → store[1] → preamble[1] → derived`, and `layers_enabled = false` coerces display to layer 1 while preserving 2..N. Key priority is overlay → picker → armed prefix → pane-class keys → focused-pane routing; `e` opens the editor for the focused/hovered target, `1..N` cycles layers preserving per-layer drafts, `Enter` persists through the atomic writer, `Esc` cancels.
- **The schema is embedded, never forked**: `schema::load_schema()` caches the compiled-in `circuits.json` behind a `Mutex<Option<&'static Schema>>` (not `OnceLock`, so tests can swap it); the plugin overlay (`merge_plugins`, later files win, warn-once on shadow) is applied by `schema::init()` from `main()` before the window opens. Editing the vendored submodule, not a copy in `src/`, is the only way to change a circuit definition.
- **The latency optimizer is pure and previews in a pane**: `latency::CostModel` is the single per-circuit cost provider (ramsize heuristic + `[latency] per_circuit`); `optimize::generate_candidates` is deterministic (FNV-1a seed order, exact enumeration under `ENUM_LIMIT`, bounded search above it, the identity ordering always present). The preview compares against the captured file-order baseline (`optimizer_diff_state`), recolours worse-red/better-blue under the error/influence/disabled precedence, and exports through the lossless writer — the loaded patch is never mutated.
- **Events are synchronous**: `events.rs` dispatches `GraphRebuilt`, `NodeMoved`, `TopologyError`, `ValidationCompleted`, `InfluenceRecomputed`, `DiffComputed` inline to `FnMut` subscribers. No queue, no async, no thread.
- **The upload edge is one-way**: `sysex::build_sysex` frames the rendered in-memory patch; `U` opens the confirm modal; only after explicit confirmation does the app fork `amidi` (preferred when installed) or `sendmidi`, addressing ports in the language of the tool that listed them. Nothing is ever read back; the child is reaped or killed on quit.
- **Generated docs are artifacts**: `ARCHITECTURE.md`, `DESIGN.md` and this skill are produced by `/make-architecture`, `/make-design`, `/make-guardrails`. Update behaviour in code and specs, then regenerate — never hand-edit their content.

## Design System
- **Tokens only**: every rendered colour resolves through `src/theme.rs` (`Theme::egui_color` / `egui_from_rgb`); no hardcoded RGB outside tests. Palettes are `classic` (the byte-identical default), `terminal` and `mono` (grayscale, shift tokens pairwise distinct, the five graph edge colours pairwise distinct).
- **Edge colour precedence**: `graph_edge_error` red > diff tokens > (latency ramp or modifier hue) > `CableKind` inference > dim. Disabled circuits dim while preserving the red error highlight; the optimizer preview overlays `graph_node/edge_diff_before` (red) and `diff_after` (blue).
- **Label colour is not state colour**: a label paints in `CellSpec.label_color` (active shift token else the element's own kind token); the composed face's outline alone carries state (`muted` while off). State rows stay muted.
- **Cell anatomy**: compact cell = top-right state marker (`h × 0.28`, clamped 6–9 pt, drawn from a 3 pt floor, painted last with the label clipped short of it) + fitted label lines + an optional muted state row. Composed button faces (P2B8, P4B2, B32 round; M4 rectangular) draw outline + folded-LED fill and a label band instead of a state row. Faders draw a `fader_led_bar` amber track.
- **Rack-first painting**: an inventory-driven chain paints every declared cell of every inventoried module — addressed cells bright with label and state, unaddressed ones dim and unlabelled, inert (no hit rect, hover reveal, selection, label editing or modifier wash). An inventory with no patch paints the whole rack dim and publishes no `component_rects`; a patch-derived chain keeps the pre-inventory rendering, master's unused cells suppressed. Never let the painter re-derive the master model or the chain shape from the patch to decide any of this.
- **Glyphs**: button `●`/`○`, switch toggle `▣`/`□` (rotary `◉`/`○`), knob/encoder `◉` plus percentage, CV in `◀` / CV out `▶`, fader `▮`, picker selection `▶`; graph ports are presence markers (left `◉` on sinks, right `●` on sources). An unaddressed rotary draws a ring + centre dot, never a bare speck.
- **A new theme token needs**: a consumer in the same change, a byte-identical `classic` value, a distinct `mono` value where it must be told apart, and a regenerated `DESIGN.md`.
- **Motion and spacing**: no animation except the 500 ms cubic-ease-out graph settle on a fresh open; no radii/shadow/elevation beyond egui's AA shapes. Cell sizes come from the mm geometry, not from a spacing scale; the zoom presets are 75/100/150/200 % of the 1:1 baseline within the supported 25–400 %.
- **Patch LED colour is the one deliberate exception**: brightness and colour written to the LED registers render as the hardware shows them (the manual's colour wheel, `patch::led_colour_for_value`); everything else is a token.

## Code Style
- Run `cargo fmt` before every commit; CI enforces `cargo fmt --check`.
- Lint gate: `cargo clippy --all-targets --all-features --locked -- -D warnings`. `clippy::pedantic` is the crate-wide baseline (`Cargo.toml [lints.clippy]`), and **that table is the whole exception policy**: a lint is disabled with a `priority = 1` entry stating why, never with `#[allow]` at a call site. Do not bypass a check, weaken a test or silence a lint to get a green result.
- No `unwrap()`/`expect()` outside `#[cfg(test)]`.
- Comments explain WHY (invariants, constraints, non-obvious decisions) and never restate code; keep them sparse.
- One responsibility per file. A file that imports 5+ unrelated modules is a split signal; use domain names (`patch.rs`, `graph.rs`, `physical.rs`, `rack.rs`, `store.rs`), not catch-all `utils.rs`/`constants.rs`.
- Reach for the indexed tools first: `codegraph_explore` for symbol/call-path questions, the file tools for edits; fall back to grep for config and plain text.

## Naming Conventions
- Rust files `snake_case.rs`; types `PascalCase`; constants `SCREAMING_SNAKE_CASE` (`BIG_CAROUSEL`, `SOLVE_ITERATIONS`).
- Circuit names are lowercased at the plugin/schema boundary; schema lookups stay case-insensitive.
- TOML keys are `snake_case` (`theme`, `layers_enabled`, `max_shift_layer`, `per_circuit`, `[layout] mode`/`ordering`, `[physical.rack] rows`/`modules`/`assign`, `[plugins] dir`/`enabled`). Branches are `feature/<slug>`; archive commits land on `archive/<slug>`.
- Hardware tokens are `B/L/P/O/I/E/S` + digits (+ `.` + digits) — `B1.1`, `L2.4`; cables carry a leading underscore (`_PULSARCLOCK`). Token scanning stays boundary-aware.
- Master spellings go through `MasterModel` only: `geometry_key()` (`master`/`master18`), `ram_key()` (`master16`/`master18`), `label()` (`MASTER`/`MASTER18`) — never a literal at a call site.
- Inventory and `assign` keys share one vocabulary: `"{controller} {instance}"` with a 1-based instance (`P2B8 1`); a bare controller is instance 1 (`B32`, `G8`, `X7`, `R2M`, `R2C`); `master`, `master18` and `CV I/O` are aliases for the one master slot.

## Build & Deployment
- Build: `cargo build` (debug) / `cargo build --release --locked`; the artifact is `droid_tui` (Linux), `droid_tui.exe` (Windows) or a `droid_tui.app` bundle (macOS). A fresh checkout needs the submodule initialised first.
- Gate at CI parity before reporting completion: `cargo fmt --check`, `cargo clippy --all-targets --all-features --locked -- -D warnings`, `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --locked`, `cargo test --locked`, `cargo build --release --locked`, `cargo test --release --test perf_gate --locked` (Linux) and `cargo run --release -- --self-test fixtures/own_buttons.ini`.
- CI (`.github/workflows/ci.yml`): a three-OS matrix (`ubuntu`, `windows`, `macos`, `fail-fast: false`) that checks out with `submodules: false` and then runs `git submodule update --init ext/droid-lsp`; all three run `cargo test --locked`, the release build and the headless self-test; Linux additionally runs fmt, clippy, rustdoc, the perf gate and the `tools/screenshots` harness build. CI never opens a window, never talks to MIDI and never publishes.
- Release (`.github/workflows/release.yml`): a `v*` tag (or a manual run naming one) produces the unsigned Windows x86_64 zip and the macOS universal zip (`scripts/package-macos.sh`, `lipo`/`ditto`), versioned from the tag; the release is created as a draft and publishing is a human step. There are no installers, no code signing and no prebuilt Linux binary.
- Screenshots for `docs/assets` come from `tools/screenshots` (a tools-only crate that path-shadows the app sources, so renders track the real paint path); regenerate rather than hand-editing images.

## Git Workflow
- Backlog platform is `browser` (work items through `@pc-userstory`); the repo platform is `none` (no PR/MR automation). Max 3 concurrent agents.
- OpenSpec change workflow: propose under `openspec/changes/<slug>`, implement on `feature/<slug>`, merge to `main`, archive into `openspec/changes/archive/` (the archive commit lands on `archive/<slug>`) and sync the deltas into `openspec/specs/`. Never mix backlog and repo CLIs.
- Task tracking is beads (`bd`); the profile is conservative — no commits, pushes or Dolt sync without explicit approval.
- Commit style follows the history: imperative one-liners, often `area: summary` or `type: summary` (`gate: …`, `fix: …`, `refactor: …`); keep generated docs out of a behaviour commit's diff unless regenerated deliberately.

## Security
- No secrets, no network, no auth, no multi-user state. The only external input is local `.ini` files: the parser returns descriptive `Err(String)` and never panics, graph edge building skips unresolvable names, and validation gates `Error`-severity findings before anything renders.
- The lossless writer refuses to overwrite its own source path, writes atomically (tmp→rename) and auto-suffixes on collision; the optimizer export shares that path.
- The one subprocess edge is the confirmed SysEx upload (`amidi`/`sendmidi`, no shell); the staged `.syx` tmpfile and the child are cleaned on drop/quit. Never widen this edge to read from hardware.
- Release artifacts are unsigned and not notarised: never describe a build as signed, and keep `docs/platforms.md` honest about Gatekeeper/SmartScreen warnings.
- A panic must leave no orphaned window: the chained panic hook runs the one-shot `destroy_window_for_panic` with each teardown step contained.

## Data & State
- Four user stores in one platform data directory (`<data dir>/droid-tui/`): `config.toml`, `labels.toml`, `favourites.toml`, `plugins/*.toml`. Every path resolves through `platform.rs` and every TOML read/write goes through `store.rs`: missing or unreadable → defaults, malformed → one warning + defaults, writes atomic, keys canonical (`store::canonical_key`).
- `config.toml` (schema version 1): `theme`; `[labels] layers_enabled`/`max_shift_layer` (clamped 1..8); `[latency] per_circuit`; `[layout] mode` (`column` default / `force` / `sections`) and `ordering` (`strict` default / `barycenter`); `[physical] labels` (`off`/`auto`/`on`), `zoom` (0.25–4.0, with the `zoom_baseline` marker guarding pre-1:1 values), `offset_x`/`offset_y`; `[physical.rack]` (`rows: [{he, hp, label?, modules?}]`, `top_mount_te`, `side_mount_te`, `assign`); `[plugins] dir` (absolute override only) and `enabled`. Sanitise on load **and** save; unknown values warn once and fall back. Each row inventory is re-emitted from its parsed key on both paths (an alias is stored as `master 1`), a malformed entry is dropped instead of failing the config, and an empty list never gains the key.
- `labels.toml` is the only per-patch persistence (`hw` per token per layer, `circuits` per `NodeId`, keyed by the canonicalized absolute patch path). Nothing else about a patch is stored.
- Everything else is in-memory `App` state and resets on `load_patch`: selection, `hold_component`/`latched_component`/`modifier_influence`/`influence_subset`, `active_shift`, pane layout and both split ratios, `graph`/positions/`pinned`/`graph_camera`/`graph_settle`, `layout_mode`/`layout_ordering`/`tension`/solver knobs, `validation_issues`, `diff_*`, `select_state`, `dependency_*`, `optimizer_diff_state`, `disabled_circuits`, `processing_paused`, `master_plan`, `physical_zoom`/`physical_offset`/`physical_fit_mode`/`physical_nav_latched`, `status_message`.
- Build-time inputs are embedded, never read at runtime: `circuits.json`, `rack_geometry.json`, `controller_geometry.json`, `tools/outlier_artifact.txt`, `tools/influence_stats.txt`, `tools/render_artifact.txt`.
