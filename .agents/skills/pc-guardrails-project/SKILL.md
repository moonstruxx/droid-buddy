# Project Guardrails

> Auto-generated by `/make-guardrails`. Regenerate with the same command when architecture or conventions change significantly.

## Semantic Anchors
- **UI mirrors HW (1:1 alignment, HIGH PRIORITY)**: the module UI renders hardware components at the same positions as on the physical modules — the user mixes live and must be able to grab the SAME button in the UI and on the hardware at any moment without abstraction. The goal is **recognizability, not reproduction**: keep 100% of the geometric arrangement (relative positions, ordering, adjacency, grid structure — which control sits where relative to its neighbours, which panel is where) and simplify the representation (glyphs, labels, semantic colours — never a literal copy of a physical part). Grids come from embedded per-controller geometry, never from window width; panels follow physical rack positions; an element's built-in LED is joined to it positionally (`L1.1` with `B1.1`), "built-in" meaning the controller's physical design, not what the patch happens to declare. The chain it draws is the rack's own contents — the configured module inventory — with the patch distributed onto it, so a patch that stays silent can never hide hardware that is physically there. The egui window is the only rendering surface; there is no terminal fallback.
- **YAGNI**: every type, variant, derive and trait in `src/` must have a current consumer — dead code is deleted on sight, not kept for "future" use. Speculative features (persistence, hardware *receive*/firmware flows, terminal fallback) are deferred ideas; introducing one requires an OpenSpec change (the one-way SysEx send arrived that way via `midi-upload`).
- **DRY**: one source of truth per fact. Generated docs (`ARCHITECTURE.md`, `DESIGN.md`, this skill) are derived artifacts — edit code and regenerate via `/make-*`, never hand-edit them. The circuit schema (`ext/droid-lsp/droid-lsp/src/circuits.json`) and the geometry data (`rack_geometry.json`, `controller_geometry.json`) are single-source build-time inputs — never fork a copy inside `src/`.
- **CodeAsDoc**: names carry DROID domain meaning; doc comments explain non-obvious invariants and reasons, never restate code; OpenSpec specs are the behaviour contract and code is the executable spec.
- **TDD London** (mockist, outside-in): test through public entry points (`handle_event`, `validate_patch`, `diff_patches`, the gui spec/paint builders); use real fixtures for cheap deterministic collaborators (the filesystem); mock only genuinely costly or unreliable boundaries — there are none today. The one true collaboration contract to keep tested is the renderer→handler geometry handoff: `component_rects`, `pane_hit_rects`, `graph_canvas_px` (the graph hit-tests world-space through its camera instead of publishing rects).

## Architecture Constraints
- **Stack and entry**: Rust 2021, one binary crate `droid_tui` (no `[features]`); native winit 0.30 + egui 0.36 + wgpu 30. `src/main.rs` owns the single `EventLoop` through `AppHandler: ApplicationHandler` and is the only place that opens the window (`queue_startup_window_open`); a startup open failure, or a loop that ends without a window, is a non-zero exit. There is no async runtime, no network and no terminal/crossterm stack.
- **Dependency direction is one-way**: `gui` and `handler` depend on `app`, `patch` and the pure models; `app` depends on `patch`, `rack`, `graph`, `layout`, `latency`, `optimize`, `panes`, `physical`, `plugin`, `schema`, `validation`, `diff`, `geometry`, `events`, `graph_render`, `store`, `config`, `platform`; `graph` depends on `patch`, `geometry`, `latency`; `layout` on `graph`; `graph_group` on `graph` + `layout`; `rack` on `patch` + `schema`; `store`/`platform`/`panes`/`expression`/`help`/`sysex`/`performance` are standalone. `patch` must not import `app`, `handler`, `gui`, `graph`, `layout`, `events`, `validation`, `diff`, `geometry`, `latency`, `optimize`, `panes`, `performance`, `sysex`, `physical`, `plugin`, `graph_render`, `platform`, `rack`, `store`; `schema` is the one allowed inbound dependency, because the parser resolves controllers and jack names through `load_schema`/`schema::JACK_TABLE`. A new module is wired in `src/lib.rs` and stays pure unless it is a `gui/` surface or the `cli` argv/report layer (`cli::parse` and `report.rs` are pure; `cli::run` is the only writer).
- **The headless CLI is a second entry point, not a second app**: `droid_tui analyze|optimize` (`src/cli.rs` + `src/report.rs`) dispatches in `main()` after config load, `theme::init` and `schema::init` — so plugin overlay matches the GUI — and before any window machinery, then exits with `cli::run`'s code: 0 clean, 1 findings at or above `--deny` (`analyze` only; default `error`), 2 could not run. stdout carries only the report, warnings stay on stderr. It never opens a window, never gates on `Error` findings (it reports them), and never re-implements a check: every number comes from the existing pure cores (`validate_patch`, `rack::resolve`, `Graph::build_from_patch`, `generate_candidates`, `patch::render_ini`).
- **The report contract is versioned**: `report.rs` (`report_version` 1) is the only CLI output shape — changing a key is a version event. Floats round to four decimals and findings keep validator/graph order with line and column. A new or changed key must also land in `.agents/skills/droid-patch-cli/references/report.md` in the same change; `tests/cli.rs` fails when a report key is undocumented there.
- **Pure means pure**: `graph`, `graph_anim`, `graph_group`, `layout`, `events`, `expression`, `help`, `validation`, `schema`, `diff`, `geometry`, `latency`, `optimize`, `panes`, `performance`, `sysex`, `physical`, `plugin`, `rack`, `store` have **no window dependency, no runtime I/O and no `App` parameter**. Schema and geometry data enter through `include_str!` at compile time (`circuits.json`, `rack_geometry.json`, `controller_geometry.json`, `tools/outlier_artifact.txt`, `tools/influence_stats.txt`); their regression tests reject `CARGO_MANIFEST_DIR` and `std::fs` in the production half. Never add an `egui`/`winit` import or an `App` argument to a pure module.
- **One source of truth per fact (the seams)**: `platform::config_dir*` for every user-data path (config, labels, favourites, plugins — no fourth XDG copy, no per-module `cfg(windows)`); `store` for the TOML rules (read/atomic write/canonical key); `App::master_model()` for the master model; `RackSpec::module_keys` for the rack inventory (the only reader of `RackRow.modules`); `App::pane_geometry` for pane rects; `rack::resolve` for master fit; `Patch::folded_led_for_element` for LED binding; `Patch::display_label`/`circuit_label` for labels; `layout::estimated_widths` for node world widths; `gui::drawn_world_sizes` for drawn/hit graph widths; `theme::active()` for colours. Add a field that mirrors one of these and the two will drift.
- **Renderer→handler geometry**: the painters publish per frame — `component_rects` (module-UI cells, cleared and refilled by `paint_panes`), `pane_hit_rects` (from `App::pane_geometry`), `graph_canvas_px` (the graph pane's visible size) and the module-UI pane rect (`note_physical_pane_rect`). The graph publishes **no** rect list: its nodes are hit-tested in world space through `GraphCamera`. A pane that is not drawn publishes nothing, so a stale rect can never hit-test. Every frame report is applied by the layer holding `&mut App` (`handle_physical_frame`, `handle_viewer_frame`, `handle_picker_frame`) — a discarded report is a silently dead input path.
- **Pane layout**: `App.layout: PaneLayout` (`src/panes.rs`) is the only representation of what is open and focused. `ViewType` = Graph | SourceViewer | Physical | Optimizer, each with a `PaneClass` (Big/Small); the band is a left big pane plus a right half that is one big pane or two stacked small panes. `Tab`/`Shift+Tab` cycle focus in tree order, `r` rotates a pane's class carousel, `z` maximizes (non-latching), `Alt+b`/`Alt+s` swap same-class panes, `Esc` closes the focused view (maximize first). Do not reintroduce a mirror (`tile_stack`, `FocusSlot`, `showing_graph`/`showing_viewer`, `pane_rects`) — all were deleted.
- **Patch parsing is hand-rolled** (the `ini` crate was removed): repeated section names are preserved, the token scanner is boundary-aware (an internal variable like `_ENV1_DECAY_POT` is not a hardware token), and `IniSection` keeps verbatim `raw_lines` plus 0-based `header_span`/`EntrySpan` spans captured **before lowercasing**. The validation modal's jump-to-source depends on original-case byte offsets: never replace them with post-lowercase indices. `Patch` builds the occurrence index, the cycle-safe `select`/`selectat` modifier index, the `cable_index` (each schema-declared output param registers a source; preamble cable maps are excluded) and the `banner_groups` (implicit unnamed group first).
- **Validation gates the load**: `App::load_patch` runs `validation::validate_patch`; **any `Error`-severity finding rejects the patch** (`patch = None`, failure modal, `clear_validation`), while `Warning`/`Hint` findings still load and report `Loaded <name> — N warnings/hints — press 'e' to view` without auto-opening the modal. There are **12 checks**: `unknown_circuit`, `duplicate_param`, `unknown_param`, `invalid_jack`, `missing_required` (with the documented-alternatives table; ranged params are skipped), `undefined_cable`, `duplicate_cable`, `unused_cable`, `ram_overflow`, `invalid_expression`, `master_conflict` (Warning), `no_master_fits` (Error). `ram_overflow` is judged against the **resolved** master's budget only. Never relax Error-gating, never let validation depend on `App` state, and keep `ValidationIssue{span, severity, code, message}` sorted by (line, col).
- **Master resolution is one pure step**: `rack::resolve(&Patch, &Schema) -> MasterPlan { model, source, conflicts, satisfiable }` — the patch's `# LABELS: master=16|18` declaration wins, else the single hosting model, else MASTER; capability rules are `I3..I8` and non-gate-typed `I1`/`I2` → MASTER, `vcotuner`/`sinfonionlink` → MASTER18. `MasterModel` is the only vocabulary (`geometry_key()`/`ram_key()`/`label()`); the three spellings never appear as literals elsewhere. `PhysicalLayout::build(Option<&Patch>, MasterModel, &[ModuleKey])` takes all three — a painter must never infer the model, and never derive the chain shape itself.
- **The rack inventory owns the chain**: `[physical.rack] rows[*].modules` is a configured inventory, not a probe and not a patch derivative. Keys are `"{controller} {instance}"` with a 1-based instance; a bare controller means instance 1; `master`/`master18`/`CV I/O` all name the master slot, so one inventory serves either master model. `RackSpec::module_keys` is the only reader (row order, then list order); it skips a malformed entry silently and an unknown controller with one process-wide warning per name, and never draws a guessed fallback faceplate. `config.rs` canonicalises every entry on load **and** save (the alias is written back as `master 1`), so load→save→load is a fixed point. `build` places inventory modules first, appends every patch module the inventory does not name (a forgotten entry must never hide patched hardware), gives an unaddressed module its declared cells with an empty component list, and accepts `None` for the patch. An empty inventory reproduces the pre-inventory chain byte for byte — that compatibility path is the thing to keep unchanged, and `inventory_driven` is its only switch. A row's `modules` list wins over `assign`; `assign` places only unlisted modules; `RackSpec::default_case` derives its width from the chain, never from a patch.
- **Element identity is data, the label is the fallback**: geometry cells carry optional `element`/`kind_letter`/`addressable`; a declared value wins over the label parse (`cell_identity`), because the label does not always name a token (`Gin1`, `serial in`, `USB`, `SD reload`). `addressable: false` renders but never resolves a token and never enters the token index — that is how the R2M/R2C serial jacks and MASTER18's gate column can both exist. `controller_geometry.json` is generated output: change `tools/acquire_geometry.py` and re-run it, never hand-edit the JSON.
- **The graph is a pure model plus a camera**: `Graph::build_from_patch(patch, clusters, cost, options)` produces nodes/edges/clusters and topology findings; three arrangements exist and `SolveKnobs` is the determinism key (same patch + machine + knobs → identical positions). Column is the default; `h` cycles the modes, `a` cycles Column-Strict → Column-Barycenter → Force → Sections. Pins are `NodeId`-keyed fixed anchors; node bodies are world-sized and zoom-projected (never fixed pixel frames); the open settle is display-only. Findings travel with the graph and never block building or viewing.
- **Same-type grouping is a post-solve view transform**: `graph_group::group_nodes` answers only "which drawn node stands in for which model node" after the solver has run — it never re-solves, never re-arranges and never touches a pin, so determinism holds per input. `[graph] group_by` is `type` (default: every circuit of a kind is one box) or `run` (only spatially stacked or ≤2-cable-hop same-type circuits); `min_group_size` (default 5) gates both. A group draws one box: the member union when the union is thin on at least one axis (a column or a row, however long), otherwise one nominal box at the member centroid. `Group::bbox` is the **collapsed** box only; `Group::members_bbox` is the never-compacted union and is what an expanded outline and its hit box must use. Intra-group cables are not drawn and the rest dedupe onto the group. `App::grouped_view` is the one cache the painter, the pointer hit test and the marquee mapping read, pre-warmed once per frame before the scene build (asking per node repeats the quadratic pass every frame). Grouping is on by default and a highlight class resolves at group level by the strongest member under the surface's existing precedence.
- **The minimap is always drawn and owns a drag gesture**: `minimap_layout` returns `None` only for an empty or zero-extent scene — never because the layout fits. `gui::graph::{minimap_world_point, minimap_world_bounds}` are the **only** minimap↔world mapping; the handler must not re-invert the transform. A press in the panel anchors a marquee (no camera move), drag frames track it clamped to the inner panel, and the release fits `GraphCamera::fit_to_world_with_nodes` over the world rectangle and latches the fit preset — unless the marquee spans under 3 px on either axis, which pans exactly as a click always did. While the map owns the drag the canvas marquee selects nothing, and `Esc` cancels the marquee without closing the view.
- **The module UI is a millimetre model**: one isotropic factor (`PHYSICAL_POINTS_PER_MM` 3.779 527 559, i.e. 100 % = 1:1), supported zoom 25–400 %, labels fit (`f`, the default: the greater of rack fit and the zoom every written label needs) and rack fit (`Shift+F`), both named in the pane title. Labels come from the 10 → 6 pt monospace ladder (`physical::label_layout`), annotation is `off`/`auto`/`on` (`a`), and the in-cell state marker is a top-right corner glyph clamped to 6–9 pt, painted **last** with the label text clipped short of its column. An unaddressed rotary position draws the addressed face at a 0.75 alpha floor on the kind token, minus the washer ring at the full-detail step; below an 18 pt face the reduced and centre-dot steps keep the addressed drawing at that floor, so the plain ring-plus-dot survives only as the sub-10 pt step. Every other unaddressed element keeps the dim dot and publishes no hit rect. Unaddressed emission has one owner, `unaddressed_cells(module, chain.inventory_driven)`: the chain flag decides it, never the controller name, and an empty inventory keeps the old `CV I/O` suppression so an existing rack renders byte-identically. No unaddressed cell is ever hit-testable.
- **Hardware faces are drawn, not glyph-marked**: a pot, encoder and CV jack render a hardware symbol through the existing `CellShape` (`Pot`/`Encoder`/`Jack`) and the `CellTextPath::Face` seam — the symbol claims the cell's top `FACE_HEIGHT_FRACTION` (`0.66 × w`, `pub` so the drawn shape and the fitted band cannot disagree) and the label takes the band `h − 0.66 × w` beneath, so a face never shrinks or displaces for text. The slot carries the value on a 270° sweep (7:30 → straight up → 4:30) from `CellSpec::value_frac` — the renamed `fader_value`, and the only value field. Detail is a ladder on the **drawn ring diameter**, never on the cell size or the zoom: the full symbol at ≥18 pt, ring + slot from 10 pt (a jack keeps ring and mouth, losing only its cross), ring + centre dot below, so a 12 mm pot is full at 100 % while a 7 mm encoder is reduced there and reaches full above about 113 %. A face cell draws no corner state marker; a jack keeps its `◀`/`▶` corner marker over the face, and a fader-marked knob/encoder draws the bottom-up `fader_led_bar` strip instead of a face. Display-only: no new token, no geometry change, hit rects identical.
- **The module-UI minimap is navigation chrome, drawn whenever there is a rack**: `physical::rack_minimap` and its inverse are the **only** rack↔map mapping — the handler never re-inverts it. The panel is 160 pt wide, inset 8 pt from the pane's bottom-right, its height following the rack aspect (56–120 pt), and it draws at every zoom including when the rack already fits, because it is a place-finder rather than an overflow indicator. It paints the case outline and one rect per module in `muted`, the focused element's module in `focus_border`, the visible part of the rack as an `accent` viewport box (clamped when everything is visible), and the live marquee in `accent`; no new token and no pane-title segment. It is a surface, not an overlay: it claims presses and the wheel **before** element hit-testing, a click centres the pane on the clicked rack point, a drag of ≥3 points fits the zoom to the dragged region, `Esc` cancels the marquee without closing the view, and the wheel over the map is unbound. `c` centres on the focused element (else the rack) and `Shift+C` reapplies the labels fit and re-arms automatic fitting, exactly as on the graph.
- **Labels are edit-in-place, never `.ini` writes**: `LabelStore` buckets by canonicalized absolute patch path (`hw` per token per shift layer, `circuits` per `NodeId`), resolution is `store[layer] → store[1] → preamble[1] → derived`, and `layers_enabled = false` coerces display to layer 1 while preserving 2..N. Key priority is overlay → picker → armed prefix → pane-class keys → focused-pane routing; `e` opens the editor for the focused/hovered target, `1..N` cycles layers preserving per-layer drafts, `Enter` persists through the atomic writer, `Esc` cancels.
- **The schema is embedded, never forked**: `schema::load_schema()` caches the compiled-in `circuits.json` behind a `Mutex<Option<&'static Schema>>` (not `OnceLock`, so tests can swap it); the plugin overlay (`merge_plugins`, later files win, warn-once on shadow) is applied by `schema::init()` from `main()` before the window opens. Editing the vendored submodule, not a copy in `src/`, is the only way to change a circuit definition.
- **The latency optimizer is pure and previews in a pane**: `latency::CostModel` is the single per-circuit cost provider (ramsize heuristic + `[latency] per_circuit`); `optimize::generate_candidates` is deterministic (FNV-1a seed order, exact enumeration under `ENUM_LIMIT`, bounded search above it, the identity ordering always present). The preview compares against the captured file-order baseline (`optimizer_diff_state`), recolours worse-red/better-blue under the error/influence/disabled precedence, and exports through the lossless writer — the loaded patch is never mutated.
- **Events are synchronous**: `events.rs` dispatches `GraphRebuilt`, `NodeMoved`, `TopologyError`, `ValidationCompleted`, `InfluenceRecomputed`, `DiffComputed` inline to `FnMut` subscribers. No queue, no async, no thread.
- **The upload edge is one-way**: `sysex::build_sysex` frames the rendered in-memory patch; `U` opens the confirm modal; only after explicit confirmation does the app fork `amidi` (preferred when installed) or `sendmidi`, addressing ports in the language of the tool that listed them. Nothing is ever read back; the child is reaped or killed on quit.
- **Generated docs are artifacts**: `ARCHITECTURE.md`, `DESIGN.md` and this skill are produced by `/make-architecture`, `/make-design`, `/make-guardrails`. Update behaviour in code and specs, then regenerate — never hand-edit their content.

## Design System
- **Tokens only**: every rendered colour resolves through `src/theme.rs` (`Theme::egui_color` / `egui_from_rgb`); no hardcoded RGB outside tests. Palettes are `classic` (the historical default; its one deliberate departure from the pre-theming colours is the graph cluster title, raised Blue → LightBlue for the 4.5:1 text floor, ADR 57), `terminal` and `mono` (grayscale, shift tokens pairwise distinct, the five graph edge colours pairwise distinct).
- **Graph text is screen-space constant and contrast-floored**: cluster titles paint at a fixed 12 pt regardless of camera zoom and yield to a box without room (one title line plus the top inset tall, three characters wide) instead of scaling with zoom or ellipsizing to a sliver; every shipped palette's cluster title clears a 4.5:1 ratio against that palette's graph canvas background, asserted by `theme::tests::cluster_title_meets_text_contrast_in_every_palette` (`terminal`'s `Reset` pair exempt). Node labels already worked this way (ADR 43); cluster titles were the exception until ADR 57.
- **Group box and minimap chrome reuse tokens, never new ones**: a collapsed group wears `graph_node_border` over `graph_node_title` (the circuit's own frame) and its label carries the strongest highlight class colour, so the box never introduces a group-specific token. The graph minimap's drag marquee is a translucent accent fill (α 40) with a 1 px accent stroke, drawn above the map dots and below the viewport box; the module-UI map reuses `muted` for the case outline and module rects, `focus_border` for the focused module, and `accent` for the viewport box and the live marquee.
- **Edge colour precedence**: `graph_edge_error` red > diff tokens > (latency ramp or modifier hue) > `CableKind` inference > dim. Disabled circuits dim while preserving the red error highlight; the optimizer preview overlays `graph_node/edge_diff_before` (red) and `diff_after` (blue).
- **Label colour is not state colour**: a label paints in `CellSpec.label_color` (active shift token else the element's own kind token); the composed face's outline alone carries state (`muted` while off). State rows stay muted.
- **Cell anatomy**: compact cell = top-right state marker (`h × 0.28`, clamped 6–9 pt, drawn from a 3 pt floor, painted last with the label clipped short of it) + fitted label lines + an optional muted state row. Composed button faces (P2B8, P4B2, B32 round; M4 rectangular) draw outline + folded-LED fill and a label band instead of a state row. Faders draw a `fader_led_bar` amber track. Pot, encoder and jack faces use the `Face` text path: symbol in the top `0.66 × w`, label band beneath, no corner marker; a fader-marked knob/encoder draws the bottom-up `fader_led_bar` strip instead of a face.
- **Rack-first painting**: an inventory-driven chain paints every declared cell of every inventoried module — addressed cells bright with label and state, unaddressed ones dim and unlabelled, inert (no hit rect, hover reveal, selection, label editing or modifier wash). An inventory with no patch paints the whole rack dim and publishes no `component_rects`; a patch-derived chain keeps the pre-inventory rendering, master's unused cells suppressed. Never let the painter re-derive the master model or the chain shape from the patch to decide any of this.
- **Glyphs**: button `●`/`○`, switch toggle `▣`/`□` (rotary `◉`/`○`), knob/encoder a drawn pot or encoder face plus a percentage where the label band holds it (no `◉` marker), CV in `◀` / CV out `▶` kept as the corner marker over the jack face, fader `▮` plus track, picker selection `▶`; graph ports are presence markers (left `◉` on sinks, right `●` on sources). An unaddressed rotary draws the dimmed addressed face (ring dropped at full detail), never a bare speck.
- **A new theme token needs**: one row in the single `macro_rules! palettes` table (the `classic, terminal, mono` columns — a token in one palette and not the others is a compile error, so the palettes cannot drift), a consumer in the same change, a byte-identical `classic` value, a distinct `mono` value where it must be told apart, an entry in `every_token()`, and a regenerated `DESIGN.md`.
- **Motion and spacing**: no animation except the 500 ms cubic-ease-out graph settle on a fresh open; no radii/shadow/elevation beyond egui's AA shapes. Cell sizes come from the mm geometry, not from a spacing scale; the zoom presets are 75/100/150/200 % of the 1:1 baseline within the supported 25–400 %.
- **Patch LED colour is the one deliberate exception**: brightness and colour written to the LED registers render as the hardware shows them (the manual's colour wheel, `patch::led_colour_for_value`); everything else is a token.

## Code Style
- Run `cargo fmt` before every commit; CI enforces `cargo fmt --check`.
- Lint gate: `cargo clippy --all-targets --all-features --locked -- -D warnings`. `clippy::pedantic` is the crate-wide baseline (`Cargo.toml [lints.clippy]`), and **that table is the crate-wide exception policy**: a rule is disabled with a `priority = 1` entry stating why. A per-site `#[allow]` is the narrow exception, allowed only where the table cannot express the case — a lint that fires on one call shape (`geometry.rs::build`'s arity, `patch.rs`'s index loop) with the reason on the same line — plus the structural `#[path]`-staging shims in `src/gui/mod.rs` (`dead_code`/`unused_imports` while the harness compiles that module). A bare `#[allow]` with no stated reason is a review failure, and `#[allow(dead_code)]` outside those shims is a defect: `scripts/codehealth.py` counts it as new debt. Do not bypass a check, weaken a test or silence a lint to get a green result.
- No `unwrap()`/`expect()` outside `#[cfg(test)]`.
- Comments explain WHY (invariants, constraints, non-obvious decisions) and never restate code; keep them sparse.
- One responsibility per file. A file that imports 5+ unrelated modules is a split signal; use domain names (`patch.rs`, `graph.rs`, `physical.rs`, `rack.rs`, `store.rs`), not catch-all `utils.rs`/`constants.rs`.
- Reach for the indexed tools first: `codegraph_explore` for symbol/call-path questions, the file tools for edits; fall back to grep for config and plain text.
- **Long dispatchers are split by section, never grown**: `handle_event` is an ordered `[KeyHandler; 19]` table, `handle_shared_key` the same shape one level down, `handle_mouse_event` an ordered `[MouseHandler; 5]` table terminated by `handle_element_mouse` under the same `true` = consumed convention, and the graph pane/window paths are sequences of named steps (`handle_graph_pane_key` is a 29-line dispatcher over `handle_grouping_key`, `handle_graph_node_key`, `handle_graph_camera_key`, …; `handle_graph_window_frame` is routing → camera resolve → hover publish → marquee → press → drag → release → keys). A helper answering `true` means "consumed"; answering `false` falls through to the next surface. A function past 15 decision points is a split signal (`scripts/codehealth.py`, the Code Health budget), and the precedence comments (minimap over scene, collapsed box over selector, member-over-group only when drawn expanded) stay at the seam where they are decided.

## Naming Conventions
- Rust files `snake_case.rs`; types `PascalCase`; constants `SCREAMING_SNAKE_CASE` (`BIG_CAROUSEL`, `SOLVE_ITERATIONS`).
- Circuit names are lowercased at the plugin/schema boundary; schema lookups stay case-insensitive.
- TOML keys are `snake_case` (`theme`, `layers_enabled`, `max_shift_layer`, `per_circuit`, `[layout] mode`/`ordering`, `[graph] group_enabled`/`min_group_size`/`group_by`, `[physical.rack] rows`/`modules`/`assign`, `[plugins] dir`/`enabled`). Branches are `feature/<slug>`; archive commits land on `archive/<slug>`.
- Hardware tokens are `B/L/P/O/I/E/S` + digits (+ `.` + digits) — `B1.1`, `L2.4`; cables carry a leading underscore (`_PULSARCLOCK`). Token scanning stays boundary-aware.
- Master spellings go through `MasterModel` only: `geometry_key()` (`master`/`master18`), `ram_key()` (`master16`/`master18`), `label()` (`MASTER`/`MASTER18`) — never a literal at a call site.
- Inventory and `assign` keys share one vocabulary: `"{controller} {instance}"` with a 1-based instance (`P2B8 1`); a bare controller is instance 1 (`B32`, `G8`, `X7`, `R2M`, `R2C`); `master`, `master18` and `CV I/O` are aliases for the one master slot.

## Testing
- `cargo test --locked` is the whole suite: **1785** tests (1745 lib + 17 `main.rs` + 15 `cli` contract + 2 `force_arrangement_invariants` + 6 perf gate; measured 2026-11-17; 0 doc-tests). Update this number in the same change that moves it.
- The headless CLI has its own contract test (`tests/cli.rs`, spawning the binary): exit codes, JSON shape, and a drift guard that fails when a report key is missing from `.agents/skills/droid-patch-cli/references/report.md`. Extend it with every new subcommand or report key, and keep `docs/cli.md` accurate.
- Unit tests live in-module (`#[cfg(test)]`) next to the code; cross-layer model/story regressions live in `src/regression.rs`; fixtures live in `fixtures/` (including the `validation/*.ini` check matrix and the physical/SysEx/graph families). Add a fixture before inventing a synthetic patch.
- Rendering is verified headlessly: `egui::Context::run` → `FullOutput` shapes/labels asserted in `src/gui/*.rs` and `src/theme.rs` (no GPU, no window); `egui_kittest::Harness` query-by-label journeys cover the graph surface. There is no snapshot testing.
- The module-UI minimap and the hardware faces split across two test layers and both are required: the pure transform (`physical::rack_minimap` round-trips through its inverse, clamps the panel height at both ends, refuses a degenerate rack, fills the viewport when the rack fits, maps one rect per module with the focused index) and the paint path (`gui::physical` asserts the panel, the per-module rects, the clamped viewport, the focus, the marquee, no map in the performance view, and the pot/encoder/jack detail ladder). Both read the existing fixtures — never invent a synthetic patch for either.
- The end-to-end smoke is `cargo run -- --self-test [patch.ini]` (6 checks, non-zero exit on failure). Run it whenever the paint dispatch, pane geometry or overlay ordering changes.
- The perf gate (`tests/perf_gate.rs`) is Linux-only (`#![cfg(target_os = "linux")]`, release timings); run `cargo test --release --test perf_gate --locked` when a gated phase's code moves and `scripts/profile-gate.sh <phase>` when it busts.
- Geometry data has its own gate: `python3 tools/acquire_geometry.py --check` must pass after any `controller_geometry.json` change — regenerate with the script, never hand-edit the JSON. The generator owns the declared `element`/`kind_letter`/`addressable` fields as much as the labels, so fix a mis-resolving cell in the script and re-run it.
- A helper more than one test module needs lives once in `src/test_support.rs` (`#[cfg(test)]`) — `fixture_graph`/`fixture_patch_and_graph`, `positions_bbox`, `rack_inventory`, `catalog_schema`, `two_group_app`. A copied fixture helper is a defect, not a convenience; only a deliberately different fixture (an unnamed banner titled `(unnamed)` instead of `""`) stays separate, with a comment saying why.
- `theme::every_token()` is the sweep's enumeration: a token missing from it is a token no determinism, opacity or contrast sweep proves, so adding a token means adding it there.
- A bug fix needs a test that would have caught it; a plan task without a test step is incomplete (OpenSpec `tasks` rule).

## Code Health
- **No dead code**: every type, variant, field, derive, trait and function in `src/` has a current consumer — delete on sight instead of keeping it for "later" (the YAGNI anchor). `cargo clippy --all-targets --all-features --locked -- -D warnings` already denies `dead_code`, and `#[allow(dead_code)]`/`#[expect(dead_code)]` is never the fix: `scripts/codehealth.py` fails on a new one. A `dead_code` hint on something reached only through trait dispatch or referenced only in type position is a false positive — verify before deleting, never silence.
- **Complexity budget: 15 decision points per function**, where a decision point is `if`, `for`, `while`, `loop`, a `match` arm, `&&`, `||`, `?`, or the `unwrap_or`/`map_or`/`and_then`/`or_else` combinators. `python3 scripts/codehealth.py` measures it over production code (test modules and `#[test]` functions excluded) and exits non-zero above budget. A function at 16+ is split by section — ordered handler tables, `CellPass`-style passes, named lookups — never by extracting a body that still holds all the branches.
- **No duplicated block**: an identical run of 8 normalised lines (comments and blank lines removed) appearing at two places in production code is a defect; the shared helper moves to its owner — `src/test_support.rs` for a fixture, the domain module for production — and a block that only *looks* similar stays separate. `scripts/codehealth.py` names both locations.
- **The budget is a ratchet, not a snapshot**: `scripts/codehealth-baseline.txt` records the pre-existing offenders so the gate fails on new debt only; a fix deletes its baseline line in the same change. `--update-baseline` regenerates the file after a fix or a deliberate, justified decision — it is never the way to accept a regression, and no baseline line is ever hand-written.
- **A code-health change is behaviour-preserving**: it lands as `refactor:` commits with fmt, clippy `-D warnings`, the full suite and the self-test green, and the diff moves no test expectation, key binding, colour token or published rect.

## Documentation
- **A derived artifact is regenerated in the change that moves its facts**: `ARCHITECTURE.md` (`/make-architecture`), `DESIGN.md` (`/make-design`) and this skill (`/make-guardrails`) each carry a `Last updated` footer; a change that moves a fact they state regenerates them in that change and never hand-edits the sentence. A footer older than `git log -- src/` is a verification finding, not cosmetic drift.

A change that moves a fact on one of those pages updates that page in the same change.

## Build & Deployment
- Build: `cargo build` (debug) / `cargo build --release --locked`; the artifact is `droid_tui` (Linux), `droid_tui.exe` (Windows) or a `droid_tui.app` bundle (macOS). A fresh checkout needs the submodule initialised first.
- Gate at CI parity before reporting completion: `cargo fmt --check`, `cargo clippy --all-targets --all-features --locked -- -D warnings`, `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --locked`, `python3 scripts/codehealth.py`, `python3 tools/acquire_geometry.py --check`, `cargo test --locked`, `cargo build --release --locked`, `cargo test --release --test perf_gate --locked` (Linux), `cargo run --release -- --self-test fixtures/own_buttons.ini` and `cargo build --manifest-path tools/screenshots/Cargo.toml --locked`. CI runs this whole set on Linux; the Windows and macOS jobs run the tests, the release build and the self-test.
- CI (`.github/workflows/ci.yml`): a three-OS matrix (`ubuntu`, `windows`, `macos`, `fail-fast: false`) that checks out with `submodules: false` and then runs `git submodule update --init ext/droid-lsp`; all three run `cargo test --locked`, the release build and the headless self-test; Linux additionally runs fmt, clippy, rustdoc, the perf gate and the `tools/screenshots` harness build. CI never opens a window, never talks to MIDI and never publishes.
- Release (`.github/workflows/release.yml`): a `v*` tag (or a manual run naming one) produces the unsigned Windows x86_64 zip and the macOS universal zip (`scripts/package-macos.sh`, `lipo`/`ditto`), versioned from the tag; the release is created as a draft and publishing is a human step. There are no installers, no code signing and no prebuilt Linux binary.
- **A new `src/` module needs a shadow in the screenshot harness**: `tools/screenshots/src/main.rs` lists the module set of `src/lib.rs` in the same order via `#[path]`, and `crate::<module>` paths inside the app sources resolve only through those shadows. Adding a module to `src/lib.rs` without its entry compiles the app but breaks the CI step that builds `tools/screenshots` (it compiles the real sources unmodified) — add the shadow in the same change.
- Screenshots for `docs/assets` come from `tools/screenshots` (a tools-only crate that path-shadows the app sources, so renders track the real paint path); regenerate rather than hand-editing images.

## Git Workflow
- Backlog platform is `browser` (work items through `@pc-userstory`); the repo platform is `none` (no PR/MR automation). Max 3 concurrent agents.
- OpenSpec change workflow: propose under `openspec/changes/<slug>`, implement on `feature/<slug>`, merge to `main`, archive into `openspec/changes/archive/` (the archive commit lands on `archive/<slug>`) and sync the deltas into `openspec/specs/`. Never mix backlog and repo CLIs.
- Task tracking is beads (`bd`); the profile is conservative — no commits, pushes or Dolt sync without explicit approval.
- Commit style follows the history: imperative one-liners, often `area: summary` or `type: summary` (`gate: …`, `fix: …`, `refactor: …`); keep generated docs out of a behaviour commit's diff unless regenerated deliberately.

## Security
- No secrets, no network, no auth, no multi-user state. The only external input is local `.ini` files: the parser returns descriptive `Err(String)` and never panics, graph edge building skips unresolvable names, and validation gates `Error`-severity findings before anything renders.
- The lossless writer refuses to overwrite its own source path, writes atomically (tmp→rename) and auto-suffixes on collision; the optimizer export shares that path.
- The one subprocess edge is the confirmed SysEx upload (`amidi`/`sendmidi`, no shell); the staged `.syx` tmpfile and the child are cleaned on drop/quit. Never widen this edge to read from hardware.
- Release artifacts are unsigned and not notarised: never describe a build as signed, and keep `docs/platforms.md` honest about Gatekeeper/SmartScreen warnings.
- A panic must leave no orphaned window: the chained panic hook runs the one-shot `destroy_window_for_panic` with each teardown step contained.

## Data & State
- Four user stores in one platform data directory (`<data dir>/droid-tui/`): `config.toml`, `labels.toml`, `favourites.toml`, `plugins/*.toml`. Every path resolves through `platform.rs` and every TOML read/write goes through `store.rs`: missing or unreadable → defaults, malformed → one warning + defaults, writes atomic, keys canonical (`store::canonical_key`).
- `config.toml` (schema version 1): `theme`; `[labels] layers_enabled`/`max_shift_layer` (clamped 1..8); `[latency] per_circuit`; `[layout] mode` (`column` default / `force` / `sections`), `ordering` (`strict` default / `barycenter` / `patch`), `slice_force` and `section_force`; `[graph] group_enabled` (default `true`), `min_group_size` (default 5, clamped 2..=64) and `group_by` (`type` default / `run`); `[physical] labels` (`off`/`auto`/`on`), `show_skeleton`, `zoom` (0.25–4.0, with the `zoom_baseline` marker guarding pre-1:1 values), `offset_x`/`offset_y`; `[physical.rack]` (`rows: [{he, hp, label?, modules?}]`, `top_mount_te`, `side_mount_te`, `assign`); `[plugins] dir` (absolute override only) and `enabled`. Sanitise on load **and** save; unknown values warn once and fall back. Each row inventory is re-emitted from its parsed key on both paths (an alias is stored as `master 1`), a malformed entry is dropped instead of failing the config, and an empty list never gains the key.
- `labels.toml` is the only per-patch persistence (`hw` per token per layer, `circuits` per `NodeId`, keyed by the canonicalized absolute patch path). Nothing else about a patch is stored.
- Everything else is in-memory `App` state and resets on `load_patch`: selection, `hold_component`/`latched_component`/`modifier_influence`/`influence_subset`, `active_shift`, pane layout and both split ratios, `graph`/positions/`pinned`/`graph_camera`/`graph_settle`, `layout_mode`/`layout_ordering`/`tension`/solver knobs, `graph_grouping`/`expanded_groups`/`isolated_group`/the `grouped_view` cache/`minimap_drag`, `validation_issues`, `diff_*`, `select_state`, `dependency_*`, `optimizer_diff_state`, `disabled_circuits`, `processing_paused`, `master_plan`, `physical_zoom`/`physical_offset`/`physical_fit_mode`/`physical_nav_latched`, `status_message`.
- Build-time inputs are embedded, never read at runtime: `circuits.json`, `rack_geometry.json`, `controller_geometry.json`, `tools/outlier_artifact.txt`, `tools/influence_stats.txt`. A binary copied away from the repository still has its schema and geometry — editing any of them needs a rebuild, not a reinstall.
- Do not add persistence, a store version bump or a migration without an OpenSpec change; the only versioning device in use is the `zoom_baseline` marker.
