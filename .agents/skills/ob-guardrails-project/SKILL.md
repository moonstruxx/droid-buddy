## Architecture Constraints
- Rust 2021 edition, single binary crate `droid_tui` (Cargo.toml) — a TUI for loading and interacting with DROID hardware patches.
- Layered module structure: `src/main.rs` (entry, terminal lifecycle) → `src/app.rs` (application state) → `src/handler.rs` (keyboard input) → `src/patch.rs` (DROID patch data model + cable index + banner groups) → `src/graph.rs` (signal-flow graph model, pure) → `src/layout.rs` (force-directed solver, pure) → `src/events.rs` (synchronous observer bus, pure) → `src/ui.rs` (rendering).
- Dependency direction is one-way: `ui` and `handler` depend on `app` and `patch`; `app` depends on `patch`, `graph`, `layout`, and `events`; `graph` depends on `patch`; `layout` depends on `graph`; `events` uses `graph` types only. `patch` must not import `app`, `handler`, `ui`, `graph`, `layout`, or `events`; `graph`/`layout`/`events` must stay pure (no terminal dependency).
- The DROID patch data model (serde `Serialize`/`Deserialize`) lives in `src/patch.rs`; keep serialization concerns there. Source viewing is an in-process UI feature, not an external protocol.
- The renderer owns layout: `ui.rs` publishes `component_rects` into `App` each frame; `handler.rs` reads them for mouse hit-testing. Only the renderer knows where components landed. Modifier-panel-highlight: structural influence via `Patch.hw_token_to_vars` → `Patch.influence_subtree` (forward BFS over `cable_index` + `circuit_outputs`, cycle-safe, `B1.1`→`_TRIG`; `hash(token)%16` hue via `theme::modifier_hue`), `App.active_modifier_var` + `App.influence` single-var reality today (second select replaces first; no `influence_cache`; additive `MOD B1.1+B1.2` union aspirational), interaction `Mouse Down` momentary (Up/Leave clears) / `Ctrl+Shift+Click` (alias `Ctrl+Click`) toggle latched / `m` keyboard alias for hovered component / `Esc` clears shift+modifier, rendering priority `graph_edge_error` (red) > modifier hue > `CableKind`, status `MOD token → N cells / M cables` (single-var) / `MOD B1.1+B1.2 → N cells / M cables` additive aspirational in hue with shift border + modifier bg coexistence.
- Layout is recomputed fresh from `frame.area()` on every draw — `Event::Resize` is a no-op; do not add resize state.
- The `.ini` parser is hand-rolled (the `ini` crate was removed): it preserves repeated section names and uses a boundary-aware token scanner so internal variables like `_ENV1_DECAY_POT` are not misread as hardware tokens.
- The parser retains verbatim raw lines and 0-based line/byte-column spans for section headers and hardware-token hits; `Patch` builds ordered occurrence indexes and cycle-safe `select`/`selectat` modifier indexes for named source-navigation consumers.
- Components are grouped by physical controller (`HwComponent.controller`); shift groups are an enum (`ShiftGroup::Group1–4`) with `color()`/`key_label()` as the single source of truth.
- The app is a patch viewer/simulator, NOT a hardware bridge: no MIDI, no network, no hardware I/O at runtime.
- The source viewer is embedded in the main TUI and opened with `g v`; it shares `App` state with panels and renders raw patch lines through parser-recorded spans and indexes.
- Viewer state uses `selected_component`, `ViewerFocus`, `SourceViewMode`, `occurrence_cursor`, `source_scroll`, `minimap_rect`, and `source_pane_rect`. Panels stay live while the viewer is open: non-conflicting panel keys (toggle, shift, scale, orientation) work from either focus, only `j/k` and arrow navigation are routed by focus (Tab switches), Esc closes while keeping selection and source position, and picker precedence remains highest.
- The renderer publishes `component_rects`, optional `minimap_rect`, and optional `source_pane_rect` each frame; handler uses them for mouse hit-testing, proportional minimap scrolling, and click-to-focus routing between panels and source pane.
- Boxed rendering is gated on parse-time LED association: a component renders as ONE bordered cell only when `HwComponent.led` is `Some` — detected from a bare `led = L.N` entry OR a numbered circuit param `ledN = L.M` paired by shared numeric suffix with a same-suffix element entry (`buttonN`/`potN`), the DROID convention for circuits like `matrixmixer`. The border uses the component-kind color; the element symbol + label live in the box's top title row and the single interior row holds state + the LED glyph (one state, not a duplicate textual LED state). LED-less components keep two-line text rendering; LEDs are never standalone cells.
- Panels may contain modules: a controller panel whose components come from more than one circuit instance is subdivided by `HwComponent.module_instance()` (the leading digit run of the token id, e.g. `1` in `B1.1`) into per-instance module sub-blocks, each bordered and titled with the instance number (`P2B8 1`); a single-instance panel renders as one flat grid and CV I/O never subdivides. Panel height is sized from the visible (LED-folded) component count, and the published `component_rects` hit rects must exactly match the rendered cell size — `scale_factor` is not applied to layout and must not inflate hit rects (that caused wrong hover/selection).
- The embedded viewer's panels/source column ratio is `App.viewer_split_ratio` (default 0.6, clamped 0.3–0.7, persists across `load_patch`; adjusted via `adjust_viewer_split_ratio(delta)`); `[`/`]` nudge it by exact 0.1 steps only while `showing_viewer` is true. `render_viewer_status(frame, area, app)` takes `&App` and must never let the trailing transient status message displace the hint spans.
- The signal-flow graph view (`g g`, mirroring `g v`) is a full-screen surface in the main band (header/status bands stay). `App` holds `showing_graph`, `graph: Option<Graph>`, `graph_positions` (parallel to `graph.nodes`), `graph_cluster_rects`, `graph_node_rects`, `graph_drag: Option<GraphDrag>`, and `events: EventBus`. `open_graph` builds via `Graph::build_from_patch(patch, clusters_from_patch(patch))` and runs a fresh full `layout::solve`; with no patch the view still opens (empty-graph message). While open the surface owns all mouse input — left-drag a node repositions it, release runs a damped `layout::local_resettle` — Esc closes, `q`/Ctrl+C still quit, `l` still opens the picker.
- Graph modules stay pure and deterministic: `graph.rs` builds nodes/edges/clusters from `Patch` (cable index + banner groups) and runs topology validation at build time (exactly-one-source per cable — dangling sink `Warning`, `n → 1` `Error`; findings never block building/viewing); `layout.rs` is a one-shot solver, not a simulation (full solve ≤ 300 iterations, local re-settle ≤ 40, no RNG — seeds from topological depth + cluster bands + node-id hash, edges sorted by `(cable, source, sink)` for reproducible f32 accumulation); `events.rs` is a synchronous observer bus (`GraphRebuilt`/`NodeMoved`/`TopologyError`, inline dispatch in subscription order, no queueing). The renderer publishes `graph_node_rects`/`graph_cluster_rects` per frame (mirroring `component_rects`) for drag hit-testing; `render_graph` splits `App` field borrows because it reads `graph` and mutates the rect fields.

## Design System
- Semantic colors (ANSI 16, terminal-dependent): component kinds — button/switch white, knob/encoder magenta, CV-in cyan, CV-out green, LED red; shift groups — 1 yellow, 2 cyan, 3 magenta, 4 green; accents — blue (header/picker/sidebar borders), dark-gray (muted/content/minimap/status background); source view — occurrences yellow, boolean/transitive modifier highlights cyan, exact-value modifier highlights magenta, current occurrence reversed.
- Spacing grid: component cell 16×3 (boxed LED cells and text cells share the grid); the scale preset (`+`/`-` cycle 50% → 100% → 150% → 200% with wrap-around) is tracked/reported as `Scaling: N%` but does NOT resize rendered cells, so hit rects stay 16×3; multi-instance panels subdivide into per-instance module sub-blocks; orientation Portrait/Landscape toggled with `o`, panels/source split adjusted with `[`/`]` (30–70%, default 60/40); header 3 rows, status 3 rows, source status 3 rows, main min 10, panel padding 1, picker ~70%×50% centered, source sidebar width = source pane width / 5 (min 20), minimap width 3 and hidden when source pane width < 40 or total area < 80.
- Modifiers: bold = emphasis, dim = de-emphasis, reversed = hover + viewer selection. No motion, radii, shadows, or elevation.
- Glyphs: button `●`/`○`, switch `▣`/`□`, LED `◉`/`○`, knob/encoder `◉`+percentage, CV `→`/`←`, picker selection `▶`; graph ports — left `◉` input on cable sinks, right `●` output on sources (presence markers, not per-parameter pairing).
- Graph surface: nodes 22×5 with rounded frames (`BorderType::Rounded`), title = circuit name + instance index when repeated (`copy`, `copy (1)`, …), node border white / title yellow; cluster containers = titled plain-bordered padded (2) unions of member rects, blue border/title; cable edges = box-drawing polylines (`│ ─ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼`) colored by inferred kind from the producing circuit's name — control (clock/gate/trigger/pulsar/div) cyan, audio (default) green, midi (midi/note/seq/pitch) magenta, unknown dark-gray — overridden by red when a topology-validation finding references the cable. Graph tokens: `graph_node_border`/`graph_node_title`, `graph_port_input`/`graph_port_output`, `graph_cluster_border`/`graph_cluster_title`, `graph_edge_control`/`audio`/`midi`/`unknown`/`error` (mono keeps the five edge colors pairwise distinct; terminal all `Reset`).

## Security
- No secrets, no network, no auth: the only external input is local `.ini` files, parsed defensively (descriptive `Err(String)`, never panics on malformed input).
- Terminal hygiene: raw mode, alternate screen, and mouse capture are restored on normal exit and on panic (chained panic hook).

## Data & State
- No persistence: all state lives in `App` in memory; the app writes no files at runtime. Viewer selection, focus, mode, occurrence cursor, scroll, and minimap geometry reset with in-memory app state.
- serde derives on the domain model (`patch.rs`) exist for future export; there is no storage layer or external viewer protocol. Do not add persistence without an OpenSpec change.

## Domain-Specific: DROID
- Hardware tokens: `B` button, `L` LED, `P` pot, `O` CV out, `I` CV in, `E` encoder, `S` switch, each followed by a digit address (e.g. `B1.1`, `P1.1`).
- Controllers: P2B8, Faderbank, Notebuttons, Encoder, Pot, Unusedfaders, etc. — component grouping mirrors physical panels.
- Authoritative circuit schema: `droid_living_examlpes/droid-lsp/src/circuits.json` (76 circuits, 10 controllers) — machine-local symlink, untracked; do not commit it.
- DROID reference skills: `droid-patch-format` (token grammar, RAM sizes, circuit catalog), `droid-circuit-reference`, `droid-patch-cookbook` (global).
- Virtual cables: signal wiring runs over named cables starting with `_` (e.g. `_PULSARCLOCK`); a circuit produces one via `output = _NAME`, any number of other circuits consume it via params like `input = _NAME`. Valid topology: 1 source feeds n sinks; n sources into one sink is invalid (the graph's topology validation flags it). Direct token references (`out1 = B1.1`) are valid but rare.
