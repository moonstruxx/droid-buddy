# Project Guardrails

> Auto-generated by `/make-guardrails`. Regenerate with the same command when architecture or conventions change significantly.

## Semantic Anchors
- **UI mirrors HW (1:1 alignment, HIGH PRIORITY)**: the UI must render hardware components at the same positions as on the physical modules — the user performs live mixes and must be able to grab the SAME button in the UI and on the hardware at any moment without abstraction. The goal is **recognizability, not reproduction**: keep 100% of the geometric arrangement (relative positions, ordering, adjacency, grid structure — which control sits where relative to its neighbors, which panel is where), but simplify the visual representation (existing glyphs, labels, colors — never a literal copy of the physical part). Grids are fixed to hardware geometry per controller (never terminal-width-derived), panels follow physical rack positions, and each element's built-in LED is joined positionally to its element (L1.1 bound to B1.1). "Built-in" means the controller's physical design, not what the patch happens to declare. If terminal stacking cannot deliver the mirror, the `kitty-gfx` escape hatch (Cargo.toml feature flag, currently a box-drawing stub) may be enabled to bring more UI in.
- **YAGNI**: every type, variant, derive, and trait in `src/` must have a current consumer — dead code is deleted on sight, not preserved for "future" use. Speculative features (persistence, hardware bridge) are deferred ideas; introducing them requires an OpenSpec change.
- **DRY**: one source of truth per fact. Generated docs (ARCHITECTURE.md, DESIGN.md, guardrails) are derived artifacts — edit code and regenerate via `/make-*`, never hand-edit generated docs. The circuit schema (`ext/droid-lsp/droid-lsp/src/circuits.json`) and the rack layout (`rack_geometry.json`) are single-source build-time inputs — never fork a copy inside `src/`.
- **CodeAsDoc**: names carry DROID domain meaning; doc comments explain non-obvious invariants and reasons, never restate code (AGENTS.md); OpenSpec specs are the behavior contract, code is the executable spec.
- **TDD London** (mockist, outside-in): test through public entry points (`handle_event`, `render`, `validate_patch`, `diff_patches`); use real fixtures for cheap deterministic collaborators (filesystem, terminal); mock only genuinely costly or unreliable boundaries — none today. Keep the renderer→handler geometry handoff (`component_rects`) collaboration test.

## Architecture Constraints
- Rust 2021 edition, single binary crate `droid_tui` (Cargo.toml) — a TUI for loading and interacting with DROID hardware patches.
- Layered module structure (wired in `src/lib.rs`): `src/main.rs` (entry, terminal lifecycle) → `src/app.rs` (application state) → `src/handler.rs` (keyboard input) → `src/patch.rs` (DROID patch data model + cable index + banner groups + `EntrySpan` spans) → `src/schema.rs` (embedded circuit schema, pure) → `src/validation.rs` (pure patch validation) → `src/diff.rs` (pure patch diff) → `src/geometry.rs` (pure rack geometry) → `src/graph.rs` (signal-flow graph model, pure) → `src/layout.rs` (force-directed solver, pure) → `src/events.rs` (synchronous observer bus, pure) → `src/ui.rs` (rendering).
- Dependency direction is one-way: `ui` and `handler` depend on `app` and `patch`; `app` depends on `patch`, `graph`, `layout`, `events`, `validation`, `schema`, `diff`, and `geometry`; `graph` depends on `patch` and `geometry`; `layout` depends on `graph`; `events` uses `graph` types only. `patch` must not import `app`, `handler`, `ui`, `graph`, `layout`, `events`, `validation`, `schema`, `diff`, or `geometry`.
- Pure modules must stay pure: `graph`, `layout`, `events`, `validation`, `schema`, `diff`, and `geometry` have **no terminal dependency, no I/O, and no `App` dependency** — `validation::validate_patch(&Patch) -> Vec<ValidationIssue>` and `diff::diff_patches(&Patch, &Patch) -> DiffReport` are pure functions over parsed input; `schema.rs` reads its data via `include_str!` at compile time; `geometry::load()` is the single I/O exception and is confined to reading `rack_geometry.json` via `CARGO_MANIFEST_DIR` (no other module may read files). Never add a `ui`/`crossterm`/`ratatui` import or an `App` parameter to a pure module.
- The DROID patch data model (serde `Serialize`/`Deserialize`) lives in `src/patch.rs`; keep serialization concerns there. Source viewing is an in-process UI feature, not an external protocol.
- The renderer owns layout: `ui.rs` publishes `component_rects` into `App` each frame; `handler.rs` reads them for mouse hit-testing. Only the renderer knows where components landed. Modifier-panel-highlight: structural influence via `Patch.hw_token_to_vars` → `Patch.influence_subtree` (forward BFS over `cable_index` + `circuit_outputs`, cycle-safe, `B1.1`→`_TRIG`; `hash(token)%16` hue via `theme::modifier_hue`), `App.active_modifier_var` + `App.influence` single-var reality today (second select replaces first; no `influence_cache`; additive `MOD B1.1+B1.2` union aspirational), interaction `Mouse Down` momentary (Up/Leave clears) / `Ctrl+Shift+Click` (alias `Ctrl+Click`) toggle latched / `m` keyboard alias for hovered component / `Esc` clears shift+modifier, rendering priority `graph_edge_error` (red) > modifier hue > `CableKind`, status `MOD token → N cells / M cables` (single-var) / `MOD B1.1+B1.2 → N cells / M cables` additive aspirational in hue with shift border + modifier bg coexistence.
- Layout is recomputed fresh from `frame.area()` on every draw — `Event::Resize` is a no-op; do not add resize state.
- The `.ini` parser is hand-rolled (the `ini` crate was removed): it preserves repeated section names and uses a boundary-aware token scanner so internal variables like `_ENV1_DECAY_POT` are not misread as hardware tokens.
- The parser retains verbatim raw lines and 0-based line/byte-column spans for section headers, hardware-token hits, **and every entry**: `IniSection.entries` carries per-entry `EntrySpan { key, value, key_span, value_span, line }` captured **before lowercasing** (alongside `header_span`/`raw_lines`) — the validation modal's jump-to-source depends on these being original-case byte offsets; never replace them with post-lowercase indices. `Patch` builds ordered occurrence indexes and cycle-safe `select`/`selectat` modifier indexes for named source-navigation consumers.
- Components are grouped by physical controller (`HwComponent.controller`); shift groups are an enum (`ShiftGroup::Group1–4`) with `color()`/`key_label()` as the single source of truth.
- The app is a patch viewer/simulator, NOT a hardware bridge: no MIDI, no network, no hardware I/O at runtime. Validation, diffing, and geometry all run in-process.
- The source viewer is embedded in the main TUI and opened with `g v`; it shares `App` state with panels and renders raw patch lines through parser-recorded spans and indexes.
- Viewer state uses `selected_component`, `ViewerFocus`, `SourceViewMode`, `occurrence_cursor`, `source_scroll`, `minimap_rect`, and `source_pane_rect`. Panels stay live while the viewer is open: non-conflicting panel keys (toggle, shift, scale, orientation) work from either focus, only `j/k` and arrow navigation are routed by focus (Tab switches), Esc closes while keeping selection and source position, and picker precedence remains highest.
- The renderer publishes `component_rects`, optional `minimap_rect`, and optional `source_pane_rect` each frame; handler uses them for mouse hit-testing, proportional minimap scrolling, and click-to-focus routing between panels and source pane.
- Boxed rendering is gated on parse-time LED association: a component renders as ONE bordered cell only when `HwComponent.led` is `Some` — detected from a bare `led = L.N` entry OR a numbered circuit param `ledN = L.M` paired by shared numeric suffix with a same-suffix element entry (`buttonN`/`potN`), the DROID convention for circuits like `matrixmixer`. The border uses the component-kind color; the element symbol + label live in the box's top title row and the single interior row holds state + the LED glyph (one state, not a duplicate textual LED state). LED-less components keep two-line text rendering; LEDs are never standalone cells.
- Panels may contain modules: a controller panel whose components come from more than one circuit instance is subdivided by `HwComponent.module_instance()` (the leading digit run of the token id, e.g. `1` in `B1.1`) into per-instance module sub-blocks, each bordered and titled with the instance number (`P2B8 1`); a single-instance panel renders as one flat grid and CV I/O never subdivides. Panel height is sized from the visible (LED-folded) component count, and the published `component_rects` hit rects must exactly match the rendered cell size — `scale_factor` is not applied to layout and must not inflate hit rects (that caused wrong hover/selection).
- The embedded viewer's panels/source column ratio is `App.viewer_split_ratio` (default 0.6, clamped 0.3–0.7, persists across `load_patch`; adjusted via `adjust_viewer_split_ratio(delta)`); `[`/`]` nudge it by exact 0.1 steps only while `showing_viewer` is true. `render_viewer_status(frame, area, app)` takes `&App` and must never let the trailing transient status message displace the hint spans.
- The signal-flow graph view (`g g`, mirroring `g v`) is a full-screen surface in the main band (header/status bands stay). `App` holds `showing_graph`, `graph: Option<Graph>`, `graph_positions` (parallel to `graph.nodes`), `graph_cluster_rects`, `graph_node_rects`, `graph_drag: Option<GraphDrag>`, and `events: EventBus`. `open_graph` builds via `Graph::build_from_patch(patch, clusters_from_patch(patch))` and runs a fresh full `layout::solve`; with no patch the view still opens (empty-graph message). While open the surface owns all mouse input — left-drag a node repositions it, release runs a damped `layout::local_resettle` — Esc closes, `q`/Ctrl+C still quit, `l` still opens the picker.
- Global processing pause (`p` key): `App.processing_paused: bool` — while set, ALL panel content renders dim, the header shows a `PROCESSING PAUSED` marker, and component mutations are blocked (toggles/value changes are no-ops); geometry (`component_rects`) stays unchanged so mouse hit-testing keeps working; `load_patch` resets it. `toggle_processing_pause` flips the flag and clears `hovered_graph_node`.
- Per-circuit processing disable (`x` key on the graph surface): `App.disabled_circuits: HashSet<(String, usize)>` keyed by `(circuit name, instance index)`; `x` toggles the hovered circuit instance (`App.hovered_graph_node` from `graph_node_rects` hit-testing; silent no-op with no hover), then `rebuild_graph` re-runs `Graph::build_from_patch` + `layout::solve` and emits `GraphRebuilt`, and influence recomputes dead-ending at disabled sinks (`influence_subtree_with_disabled`); `load_patch` resets the set. Disabled nodes and incident edges render with the `graph_node_dim`/`graph_edge_dim` tokens (dim modifier) — this overrides the modifier hue but must preserve the red `graph_edge_error` highlight and hover styling.
- Graph modules stay pure and deterministic: `graph.rs` builds nodes/edges/clusters from `Patch` (cable index + banner groups) and runs topology validation at build time (exactly-one-source per cable — dangling sink `Warning`, `n → 1` `Error`; findings never block building/viewing) **plus wiring-outlier detection**: `validate_topology` resolves `geometry::RackGeometry` and flags cables whose endpoint distance exceeds `DISTANCE_THRESHOLD` (8.0) as a `Warning` reusing the `graph_edge_error` red highlight — do not change the threshold or color without an OpenSpec change. `layout.rs` is a one-shot solver, not a simulation (full solve ≤ 300 iterations, local re-settle ≤ 40, no RNG — seeds from topological depth + cluster bands + node-id hash, edges sorted by `(cable, source, sink)` for reproducible f32 accumulation); `events.rs` is a synchronous observer bus (`GraphRebuilt`/`NodeMoved`/`TopologyError`/`ValidationCompleted`/`DiffComputed`, inline dispatch in subscription order, no queueing). The renderer publishes `graph_node_rects`/`graph_cluster_rects` per frame (mirroring `component_rects`) for drag hit-testing; `render_graph` splits `App` field borrows because it reads `graph` and mutates the rect fields.
- Patch validation runs on every load and gates on severity: `App::load_patch` runs `validation::validate_patch` over the parsed `Patch` — **any `Error`-severity finding rejects the patch** (`patch=None`, failure modal, `clear_validation`), while `Warning`/`Hint` findings still load and populate `validation_issues`; completion dispatches `Event::ValidationCompleted`. The 9 checks (`unknown_circuit` Error+suggestion, `duplicate_param` Warning, `unknown_param` Error, `invalid_jack` Warning, `missing_required` Warning@header, `undefined_cable`/`duplicate_cable` Warning, `unused_cable` Hint, `ramsize` Error) are ported 1:1 from `ext/droid-lsp/droid-lsp/src/diagnostics.ts` and the issue list is sorted by (line, col); each `ValidationIssue { span, severity, code, message }` carries an `EntrySpan` so the modal (`e` toggles, `j`/`k` navigate, `Enter` jumps to source, `Esc` closes) can jump to the exact location. Never relax the Error-gating rule, and never make validation depend on `App` state.
- `src/schema.rs` embeds the authoritative schema at build time: `include_str!("../ext/droid-lsp/droid-lsp/src/circuits.json")` — the vendored `ext/droid-lsp` git submodule is the source of truth; `loadSchema` parses it once, `JackTable` feeds valid-jack checks, `prefix`/`count`/`start_at` expansion covers numbered params, and a Levenshtein helper proposes the nearest circuit for `unknown_circuit`. Never edit the embedded JSON in place (edit the vendored submodule and rebuild); the build fails until `git submodule update --init` is run.
- `src/diff.rs` is a pure, **read-only** diff model: `diff_patches(base: &Patch, new: &Patch) -> DiffReport` classifies added/removed/changed cables + nodes, each list sorted for stable output. The diff never mutates either patch and has no terminal dependency. Wiring: `g d` opens the picker to choose the B patch → `App::load_diff_patch` computes the report once and dispatches `Event::DiffComputed`; `d` toggles the overlay; `Esc` clears the `diff_scope` filter first, then hides the overlay; `diff_scope` filters via `scope_report` so the graph highlight and `status_for_scope()` ("Diff scope: {token} (N cables)") agree.
- `src/geometry.rs` is a pure rack-geometry model (`RackGeometry`/`Rack`/`ControllerSlot`) whose serde types mirror the `rack_geometry.json` schema at the repo root — keep the mirror in sync whenever that file's layout changes; `load()` reads it once via `CARGO_MANIFEST_DIR` (no other file access), `resolve()` places controllers into slots, and `distance()`/`is_adjacent()` feed `validate_topology`.
- Label overlay is edit-in-place with no `.ini` mutation: `LabelStore` at `$XDG_CONFIG_HOME/droid-tui/labels.toml` (canonicalized absolute patch path buckets, `hw` per-`HwToken` per-`ShiftGroup` slot 1..=max_shift_layer + `circuits` per-`NodeId`, atomic tmp→rename, warn-once on corrupt TOML). `Patch::display_label` merges `store[layer]→store[1]→preamble[1]→derived` with `effective_shift` clamping 1..8 and `layers_enabled=false` coercing to layer 1 while preserving 2..N; empty `I4:` treated as absent. `circuit_label` overrides source header + graph node title in both FULL and FILTERED panes. `App.editing: Option<EditState>` holds kind HW/Circuit + per-layer drafts; `handler.rs` priority is overlay→picker→prefix→graph→source→panels, `e` enters for focused panel token / source header instance / `hovered_graph_node`, `1..N` cycles Group layer preserving drafts, `Enter` saves + `recompute_influence` for `<token> / Group<N> → N ckts / M cables` status in `modifier_hue` (`graph_edge_error` red > modifier hue > `CableKind`), `Esc` cancels; `ui.rs` renders HW cells via `display_label`, source headers + graph nodes via `circuit_label`, and the centered single-field overlay z-layer with same hue/error precedence, responsive per width.

## Design System
- Semantic colors (ANSI 16, terminal-dependent): component kinds — button/switch white, knob/encoder magenta, CV-in cyan, CV-out green, LED red; shift groups — 1 yellow, 2 cyan, 3 magenta, 4 green; accents — blue (header/picker/sidebar borders), dark-gray (muted/content/minimap/status background); source view — occurrences yellow, boolean/transitive modifier highlights cyan, exact-value modifier highlights magenta, current occurrence reversed. Graph surface dim tokens: `graph_node_dim` (gray classic / black mono) and `graph_edge_dim` (dark-gray classic/mono) render disabled circuits dim; `switch` token keeps switches tellable apart from buttons (dark-gray in mono, white in classic). The `dim` modifier is also the global paused-panel treatment (`processing_paused`).
- Validation severity tokens: `validation_error` red, `validation_warning` yellow, `validation_hint` cyan (bold severity brackets) plus modal chrome `validation_modal_border` (red) and `validation_selected_bg` (dark-gray); diff tokens: `graph_edge_diff_added` green, `graph_edge_diff_removed` magenta (plus `diff` `added`/`removed`). Edge-color precedence when the diff is shown: topology-error red > diff colors > cable-kind inference; dim (`graph_edge_dim`) still wins over diff and hue but preserves the red error highlight.
- Spacing grid: component cell 16×3 (boxed LED cells and text cells share the grid); the scale preset (`+`/`-` cycle 50% → 100% → 150% → 200% with wrap-around) is tracked/reported as `Scaling: N%` but does NOT resize rendered cells, so hit rects stay 16×3; multi-instance panels subdivide into per-instance module sub-blocks; orientation Portrait/Landscape toggled with `o`, panels/source split adjusted with `[`/`]` (30–70%, default 60/40); header 3 rows, status 3 rows, source status 3 rows, main min 10, panel padding 1, picker ~70%×50% centered, source sidebar width = source pane width / 5 (min 20), minimap width 3 and hidden when source pane width < 40 or total area < 80; validation modal ≈60%×70% centered (clamped; shrinks to near full-main-width on narrow terminals).
- Modifiers: bold = emphasis, dim = de-emphasis, reversed = hover + viewer selection. No motion, radii, shadows, or elevation.
- Glyphs: button `●`/`○`, switch `▣`/`□`, LED `◉`/`○`, knob/encoder `◉`+percentage, CV `→`/`←`, picker selection `▶`; graph ports — left `◉` input on cable sinks, right `●` output on sources (presence markers, not per-parameter pairing). A switch in `ComponentState::Value` mirrors the knob/encoder percentage display (state text shows the percentage, rendered in the `switch` token, e.g. mono DarkGray so switches stay tellable apart from buttons); on/off switches keep the filled/hollow glyph + label.
- Graph surface: nodes 22×5 with rounded frames (`BorderType::Rounded`), title = circuit name + instance index when repeated (`copy`, `copy (1)`, …), node border white / title yellow; cluster containers = titled plain-bordered padded (2) unions of member rects, blue border/title; cable edges = box-drawing polylines (`│ ─ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼`) colored by inferred kind from the producing circuit's name — control (clock/gate/trigger/pulsar/div) cyan, audio (default) green, midi (midi/note/seq/pitch) magenta, unknown dark-gray — overridden by red when a topology-validation or wiring-outlier finding references the cable, and by the diff tokens when the diff overlay is shown. Graph tokens: `graph_node_border`/`graph_node_title`, `graph_port_input`/`graph_port_output`, `graph_cluster_border`/`graph_cluster_title`, `graph_edge_control`/`audio`/`midi`/`unknown`/`error` (mono keeps the five edge colors pairwise distinct; terminal all `Reset`).
- `DESIGN.md` (last updated 2026-08-28 · patch-validation + patch-diff-viewer + rack-wiring-outlier-detection) is the authoritative design reference; update it when the design system changes.

## Security
- No secrets, no network, no auth: the only external input is local `.ini` files, parsed defensively (descriptive `Err(String)`, never panics on malformed input; graph edge building skips unresolvable cable names instead of panicking; patch validation gates the load on `Error`-severity findings).
- Terminal hygiene: raw mode, alternate screen, and mouse capture are restored on normal exit and on panic (chained panic hook).

## Data & State

## Domain-Specific: DROID
- Hardware tokens: `B` button, `L` LED, `P` pot, `O` CV out, `I` CV in, `E` encoder, `S` switch, each followed by a digit address (e.g. `B1.1`, `P1.1`).
- Controllers: P2B8, Faderbank, Notebuttons, Encoder, Pot, Unusedfaders, etc. — component grouping mirrors physical panels.
- Authoritative circuit schema: `ext/droid-lsp/droid-lsp/src/circuits.json` (vendored git submodule, embedded at build time via `schema.rs`) — the single source of truth for circuit names, params, jacks, presets, and RAM sizes; the validation checks are ported 1:1 from `ext/droid-lsp/droid-lsp/src/diagnostics.ts`. Run `git submodule update --init` before building; do not commit the checkout.
- Rack geometry: `rack_geometry.json` at the repo root describes the physical rack (Rack/ControllerSlot layout); wiring-outlier detection flags cables whose endpoint modules are farther apart than `DISTANCE_THRESHOLD` (8.0) as a `Warning` during `validate_topology` — a physical sanity check layered on the logical topology rules.
- DROID reference skills: `droid-patch-format` (token grammar, RAM sizes, circuit catalog), `droid-circuit-reference`, `droid-patch-cookbook` (global).
- Virtual cables: signal wiring runs over named cables starting with `_` (e.g. `_PULSARCLOCK`); a circuit produces one via `output = _NAME`, any number of other circuits consume it via params like `input = _NAME`. Valid topology: 1 source feeds n sinks; n sources into one sink is invalid (the graph's topology validation flags it). Direct token references (`out1 = B1.1`) are valid but rare.
