# ARCHITECTURE.md

## Architecture Overview

`droid_tui` is a single-crate Rust desktop application for loading, inspecting, and interacting with DROID hardware patch files (`.ini`). It renders the hardware components a patch defines — buttons, knobs, CV I/O, encoders, LEDs, switches — as physical faceplates that mirror the controller layout (P2B8, Faderbank, Notebuttons, …), and supports keyboard and mouse interaction, shift-group visualization, and a modifier wash that recolors the cells a held or latched modifier influences across every surface. Clicking a module-UI element focuses it across surfaces: the cell stays selected on the faceplate, the source pane jumps to its occurrence, and the signal-flow graph highlights the element's register entity plus its influence subtree (a click never toggles component state — that stays on `Enter`/`Space`). The main band is a **class-based pane layout**: every view belongs to a window class (`PaneClass::Big` or `Small`), and the adaptive band splits into a full-height left big pane plus a right half that is either a single big pane (when no small-class view is open) or two stacked small panes. The module UI opens at startup in the left big pane with the source viewer in a small pane; the signal-flow graph (`g g`) and the module UI (`Physical`) are big-class views, while the source viewer (`g v`) and the latency optimizer (`g o`) are small-class views. Focus routing sends keys to exactly one pane at a time (`Tab`/`Shift+Tab` cycle focus in tree order; focused/unfocused borders use `pane_focus_border`/`pane_unfocused_border`), `r` rotates the focused pane through its class carousel, `z` maximizes a pane, and `Alt+b`/`Alt+s` swap same-class panes. The module UI is a **physical 1:1 layout**: a millimeter-accurate grid model of the rack — case rows, fold bars, mount sections, module faceplates — rendered to scale with pan (arrow keys / wheel) and zoom (`+`/`-`), plus an optional skeleton reference presentation (`s`) that swaps the full render for a pure geometry outline. Clicking the graph minimap pans the camera to the clicked world point. Centered overlays sit on top of the pane layout unchanged: the source pane links selected hardware components to their occurrences and modifier relationships; the signal-flow graph renders circuits as nodes and virtual `_cable` connections as directed edges, laid out by a deterministic column arrangement by default (the force-directed solver is retained and reachable via `h` or `[layout] mode = "force"`), with banner-group clusters, topology validation, and wiring-outlier detection; a validation modal, opened with `e`, lists schema and lint findings when a patch fails or warns; a patch diff surface, opened with `g` then `d`, highlights the differences between the loaded patch and a second one; and the latency optimizer (`g o`) opens as a small pane with the other panes still visible.

The system is a **layered monolith** with no framework, no async runtime, and no network: a single-threaded winit event loop reads window/keyboard/mouse events, mutates an in-memory application state, and repaints the egui surfaces. The domain model, `.ini` parser, signal-flow graph model, layout solver, circuit-schema validator, diff model, rack-geometry model, and physical-layout model are pure functions over strings/structs (no UI dependency); the gui paint layer owns all layout decisions and publishes per-frame geometry back to the state for mouse hit-testing.

The app is a **patch viewer/interactor with a one-way hardware bridge**: it parses `.ini` files and simulates component state locally, and it can send the in-memory patch to DROID hardware over MIDI SysEx (USB or DIN) through a confirm modal and a background transfer. It receives nothing back — no state is read from the rack.

## 3. Core Components

### 3.1 User Interface (`src/gui/`)

- **Responsibility**: paint the egui surfaces from `App` state each frame; compute layout; publish component and graph geometry for mouse hit-testing.
- **Key functions**: `gui/mod.rs::paint_panes` is the real dispatch: it derives every pane rect from `App::pane_geometry(band)` (the ADR 35 single geometry source, published as `pane_hit_rects` via `App::refresh_hit_geometry`) and paints each pane's view into its cell — `physical.rs::physical_spec(app, pane)`/`paint_physical` (the module UI: the mm grid anchored at the pane origin, pan/zoom, skeleton toggle, element-state cells, the `Module UI` pane frame, and the per-element `component_index` + rect list `paint_panes` republishes as `component_rects`), `graph.rs::paint_scene_in`/`build_scene_spec` (world-sized node bodies projected through the camera, zoom-scaled chrome, label level of detail), `viewer.rs::paint_viewer` (raw/prettified source blocks, sidebar, minimap, occurrence navigation, scroll), and `overlays.rs::paint_optimizer` (the optimizer's own pane). `gui/mod.rs::paint_overlays` dispatches the centered overlays over the base (diff, validation, select-state menu, picker, label editor, help). `graph.rs::graph_pane_rect` re-derives the graph pane from `App::pane_geometry` — not the legacy `tile_stack` slot mirror — so the scene origin, the first-frame fit, the published `graph_canvas_px`, and `paint_panes` all agree on one source (ADR 35; this is what lets `c` center the graph in its actual pane). Paint routines emit `egui::Shape`/`Shape::Text` and record `component_rects` / `graph_node_rects` / `graph_cluster_rects` / `pane_hit_rects` for hit-testing. Frame specs (`PhysicalFrame`, `ViewerFrame`, `PickerFrame`, `WindowFrame`) carry the egui/winit input to the handler layer, which applies the same key/mouse semantics as before (shift groups, g-prefix, p/x, scale/split, s, Tab focus, Esc, hover/click/scroll/drag).
- **Technologies**: egui (`Painter`, `Shape`, `Rect`, `Context`), winit window events, wgpu backend; all colors derive from `Theme` tokens via `Theme::egui_color` / `Theme::egui_from_rgb` (no hardcoded RGB).
- **Inputs**: `&mut App`; **Outputs**: egui shapes/labels; side effect: `app.component_rects`, `app.graph_node_rects`, `app.graph_cluster_rects`, `app.pane_hit_rects` filled per frame.
- **Key invariant**: layout is recomputed fresh from the window rect on every paint — window resize needs no state handling. Hit geometry is republished fresh per frame too: `paint_panes` clears `component_rects` first and refills it from the Physical pane's drawn cells, so a pane not showing the module UI publishes nothing and a stale rect can never hit-test.

### 3.2 Domain Model & Parser (`src/patch.rs`)

- **Responsibility**: typed model of a DROID patch and a hand-rolled `.ini` parser that builds it.
- **Types**: `Patch` (name, `hw_components`, `modules`, `sections`, raw lines, token spans, occurrence index, modifier index, `shift_groups`, `cable_index`, `banner_groups`, `preamble_labels` — leading `# TOKEN: label` map), `Span` (0-based line and byte-column range), `EntrySpan` (per-entry key/value byte spans carried on `IniSection`, captured before lowercasing, alongside `header_span`/`raw_lines` — feeds the validation modal's jump-to-source), `ModifierAffect` (resolved modifier span/source/selectat), `HwComponent` (id, label, kind, shift_group, state, controller, led, plus `module_instance()` deriving the component's circuit-instance number from the leading digit run of its token id), `ComponentKind` (Button, CvIn, CvOut, Knob, Switch, Led, Encoder), `ComponentState` (Off, On, Value(f32), Active), `ShiftGroup` (Group1–4 with `color()`/`key_label()`), `Module` / `ModuleWidth`, `IniSection` (with per-entry `EntrySpan`), `CableIndexEntry` (cable name → producing circuits + ordered sink references), `BannerGroup` (banner text + section range), `ViewerCircuit` for prettified blocks, `SelectSignal` (signal name, `kind: SelectSignalKind` Register|Cable, usage count, `candidates: Vec<SelectCandidate>`), `SelectCandidate` (inferred `value: f64` + occurrence `count`), and `SelectSignalKind` (Register/Cable).
- **Key functions**: `Patch::from_ini_file` / `from_ini_str` / `sample`, `parse_ini_sections` (comment stripping, repeated-section preservation and header spans + per-entry `EntrySpan` capture), `collect_token_spans`, `scan_hw_tokens` (boundary-aware token scanner), `build_occurrence_index`, `build_modifier_index` (cycle-safe `select`/`selectat` resolution), `token_kind`, `add_component`, `collect_cable_index` (each `output = _NAME` registers a cable source for the section's circuit; each `input = _NAME` / similar sink param records an ordered `(section_name, param_key)` reference; preamble cable maps that must not produce edges are excluded), `parse_banner` / `collect_banner_groups` (a `# ---- Name ----` comment banner owns the ordered circuit-section range from its line until the next banner or EOF; sections before the first banner form an implicit unnamed group ordered first); LED-association detection (a bare `led = L.N` entry, plus numbered circuit params `ledN = L.M` paired by shared numeric suffix with a same-suffix element entry — `buttonN`/`potN`/`encoderN`/`switchN`/`faderN`, the DROID convention for circuits like `matrixmixer`; `M` tokens resolve to `ComponentKind::Knob` so faders share the knob rendering path; the association is device-dependent — when a section has no explicit pairing the parser applies the controller/device default: M4 fader touch plates resolve their RGB `L`+`R` register pair, B32 buttons stay white-only, and master LEDs default-link to their CD channels); rack-recognition API `module_types` / `needs_by_type` / `master_requirement`; `occurrences_for`, `modifier_affected_spans`, `modifier_entries_for`, `viewer_circuits`, `parse_preamble_labels` (leading `# B3.17: [RATC]` map; `I4:` empty treated as absent), select-signal discovery `discover_select_signals` (scans section params and the cable index for `select`-style signals, inferring each signal's candidate values via `parse_candidate_value` — a trailing `V` suffix scales by ÷10, otherwise plain `f64` — with `format_candidate` for display; the result feeds the select-state menu's Register/Cable rows) and label resolution `effective_shift` + `display_label(token, shift, layers_enabled, max_shift_layer, hw_store)` with fallback `store[layer]→store[1]→preamble[1]→derived` and clamping/disabled coercion + `circuit_label`/`circuit_display_label` per-`NodeId` override; lossless writer `write_to_ini`/`render_ini` (block-slices `raw_lines` by section header line, preamble first, comment/banner runs travel with their section, byte-identical round-trip; refuses the source's canonicalized path, atomic tmp→rename, auto-suffix on destination collision).
- **Inputs**: `.ini` file content; **Outputs**: `Result<Patch, String>` (descriptive errors, never panics on malformed input).
- **Design notes**: the parser is deliberately custom (the `ini` crate was removed from `Cargo.toml`) to preserve repeated section names and control token extraction precisely.

### 3.3 Input Handling (`src/handler.rs`)

- **Responsibility**: translate window events into `App` mutations.
- **Key functions**: `handle_event` (priority order: overlay → picker → armed prefix → class-layout pane keys (`z`, `Alt+b`, `Alt+s`, Esc-maximize) → focused-pane routing → normal keys; overlay eats all keys while `App.editing.is_some()`; modifier chord: `Mouse Down` on modifier-eligible component without mods = held (momentary, hit-test via `component_rects`), `Up`/`Leave` clears; `m` on the hovered panel component and `Ctrl+Shift+Click` (alias `Ctrl+Click`) latch the modifier so it survives until `Esc`; exactly one modifier is effective (a second latch replaces the first, additive union aspirational); while either state is active the influenced cells wash in `modifier_hue` and the rest dim on the module UI and source surfaces (raw and prettified); `Esc` clears shift plus both modifier states; rendering priority `graph_edge_error` (red) > modifier hue > `CableKind`); keyboard: `q`/Ctrl+C quit, `l` open picker, `g` arms a vim-style prefix (`g v` opens the source pane in a small pane, `g g` opens the signal-flow graph in a big pane, `g d` opens the picker to choose the B patch for a diff, `g o` opens the latency optimizer in a small pane, `g s` opens the select-state menu overlay (see below), `g c` toggles cable latency coloring on the graph, `t` toggles raw/prettified mode, `p` toggles the global processing pause (the module UI dims + `PROCESSING PAUSED` status, component mutations blocked while paused), `e` toggles the validation modal (from the status/view; `j`/`k` navigate issues, `Enter` jumps the source-pane scroll to the issue's line:col, `Esc` closes via `clear_validation`), `d` toggles the diff overlay (diff surface; `Esc` clears the diff scope then hides the overlay), Tab cycles focus forward across the non-empty panes in tree order and `Shift+Tab` cycles backward, `r` rotates the focused pane through its class carousel, `z` maximizes the focused pane (cleared by focus change or Esc), `Alt+b`/`Alt+s` swap within a class, `+`/`-` scale the focused pane (panels scale when panels focused, graph camera zoom when graph focused; `Shift++`/`Shift+-` scale the other pane), `[`/`]` adjust the left big-pane / right-half split ratio ±0.1 (clamped 30 %–70 %; `Alt+[`/`Alt+]` adjust the small-pane split ratio, and on the graph pane they lower/raise cable tension), `1`–`4` shift groups, `?` opens the help modal, `Esc` closes the focused pane's view (or cancels prefix / clears selection when panels are focused), Enter/Space toggle/select components, `j`/`k` scroll or navigate, and Up/Down/Home/End navigate occurrences; label overlay: `e` opens single-field overlay for focused panel token / source header instance / hovered graph node (`hovered_graph_node`); inside overlay `1..N` (N=`max_shift_layer` clamped 1..8) cycles the edited HW layer preserving per-layer drafts, char/Backspace edits draft, `Enter` saves via `LabelStore` atomic rewrite, `Esc` cancels), `handle_mouse_event` (hover highlight, panel click toggle/select, empty-space deselection, scroll ±0.05 on knobs/faders, minimap click-to-scroll, click on a pane sets focus to it), `handle_graph_mouse` (while the graph pane is focused it owns mouse input inside its pane: left-button Down on a `graph_node_rects` entry starts a `GraphDrag` with the node index and drags the node so its movement keeps pace with the cursor without layout jitter until `Up`; drag single-steps into `layout::local_resettle`; hover sets `app.hovered_graph_node` for the `x` toggle / `e` label overlay / diff scope). Physical-view input: `s` toggles the skeleton reference presentation (`Skeleton: on/off` status); `+`/`-` cycle the zoom presets 75 %–200 % with wrap-around (synced to `physical_zoom`, status reads `Scaling: N%` or the rack-aware `physical_status_hint`); arrow keys pan the rack when it overflows the main area (`physical_pan_if_overflow`) and Up/Down fall back to panel navigation when it fits; `j`/`k` always navigate. The mouse wheel pans on overflow — a wheel over a knob/fader cell still adjusts its value when no overflow forces panning (D5).
- **Window frame path**: `handle_window_event` / `handle_window_key_event` convert winit keyboard events into the neutral `KeyEvent` and run the same dispatch; `handle_graph_window_frame` applies the window's pointer/wheel/mouse report to the hovered graph node, mapping window-space coordinates through `graph_pane_origin(app)` so they line up with the pane-relative camera. The frame path also routes the module UI: when the pointer is inside a pane whose view is `Physical`, it sets `hovered_component` from `component_rects` and, on `primary_pressed`, focuses that pane and calls `select_component` (status `Focused: <token>`) — a left-click never toggles component state (that stays on `Enter`/`Space`), and when the graph pane is open it also centers the camera on the element's focused nodes via `center_graph_camera_on_nodes`; pointer over any other pane clears the module-UI hover and falls through to the graph logic unchanged. An optimizer-pane click hit-tests candidate rows (`optimizer_row_at`: 24px header, 16px rows, 12-row cap) and previews the row exactly like `Enter` (cursor set + `optimizer_preview`), handled before the graph-camera gate so it works with no graph open.
- **Inputs**: `KeyEvent`/`MouseEvent`; **Outputs**: `bool` (quit flag) or `()`; mutates `App`.
- **Key invariant**: mouse hit-testing uses `app.component_rects` / `app.graph_node_rects` written by the renderer — the renderer, not the handler, knows where components actually landed on screen.
- **Graph pane keys**: `x` toggles processing for the hovered circuit instance (hit-test via `graph_node_rects` and `app.hovered_graph_node`; rebuilds the graph, recomputes influence dead-ending at disabled sinks, emits `GraphRebuilt`, sets status `Processing disabled/enabled: <name> <instance>`; silent no-op with no hover); `p` toggles the global processing pause on every surface **except** the graph pane, where `p` toggles pin/unpin on the hovered graph node (design D7: `pinned` is a fixed solver anchor, the tip is pinned by default, drag auto-pins; status `Pinned/Unpinned: <name> <instance>`; silent no-op with no hover). `Esc` closes the graph pane; `q`/Ctrl+C still quit and `l` opens the picker, mirroring the viewer's global-key behavior. ### 3.5 Signal-Flow Graph Model (`src/graph.rs`)

- **Arrangement state**: `layout_mode`/`layout_ordering` persist the cycle selection like before (`h` remains the two-state shortcut, `a` the full cycle); `solve_graph_positions` carries pinned anchors by `NodeId` (new index → id → old-graph position), so section reorders never scramble placements. `live_graph_viewport` (live `pane_hit_rects` geometry) feeds `refit_viewport` (live → published canvas → default), so preview and arrange refits never silently skip.

- **Responsibility**: pure model of the patch's signal topology — circuits, controllers, and hardware registers as nodes; virtual cables and register reads/writes as directed edges; banner groups as clusters — plus topology validation and wiring-outlier detection. No terminal dependency (testable without rendering).
- **Types**: `NodeId` (`Circuit(name, instance)` / `Controller(type, ordinal)` / `Jack(token)`; defined in `patch` for the influence walk), `NodeKind` (`Circuit`, `Controller`, `InputJack`, `OutputJack`), `GraphNode` (id, kind, circuit, instance_index, section_index), `GraphEdge` (cable name, source `NodeId`, sink `NodeId`), `Cluster` (title + `Range<usize>` into `Patch.sections`), `TopologySeverity` (`Warning` for a dangling sink, `Error` for `n → 1`), `TopologyIssue` (cable, severity, message), `GraphOptions` (select-state `state: HashMap<String, f64>` + `hide_unselected: bool`; `Default` = empty state, no hiding), `SelectClass` (`Selected`/`NotSelected`/`Unknown` per section), and `Graph` (nodes, edges, clusters, validation, latency, plus `not_selected: HashSet<usize>` of section indices classified NotSelected).
- **Key functions**: `Graph::build_from_patch(patch, clusters, cost, options)` — every section becomes a node with distinct instance indices in file order; each cable in `patch.cable_index` fans its source out to every sink reference, one directed edge per (cable, source, sink); controller/jack nodes and register edges are built from the patch's register references (`build_register_nodes_and_edges`): catalog output/`led` params write their register refs (circuit → target) and catalog inputs read them, `PBESLR` letters resolve to declared controller nodes by ordinal, unmatched letters fall back to master input/output jacks, and identical edges are deduplicated; unresolvable names are skipped rather than panicking; edges are sorted deterministically by `(cable, source, sink)` (the cable index is a `HashMap` whose iteration order is randomized per process, and edge order feeds the layout solver's f32 accumulation and the renderer's shared-cell ownership — stable order is required for reproducible layouts); **select-state classification** (`classify_sections` + `classify_for_status`) labels every section `Selected`/`NotSelected`/`Unknown` from the `GraphOptions.state` values (`Unknown` = no select-param match, always kept); NotSelected circuits lose their controller register edges (a register edge whose circuit endpoint is NotSelected survives only when it reaches a controller node — the shared cross-controller pair is kept), and with `hide_unselected` their circuit nodes are dropped entirely; `not_selected` travels on the graph so the renderer dims them (`graph_node_dim`) and `upstream_dependencies(root)` / `internal_edges(members)` feed the dependency subgraph; `validate_topology` runs as a build step — exactly one source per cable is valid, zero sources (a dangling reference) is a `Warning`, two or more sources is an invalid `n → 1` topology and an `Error`; produced-but-unused cables are fine; findings travel with the graph for the renderer to highlight and never block building or viewing. `validate_topology` also runs `geometry::RackGeometry` resolution and delegates wiring-outlier scoring to `WiringOutlierScorer` (src/geometry.rs) — an embedded learned decision table (`tools/outlier_artifact.txt` via `include_str!`, schema.rs precedent) that classifies `BindingFeatures` as implausible, with a preserved threshold fallback (`euclidean > 8.0 && cable_hops == 0`) on a table miss (design D1); invariant guards (adjacent / co-located / via-cable) stay explicit at the call site and never reach the scorer (design D5). `validate_topology` also emits the per-token influence second opinion (`InfluenceStats` in src/patch.rs, embedded `tools/influence_stats.txt`): every distinct hardware token is z-scored against per-kind corpus mean/std of `influence_subtree` size; tokens beyond the 3.0 band produce a `Warning` attached to the token's first root-var cable (design D4). Findings travel with the graph, never block building or viewing, and never gate patch loading.
- **Dependency subgraph**: `Graph::upstream_dependencies(root)` is a reversed-edge BFS over the full graph (cycle-safe) that walks producers of cables the root consumes — controller and input-jack leaves terminate the walk, and an output-jack root walks its producing circuits; `Graph::internal_edges(members)` returns the edge indices whose both endpoints are in the member set. `App::apply_dependency_subset` builds a subset `Graph` from those index lists, solves it as its own layout (subset-relative pins mapped from `App.pinned`), and writes the positions back into full-graph index space, so the filtered render draws only the subgraph with a fresh camera fit.
- **Cable attribution**: by section *name* (the cable index records names, not instance indices), so a name shared by several instances resolves to the first instance for edge building; instance-accurate attribution is the topology-validation pass's concern, keeping that convention consistent.

### 3.6 Layout Solver (`src/layout.rs`)

- **Responsibility**: two deterministic layout paths — the column arrangement (default, graph-column-layout D1-D6) and the retained force-directed convergence solver (a one-shot solve, not a simulation). The column path dense-normalizes circuit depth (capped Bellman-Ford over circuit-only edges) into columns `0..N-1`, places controller/jack nodes in fixed outer columns, stacks nodes width-aware (estimated widths, grid-snapped to `GRID_SNAP`) with no overlap, and orders within-column strict or barycenter (config `[layout] ordering`); no force relaxation runs on it. The force path is unchanged and reachable via `h` or `[layout] mode = "force"`.
- **Key functions**: `solve_columns` / `solve_columns_pinned` (column path: `circuit_depth`/`depth_over`, `dense_columns`, `assign_columns`, `column_ranks`/`crossing_minimized_layers`, `estimated_widths`/`estimate_node_width`/`estimated_title` (the same width estimate the graph renderer uses as each node's drawn world width, ADR 40), `GRID_SNAP`; pinned nodes act as fixed-position anchors), `solve(graph, pinned, tension) -> Vec<(f32, f32)>` (force path, positions parallel to `graph.nodes`; full solve from scratch: layered seed → bounded refinement of up to `SOLVE_ITERATIONS` (60) iterations, freezing early when total kinetic energy drops below `ENERGY_THRESHOLD` (0.5); `tension` is the spring stiffness, `DEFAULT_TENSION` = `SPRING_K`), `local_resettle(graph, positions, moved, radius, iterations, pinned, tension) -> bool` (damped re-settle after a node move — only nodes within `radius` (`LOCAL_RADIUS` 200, default `LOCAL_ITERATIONS` 40) are active; distant nodes act as unmoved anchors; `pinned` node indices never move; no-op for an unknown node).
- **Layered seed (design gv5)**: initial positions are a layered (Sugiyama-style) arrangement along a single dominant left→right axis — `x = depth · HORIZONTAL_SPACING`, `y = within-layer order · VERTICAL_SPACING` — where the within-layer order comes from deterministic barycenter crossing-minimization sweeps (`CROSSING_SWEEPS` 8, alternating left→right/right→left, stable sort, no RNG) instead of file order, and coordinates land exactly on the `GRID_SNAP` (10) grid (no jitter). The relaxation is a bounded refinement of that seed, so the convergence target is a clean horizontal chain of aligned columns (design D1). Parallel edges between the same two circuits are normalized to one spring (a cable bundle is one connection), so a button feeding 11 inputs of one circuit does not create an 11×-stiff oscillator. Constants: `FRICTION` 0.5, `SPRING_REST` 80, `SPRING_K` 0.15 (raised so cable springs dominate repulsion, design D2), `DEFAULT_TENSION` = `SPRING_K` (the keyboard-adjustable default, so existing layouts stay byte-identical), `TENSION_STEP` 0.05 / `TENSION_MIN` 0.05 / `TENSION_MAX` 0.5 (the `[`/`]` adjustment range), `SOLVE_ITERATIONS` 60 (the full-solve refinement budget), `REPULSION_STRENGTH` 1500 (softened), `REPULSION_RADIUS` 120, `MAX_DISPLACEMENT` 20, `COHESION_K` 0.01 (weak per-cluster cohesion, far below `SPRING_K`, design D4), `HORIZONTAL_SPACING` 80, `VERTICAL_SPACING` 120.
- **Performance**: repulsion uses uniform-grid cell hashing (rebuilt per iteration; cell size = repulsion radius) so a node only repels against nodes in neighboring cells, keeping the 600-node case near-linear instead of O(n²).

### 3.7 Observer Event Bus (`src/events.rs`)

- **Responsibility**: synchronous observer event bus connecting model, graph, renderer, and validation (design D6). Deliberately minimal: an event enum, inline dispatch to subscribers, no queueing, no async, single-threaded.
- **Events**: `Event::GraphRebuilt` (graph (re)built and re-solved; subscribers re-render), `Event::NodeMoved(NodeId)` (node dragged to a new position after a local re-settle), `Event::TopologyError(TopologyIssue)` (topology-validation finding — a path to the status surface), `Event::ValidationCompleted { count, error_count }` (schema/lint validation finished for a loaded patch), `Event::InfluenceRecomputed(InfluenceSubtree)` (the modifier/element influence subtree was recomputed — the module-UI/source wash and the graph highlight all read the same subtree), `Event::DiffComputed { added_cables, removed_cables, changed_cables, added_nodes, removed_nodes, changed_nodes }` (a B patch was loaded and its diff computed).
- **Key functions**: `subscribe -> Subscription` (plain `FnMut` closures invoked in subscription order on dispatch), `unsubscribe` (stale/duplicate handle is a no-op), `dispatch` (inline, no-op with no subscribers).
- **Wiring today**: dispatch sites are live — `App::open_graph` emits `GraphRebuilt` plus one `TopologyError` per validation finding; `App::notify_node_moved` emits `NodeMoved` after a drag re-settle; `App::validate_patch` emits `ValidationCompleted`; `App::recompute_influence` emits `InfluenceRecomputed` with the recomputed subtree (the element register-focus union included); `App::load_diff_patch` emits `DiffComputed`. No production subscriber is registered yet (design D6 extension point; the API is exercised by tests).

### 3.8 Entry Point & Event Loop (`src/main.rs`)

- **Responsibility**: process lifecycle and the draw→read→dispatch loop.
- **Key functions**: `main` (color-eyre install, config load + `theme::init` before the window opens so warnings land on a clean console and rendering never starts half-themed, panic-hook chaining, demo-patch fallback), `seed_app` (seeds the cost model, physical-view state, layout mode/ordering, and the `[labels]` policy from settings), `load_initial_patch` (reads `argv[1]` and otherwise falls back to the embedded demo patch), `run` (owns the single winit `EventLoop`; `AppHandler` implements `ApplicationHandler` with `ControlFlow::Poll`, draining winit events each frame through `handle_window_event` (draw→read→dispatch), with all view routing in `handler::handle_event`). Startup opens the module UI in the left big pane and the source viewer in a small pane (the `PaneLayout::default()` arrangement) and queues `queue_startup_window_open` (the only path that opens the window); no graph view is opened until the user presses `g g`.
- **Technologies**: winit (window + event loop), egui/egui-winit (immediate-mode UI), wgpu (GPU backend). The window opens only from the startup request; no runtime path opens or closes it.

### 3.9 Authoritative Schema (`src/schema.rs`)

- **Responsibility**: embed the authoritative DROID circuit schema and expose it as typed lookups for validation. No UI dependency.
- **Caching**: `load_schema() -> &'static Schema` returns the process-wide cached schema behind a `Mutex<Option<&'static Schema>>` — a `Mutex`, not a `OnceLock`, so tests can reset it via `set_test_schema` / `reset_test_schema` (theme.rs idiom, pinning or clearing per-thread views without cross-test poisoning); an uninitialized fallback parses the embedded JSON once and leaks it. `merge_plugins(base, files) -> Schema` performs the plugin overlay (insert-or-override on name collision, warn-once shadow per file); `schema::init()` (embedded base + merged plugins, honoring `[plugins]`) is called from `main()` before the window opens so plugin shadow/skip warnings land on a clean console (ADR 14). `CircuitDef` now carries optional `cable_kind` + `color` (declared rendering metadata; `None` defers to substring inference).
- **Embedding**: `const CIRCUITS_JSON: &str = include_str!("../ext/droid-lsp/droid-lsp/src/circuits.json")` — the vendored `ext/droid-lsp` git submodule (GitHub `moonstruxx/droid-lsp`) is the schema source of truth, compiled in at build time.
- **Types**: serde mirror structs over the JSON (`RawSchema` with `firmware_version`, `jacktable_initial_size`, `available_memory`, `circuits`, `controllers`, `manual_references`; `RawCircuitDef` with `category`, `title`, `description`, `ramsize`, `inputs`/`outputs` params, `presets`, `manual`; `RawParam` with `name`, `short`, `type`, `default`, `prefix`, `count`, `start_at`, …); `JackTable` (jack-name set derived from the schema for valid-jack checks).
- **Key functions**: `load_schema` (parse the embedded JSON once into a `HashMap` keyed by circuit name, cache a `&'static Schema`), circuit/param expansion that accounts for `prefix`/`count`/`start_at` (a repeated param like `potN` expands to its numbered instances), and a Levenshtein-based suggestion helper used by the `unknown_circuit` validation check to propose the nearest named circuit.
- **Inputs**: embedded `circuits.json`; **Outputs**: typed circuit definitions + jack table for `validation.rs`.

### 3.10 Patch Validation (`src/validation.rs`)

- **Responsibility**: pure, deterministic validation of a parsed `Patch` against the authoritative schema. No terminal dependency.
- **Types**: `Severity` (`Error`, `Warning`, `Hint`), `ValidationIssue` (`span`, `severity`, `code`, `message`), sorted by (line, col) for stable modal ordering.
- **Checks** (9, ported 1:1 from `ext/droid-lsp/droid-lsp/src/diagnostics.ts`): `unknown_circuit` (`Error` + Levenshtein suggestion via `schema.rs`), `duplicate_param` (`Warning`), `unknown_param` (`Error`), `invalid_jack` (`Warning`), `missing_required` (`Warning` at the header), `undefined_cable` (`Warning`), `duplicate_cable` (`Warning`), `unused_cable` (`Hint`), and RAM sizing (`ramsize` `Error`).
- **Key function**: `validate_patch(&Patch) -> Vec<ValidationIssue>` — pure over the parsed patch and the embedded schema; the span data come from `IniSection::EntrySpan` so each finding can be located and jumped to in the source pane.
- **Wiring**: `App::load_patch` runs validation on load, gates the patch on any `Error` finding (rejected → modal), and dispatches `Event::ValidationCompleted`.

### 3.11 Patch Diff (`src/diff.rs`)

- **Responsibility**: pure model of the differences between two patches. No terminal dependency.
- **Types**: `DiffReport` (`added_cables`, `removed_cables`, `changed_cables: Vec<ChangedCable>`, `added_nodes`, `removed_nodes`, `changed_nodes: Vec<ChangedNode>`; each sorted for stable output); `ChangedCable { cable, … }`, `ChangedNode { … }`.
- **Key function**: `diff_patches(base: &Patch, new: &Patch) -> DiffReport` — compares cables and circuit instances between the loaded (base) patch and a second (new) patch, classifying each as added/removed/changed.
- **Wiring**: `g d` opens the picker to choose the B patch → `App::load_diff_patch` computes the report and dispatches `Event::DiffComputed`; `d` toggles the overlay, `Esc` clears the diff scope, and the graph surface colors cables/nodes by their diff classification via the theme `graph_edge_diff_added`/`graph_edge_diff_removed` tokens.

### 3.12 Rack Geometry (`src/geometry.rs`)

- **Responsibility**: pure model of the physical DROID rack layout used to detect wiring outliers. No terminal dependency.
- **Types**: `RackGeometry`, `Rack`, `ControllerSlot`.
- **Key functions**: `load()` (reads `rack_geometry.json` resolved via `CARGO_MANIFEST_DIR`), `resolve()` (places controllers into slots), `distance()` / `is_adjacent()` (physical distance between two modules' slots).
- **Wiring**: `graph::validate_topology` delegates wiring-outlier classification to `geometry::WiringOutlierScorer` (embedded learned decision table + preserved threshold fallback) with call-site invariant guards (adjacent / co-located / via-cable never scored), and adds the per-token `influence_subtree` z-score second opinion (`patch::InfluenceStats`) — both `Warning` channel, neither gates loading.

### 3.13 Physical Layout (`src/physical.rs`)

- **Responsibility**: pure model of the physical DROID rack — the 1:1 main view's geometry source. No terminal dependency.
- **Types**: `PhysicalLayout` (modules resolved from `hw_components` with mm extents and faceplate cells), `CellGrid`/`CellRect`, `RectMm`, `ScreenMapping` (aspect-compensated mm→chars factors, zoom, pan offset), `RackSpec` (ordered rows `{he, hp, label?}`, `top_mount_te`/`side_mount_te`, per-module `assign` overrides), `RackLayout` (rows with placed modules, fold bars, mount regions, total mm bounds).
- **Key functions**: `PhysicalLayout::build(&Patch)` (chain order from patch declaration order, D3), `RackSpec::default_case` (a single 3-HE row wide enough for the whole chain — no config required), `RackLayout::pack` (auto-pack rows left-to-right with per-module row overrides, D10), `ScreenMapping` (`mm × factor × zoom − offset` per D4/D5, `pan`, `screen_size` for overflow detection).
- **Wiring**: config `[physical.rack]` parses into `RackSpec` (`config.rs`, D12); `gui/physical.rs` maps the rack to screen via `ScreenMapping` for both the full render and the skeleton presentation; controller geometry loads from `controller_geometry.json` with fallback width + warn (D6); `FOLD_BAR_HEIGHT_MM` drives fold-bar dividers (D11).

### 3.14 Plugin Circuits (`src/plugin.rs`)

- **Responsibility**: discover and parse user-supplied DROID circuit definitions (TOML plugin files) that extend the embedded schema without editing the vendored submodule or rebuilding. Discovery + parse only — merging into `Schema` lives in `schema.rs`.
- **Types**: `RawPluginCircuit` / `RawPluginParam` (serde mirrors over the TOML, `ramsize` an `Option` so its absence is a *semantic* error handled after parse, not a serde failure), `PluginDocument` (top-level `[[circuit]]` array), the normalized `PluginCircuit` (lowercased `name`, `category`, `ramsize: u32`, `title` defaulting to the declared name, `description` defaulting to `""`, optional `cable_kind`/`color`), `PluginParam` (`name`, `short`, `param_type`, `default`, `prefix`, `count`, `start_at`), and `PluginFile` (`path` + `circuits: Vec<PluginCircuit>`, one per successfully parsed file).
- **Key functions**: `discover_plugins(xdg_config_home, home)` (resolve the XDG directory, then delegate), `discover_plugins_from_dir(dir)` (list every `*.toml` under an explicit directory in sorted-filename order and `load_file` each — the `[plugins].dir` override entry point), and `load_file(path)` (`pub(crate)`, so schema tests load real fixtures) — reads, parses, and semantically validates one file, returning `None` (with one warn-once stderr notice) for an unreadable, malformed-Toml, or missing-`ramsize` file. Helper `plugin_dir` mirrors `config::config_dir`: a non-absolute `$XDG_CONFIG_HOME` is treated as unset, falling back to `$HOME/.config`.
- **Discovery path**: `$XDG_CONFIG_HOME/droid-tui/plugins/*.toml` (or `$HOME/.config/droid-tui/plugins/` when XDG is unset). A missing directory yields an empty list with no warning; non-`.toml` files are ignored; files load in sorted-filename order so the schema overlay is deterministic (later files win on collision).
- **Skip semantics**: a plugin never aborts startup — an unreadable file, a malformed TOML file, or a circuit without the required `ramsize` all reject *that one file* with a single stderr warning naming the file (and circuit), and the remaining files still load. Circuit names are lowercased here (case-insensitive, matching the embedded `load_schema` key convention).
- **TOML shape**: one `[[circuit]]` table per circuit with `name`, `category`, required `ramsize` (bytes), optional `title`/`description`/`cable_kind`/`color`, and `inputs`/`outputs` arrays (both `#[serde(default)]`) of param tables carrying `name`, `short`, `type`, optional `default`, and the `prefix`/`count`/`start_at` expansion trio — preserved intact so numbered plugin params expand through the same `expand_names` path as embedded ones.
- **Merge**: `schema::merge_plugins(base, files) -> Schema` applies `files` in slice (sorted) order over the embedded base — insert-or-override on name collision; a plugin name shadowing an embedded circuit warns once per file. Neutral defaults (`presets`, `manual`, per-param `essential`/`ramhint`/`autotitle`) are applied by `circuit_def`/`circuit_param` here, not in `plugin.rs`.
- **Declared metadata**: a plugin circuit's optional `cable_kind` (`control`/`audio`/`midi`/`unknown`) and `color` (a component-kind theme token) ride `CircuitDef`. `CableKind::from_circuit` and `circuit_color` (`src/gui/`) consult the declared fields first and keep the name-substring tables as fallback — so the 76 embedded circuits (which declare nothing) classify byte-for-byte as before, while plugin circuits can declare their edge kind and node color explicitly.
- **Inputs**: the plugin directory + env values (injected as `Option<&OsStr>` so tests never touch process env); **Outputs**: `Vec<PluginFile>` for the schema merge.

### 3.15 Latency-Optimized Patch Generation (`src/optimize.rs` + `src/latency.rs`)

- **Responsibility**: propose section reorderings of a loaded patch that reduce forward-loop latency — the extra loop units a consumer circuit reads from a producer that runs later in the scan. Pure functions over the parsed patch; no terminal dependency.
- **Cost model**: `latency::CostModel` is the shared per-circuit average-latency (`AVG`) provider for both the latency ramp and the optimizer (design D2); `AVG` is proportional to the circuit's RAM size, overridable per circuit via `[latency] per_circuit` config.
- **Key functions**: `generate_candidates` yields candidate section orderings (banner-preserving min-sum default, global min-sum, min-max minimizing the worst forward-loop latency), each evaluated via `evaluate_order → forward_latency`; the identity ordering is always among the candidates; exact enumeration when `N! ≤ ENUM_LIMIT`, else a bounded local hill-climb (≤ `SEARCH_STEPS`) with same-name-relative-order-preserving swaps and a deterministic FNV-1a seed order. The preview diff is latency-based, not structural: `open_optimizer` snapshots the file-order per-edge latency (`OptimizerDiffState{before_cable, before_latency}`, parallel to the deterministically-sorted edge vector with a cable-name guard); `optimizer_preview` compares the rebuilt graph against it in `first_affected_node` and the renderer colors worse-red/better-blue under the error/influence/disabled precedence (as-built latency-delta form of change `optimizer-click-focus`, superseding its dual-SceneSpec proposal). The latency-optimizer-upgrades change extends the search: a cheap **FAS-indegree first pass** ranks sections to target back edges before search, **multilevel coarsening + VNS** (banner groups as coarsening hints) scales large patches, and **simulated annealing with a seeded PRNG** adds a further deterministic strategy (design D9 contract). The menu exposes a **weighted slider objective** `(1−w)·Sum + w·max` with `w` clamped to [0,1] — `[`/`]` adjust it by 0.1 while the menu is open and candidates regenerate live.
- **Wiring**: `g o` opens the optimizer as a **small pane** (`paint_optimizer` in `gui/overlays.rs`, not a centered modal — the other panes stay visible); `j`/`k` navigate, `Enter` or a candidate-row click previews (reorders `patch.sections` in place, rebuilds the graph, refits the camera, colors latency-worse red / latency-better blue against the file-order baseline, selects the first affected circuit for the cross-view jump while keeping focus on the optimizer pane so `r` still restores; status `Preview: <label>`), `r`/`Esc` restore the original order and close the pane (clearing the latency baseline), `s` exports the selected candidate to `<stem>-latopt.ini` via the lossless writer (atomic, auto-suffix on collision; the loaded patch is never mutated), and `[`/`]` adjust the weighted slider objective `w` while the pane has focus. The `optimizer_modal_border`/`optimizer_selected_bg` tokens are superseded by the pane focus border tokens (`pane_focus_border`/`pane_unfocused_border`).

### 3.16 Droid Expression Evaluator (`src/expression.rs`)

- **Responsibility**: evaluate Droid-style arithmetic expressions on a register/cable value map — the value source behind select-state candidate resolution and any future `select`-param consumers. Pure functions over strings; no terminal dependency.
- **Key function**: `evaluate_droid_expr(expr, values) -> Option<f64>` — left-to-right evaluation with **no operator precedence and no parentheses** (Droid semantics), `+ - * /` over `f64` operands; a literal `1V` suffix scales by 0.1 (1 V = 0.1), division by zero yields `0.0`, and an unknown token (not in `values`) yields `None` so callers can fall back. The parser is intentionally minimal: no variables beyond the `values` map, no functions.

### 3.17 Class-Based Pane Layout (`src/panes.rs`)

- **Responsibility**: pure model of the adaptive main band — which pane holds which view and how the band divides. No UI dependency; `App` owns the instance.
- **Types**: `PaneClass` (a `Big` full-height pane or a `Small` quarter-height right-half pane), `PaneId` (`BigLeft` | `BigRight` | `SmallTop` | `SmallBottom`), `Pane` (a fixed `class` plus an optional `view: Option<ViewType>`), and `PaneLayout` (`big_left`/`big_right`/`small_top`/`small_bottom` panes + `focus: PaneId` + `maximized: Option<PaneId>` + `main_split_ratio` 0.5 + `small_split_ratio` 0.5).
- **Key functions**: `ViewType::class()` routes each view to its class (`Graph`/`Physical` → `Big`; `SourceViewer`/`Optimizer` → `Small`); `PaneLayout::has_small_view()` is the arrangement switch (true → two stacked small panes on the right, false → one big right pane); `pane(id)`/`pane_mut(id)` accessors; `PaneLayout::default()` is the startup arrangement (module UI in `BigLeft`, source viewer in `SmallTop`, focus `BigLeft`, both ratios 0.5).
- **Geometry**: `App::pane_geometry(band)` turns the layout into per-pane rects (left big pane at `main_split_ratio` clamped 0.3–0.7; the right half as one big pane or two small panes split at `small_split_ratio` in tree order; the maximize override returns only the maximized pane at full band). This is the ADR 35 single source: `paint_panes` draws from it and `refresh_hit_geometry` publishes it as `pane_hit_rects`.
- **Carousels**: `BIG_CAROUSEL` = [Graph, Physical] and `SMALL_CAROUSEL` = [SourceViewer, Optimizer] drive the `r` key (`App::cycle_view_in_slot`).

### 3.18 Graph Settle Animation (`src/graph_anim.rs`)

- **Responsibility**: pure open-animation driver for the signal-flow graph — interpolating the drawn node positions from a compact seed into the solved layout over a fixed duration, then freezing. No UI dependency (no egui/winit); the solved layout stays the single source of truth and only display positions interpolate.
- **Types**: `GraphSettle` (seed/target position vectors + start instant), `SETTLE_DURATION_MS` 500, `SETTLE_SEED_SCALE` 0.08.
- **Key functions**: `ease_out_cubic(t)` (standard cubic ease-out, clamped, monotonic), `compact_seed(positions)` (collapses positions toward the layout centroid by `SETTLE_SEED_SCALE`), `GraphSettle::new(seed)` / `progress(now)` / `display(now, target)` (eased interpolation; a length mismatch yields the target directly).
- **Wiring**: `App` carries `graph_settle: Option<GraphSettle>` + `graph_settle_pending: bool`; a fresh `open_graph` queues a settle and `begin_graph_settle` starts it on the first painted frame with a real viewport; `graph_settle_active`/`cancel_graph_settle` bound its lifetime (a node grab cancels it) and `graph_display_positions` is what the renderer (`build_scene_spec`) and the pointer hit-testing (`handle_graph_window_frame`) both read, so hover matches what is drawn. Rebuilds, restores, and drag re-settles stay instant — only the fresh open animates.

### 3.19 Performance Placement (`src/performance.rs`)

- **Responsibility**: pure side-bound callout layout — which label goes over/under/left/right of the rack and where it sits. No egui dependency.
- **Types**: `Side` (Over/Under/Left/Right), `LabelInput` (host id/rect/label size), `PlacedLabel` (side/label rect/anchor), f32 `Rect`/`Point` primitives.
- **Key functions**: `place_labels(rack, inputs)` — quadrant-by-dominant-axis side assignment, within-side host-coordinate ordering (host-id tiebreak), outward band stacking with wrap, host-edge leader anchors; deterministic (inputs sorted, output in host-id order); label rects disjoint from the rack and each other by construction.

### 3.20 SysEx Payload (`src/sysex.rs`)

- **Responsibility**: pure MIDI SysEx payload builder — the sendable bytes for the in-memory patch. No process/UI dependency.
- **Key functions**: `build_sysex(rendered)` strips per line per the `droidpatch` rules (comment strip unless `"` precedes `#`, whitespace collapse, keep-only `0x0A..=0x7E`) and frames `F0 00 66 66 50 … F7`; `strip_line`, `SYSEX_HEADER`/`SYSEX_FOOTER`, `is_seven_bit_clean` helpers. Callers serialize via the lossless `render_ini` (now `pub(crate)`) before building.

**Key user journeys**:
- **Load a patch**: press `l` → picker overlay lists current dir → navigate with `j`/`k`/arrows → Enter on `.ini` → `Patch::from_ini_file` parses → `validate_patch` runs (Error findings gate the load; Warning/Hint still load) → picker closes → panels render.
- **Focus a component (module UI)**: left-click a module-UI element (or hover it and press `Enter`/`Space`) → the click focuses the pane and calls `select_component`: the clicked cell stays highlighted on the faceplate, the source pane jumps to its occurrence, and the graph highlights the element's register entity (`_REG:<token>` edge + controller/circuit nodes) plus its influence subtree, centering the camera when the graph pane is open; status bar shows `Focused: <token>`. A click never flips `ComponentState` — `Enter`/`Space` on the hovered cell still toggles it and shows "Toggled: <label>".
- **Shift visualization**: press `1`–`4` → `active_shift` set → panels containing matching `shift_group` get bold colored borders, others dim; `Esc` clears.
- **Open the source viewer**: press `g` then `v` within 1 s → the source viewer opens in a small pane (the other panes stay visible). Raw lines render by default; `t` switches to prettified circuit blocks. `j`/`k` scroll, Up/Down/Home/End navigate selected-token occurrences, Tab changes focus, and Esc closes the slot while keeping selection and scroll.
- **Open the signal-flow graph**: press `g` then `g` → `open_graph` builds the graph from the current patch's cable index and banner groups, runs a fresh full solve (the default column arrangement; the force solver when `layout_mode` is `Force`), and opens the graph in a big pane. The canvas draws titled banner-group cluster containers, cable edges (colored by cable kind — the producing circuit's declared `cable_kind` when present, else name-substring inference: control/audio/midi — or by the topology-error token when the cable has a validation finding), and rounded circuit-node frames with input/output port markers. Dragging a node with the mouse re-settles the local neighborhood (damped, bounded iteration budget) and emits `NodeMoved`. `Esc` closes the graph pane and the pane reflows; `q`/Ctrl+C still quit.
- **Review validation findings**: after a load, press `e` to open the validation modal; `j`/`k` move between issues, `Enter` jumps the source pane to the issue's `line:col`, `Esc` closes. Error-severity findings gate the load; Warning/Hint findings still load.
- **Diff two patches**: press `g` then `d` → picker chooses the second (B) patch → `load_diff_patch` computes and shows the diff; `d` toggles the overlay, `Esc` clears the diff scope. The graph colors added/removed/changed cables and nodes; `status_for_scope` shows "Diff scope: {token} (N cables)".
- **Scale modules**: press `+`/`-` → cycle presets 75 % → 100 % → 150 % → 200 % (wrapping at both ends) → the renderer multiplies the component cell size; status bar shows "Scaling: N%".
- **Adjust cable tension**: on the graph pane (open via `g g`), press `Alt+[`/`Alt+]` → lower/raise the force solver's spring stiffness by 0.05 within [0.05, 0.5] → the layout re-solves live under the new tension (on the column arrangement the value is stored and reported while positions stay put); status bar shows "Cable tension: N.NN". Determinism holds per value: same patch + same machine + same tension → same layout.
- **Adjust the pane splits**: press `[`/`]` to move the left big-pane / right-half boundary in exact 10 % steps between 30 % and 70 %, or `Alt+[`/`Alt+]` to move the small-pane boundary; the layout reflows immediately and the status bar trails the split.
- **Cycle focus, rotate and manage panes**: `Tab`/`Shift+Tab` cycle focus across the non-empty panes in tree order; `r` rotates the focused pane through its class carousel (big: graph → module UI → physical; small: source viewer → optimizer), focusing the view's existing pane when it is already open elsewhere. `z` maximizes the focused pane (cleared by a focus change or Esc), `Alt+b` swaps the two big panes, and `Alt+s` swaps the small panes. `Esc` closes the focused pane's view (clearing a maximize first).
- **Optimize patch latency**: press `g` then `o` → the optimizer opens in a small pane proposing section reorderings that reduce forward-loop latency, scored by the shared `CostModel`; `j`/`k` move between candidates (shown with `before → after` summaries), `[`/`]` adjust the objective weight `w`, clicking a candidate row or `Enter` previews (reorders sections, rebuilds the graph, refits the camera, recolors latency-worse red / latency-better blue, focuses the first affected circuit across graph/source/module UI while keeping optimizer focus, status "Preview: <label>"), `r`/`Esc` restores the original order and closes the pane, `s` exports to `<stem>-latopt.ini`.
- **Assume a select state**: press `g` then `s` → the select-state overlay lists the patch's discovered Register/Cable signals with their inferred candidate values; `j`/`k` move between signals, `[`/`]`/Enter cycle the selected signal's candidate (e.g. a `select` param's value) — each cycle writes `state`, rebuilds the graph, and reclassifies sections (Selected keep their full edges, NotSelected dim and lose controller register edges, Unknown are always kept); `Esc` clears and restores the default graph. Status reports "Select state: N selected / M unselected / K unknown".
- **Filter to upstream dependencies**: on the graph pane, hover a node (or rely on the shared circuit selection) and press `f` → the graph rebuilds to that node's upstream-dependency subgraph — a reversed-edge walk through the producers of the cables it consumes, stopping at controller/input-jack leaves — solved as its own layout with a fresh camera fit; `Esc` clears the filter, and an active filter survives later rebuilds unless its root node disappears.
- **Edit a label**: focus a panel cell / source header instance / hovered graph node → press `e` → centered single-field overlay opens (hint in `modifier_hue`, `1..N` cycles Group layer); `Enter` saves via `LabelStore` atomic rewrite, `Esc` cancels. HW merges `store[layer]→store[1]→preamble[1]→derived`; circuit label overrides source header + graph node title in both FULL and FILTERED panes; status shows `<token> / Group<N> → N ckts / M cables` in `modifier_hue` (`graph_edge_error` red precedence kept).
- **Open the performance view**: with the Physical pane focused press `p` → compact centered rack with big side-bound labels and leader lines; activating an element updates its callout live, `R` resets all element states, `Esc` leaves the view (other panes keep their `p` meaning).
- **Upload the patch to hardware**: press `U` → confirm modal (bytes + transport); `y` sends the in-memory patch via USB/DIN MIDI SysEx with waiting-bar progress, `n`/`Esc` cancels; missing tools/hardware are named, never silent.
- **Resize**: window resize is handled by the winit loop; the next paint recomputes layout from the new window rect.

## 5. Data Stores

**None at runtime.** The application holds all state in memory (`App`) and persists nothing during normal use. The `.beads/` directory is the beads issue-tracker's Dolt-backed store, developer tooling, not application data. No database, no schema, no migration strategy.

Two build-time data inputs are embedded, not consulted at runtime: the authoritative DROID circuit schema is compiled in from `ext/droid-lsp/droid-lsp/src/circuits.json` via `schema.rs::include_str!`, and the rack layout is read from `rack_geometry.json` via `geometry::load()` (resolved through `CARGO_MANIFEST_DIR`). Both are static, deterministic inputs that ship inside the binary.

## 6. External Integrations / APIs

The app reads local `.ini` files, simulates component state, and renders everything in-process — except one deliberate edge: patch upload shells out to the system MIDI tools. `src/sysex.rs` builds the framed payload from the in-memory patch; `U` confirms (bytes + transport) and the send forks `amidi -p <port> -s` (preferred) or `sendmidi dev <port> syf`, polled per event with a waiting-bar state and a status verdict. Transports are USB-MIDI (X7 autodetect via `amidi -l`) and DIN MIDI; missing tools/hardware name themselves, never silently skip. The staged `.syx` tmpfile is cleaned by `Drop` and the child is killed on quit. No other subprocess, network service, IPC, or terminal-multiplexer integration is used.

The `ext/droid-lsp` submodule is used for development reference and as the vendored schema source of truth.

## 9. Security Architecture

- **Trust boundary**: the app runs locally with the user's privileges; file input is local `.ini` files and MIDI output goes to locally attached DROID hardware. The embedded viewer executes no external commands; the single exception is the upload sender, which execs `amidi`/`sendmidi` directly (no shell) only after an explicit `y` confirmation, with a preflight tool/port probe gating the modal and tmpfile/child hygiene on quit.
- **Input validation**: the parser is defensive — malformed/empty files return descriptive `Err(String)` and never panic (tested: `rejects_empty_file`); graph edge building skips unresolvable cable names instead of panicking; patch validation gates the load on `Error`-severity findings.
- **Secrets**: none handled, none stored.
- **Auth/authz**: not applicable (no network, no multi-user).
- **Window hygiene**: window and console state are restored on normal exit and on panic (chained panic hook).

## 11. Performance & Scalability

- **Model**: single-threaded, no concurrency, no caching.
- **Per-frame cost**: layout and panel grouping are recomputed every draw — O(n) in component count with small constants (`COMPONENT_WIDTH = 16`, `COMPONENT_HEIGHT = 2`). Fine for real DROID patches (tens of components).
- **Graph solve**: the default column arrangement is a single-pass placement — width-aware blocks, no iterations, no force relaxation; the retained force arrangement is one-shot and bounded — full solve ≤ 300 iterations (freezes early at the energy threshold), local re-settle ≤ 40, repulsion near-linear via uniform-grid cell hashing (600-node chain tested finite). Re-solve triggers: patch load, node drag, and the rebuild family (arrangement toggle, tension, select-state cycles, processing toggles). The per-node width estimate (`layout::estimated_widths`, on the per-frame scene-build and hit-test hot path) was rewritten from O(n·(n+e)) to O(n+e) by precomputing the node index, edge incidence, and repeat counts once — 155 ms/call down to ~0.3 ms at melody2 scale — after it froze graph opens at ~3 fps under the settle animation's continuous redraws.
- **Validation**: `validate_patch` runs once per load over the parsed patch and the in-memory schema; the 9 checks are linear in sections/params with schema lookups. Diff runs once per B-patch load over two patch models. `Graph::build_from_patch` runs `validate_topology` (wiring-outlier scan + per-token influence z-score + cable-source checks) per build; both outlier passes build one precomputed context (cable-sink index, token containment, resolved geometry) per build and every pair/token then costs O(1) lookups instead of rescanning every section, which is what kept the melody2 build at ~24-28 s release before the 2026-09-14 fix.
- **Known bottleneck**: none at current scale; a pathological patch with thousands of components would redraw slowly, but DROID hardware RAM limits make this unrealistic.
- **Profiling gate** (`tests/perf_gate.rs`): integration tests in the default `cargo test` suite run three core pure phases over the scale anchor `fixtures/droid_mpfs5melody2.ini`, the largest real patch in the corpus (532 sections / 457 cables / 115 hw tokens) and the measured worst case for every gated phase. Each phase runs on a worker thread under a wall-clock budget via the `budgeted(name, budget, f)` watchdog, which uses an `mpsc::recv_timeout` ceiling; a phase past its budget fails the test with the phase name and elapsed time, so an endless loop busts the suite instead of hanging it. Budgets are wide margins over the measured release baselines: `PARSE_RENDER_BUDGET` 10 s (parse + `validate_patch`), `GRAPH_SOLVE_BUDGET` 10 s (`Graph::build_from_patch` + `layout::solve`; release baseline ~0.4 s since the topology precompute fix, ~28 s before), `OPTIMIZER_BUDGET` 10 s (`optimize::generate_candidates`, MinMax scope). A fourth phase, `phase_scene_widths`, calls the width estimator 100 times over the scale anchor under the same 10 s budget (release ~0.03 s), guarding the O(n+e) rewrite above. The terminal render phase was removed with the teardown; the egui paint path is covered by the gui-module shape/label tests.

## 14. Architectural Decisions & Rationale

1. **Hand-rolled `.ini` parser over the `ini` crate** — preserves repeated section names (DROID patches repeat `[button]` etc.) and gives precise control over token extraction; the crate was removed from `Cargo.toml`.
2. **Boundary-aware hardware-token scanner** — a token starts at a letter (`B/L/P/O/I/E/S`) followed by a digit with a non-alphanumeric/underscore boundary before it, so internal variables like `_ENV1_DECAY_POT` are not misread as hardware tokens.
3. **Components grouped by physical controller** — `HwComponent.controller` ("P2B8", "Faderbank", …) drives panel grouping, mirroring the hardware layout (design.md Decision 3).
4. **Renderer owns layout; handler consumes geometry** — `component_rects` is written by the gui paint layer (`src/gui/*.rs`) each frame and read by `handler.rs` for mouse hit-testing, because only the renderer knows where components actually landed on screen. The graph surface extends the same pattern with `graph_node_rects` / `graph_cluster_rects` (ADR 22).
5. **Fresh layout per frame** — no resize state; `Event::Resize` is a no-op and the next draw reflows automatically.
6. **Chained panic hook** — color-eyre's hook restores the window/console state; a panic leaves a clean console.
7. **Shift groups as an enum** — `ShiftGroup::Group1–4` with `color()`/`key_label()`; panel borders and status bar derive from one source of truth.
8. **Vim-style `g` prefix with lazy timeout** — arming stores only `PrefixState { started: Instant }`; expiry against `PREFIX_TIMEOUT` (1 s) is checked when the next event arrives instead of running a timer thread, keeping the event loop single-threaded and synchronous. `g v` opens the source viewer; `g g` opens the graph surface (ADR 16); `g d` opens the B-patch picker for a diff (ADR 25).
9. **Embedded source viewer** — `g v` opens a source pane in the same window and `App`; raw lines and parser-recorded spans support selection jumps, occurrence navigation, modifier highlights, and minimap interaction without IPC or a process boundary.
10. **Boxed rendering gated on parse-time LED association** — a component renders as ONE bordered cell only when its `.ini` section carries an LED association (stored as `HwComponent.led`): a bare `led = L.N` entry, or a numbered circuit `ledN = L.M` param paired by shared numeric suffix with a same-suffix element entry (`buttonN`/`potN`/`encoderN`/`switchN`/`faderN`) as used by circuits like `matrixmixer` (the `ledN` value is authoritative for the LED token). The boxed path covers every control kind that can carry a resolvable LED association — button, knob/pot, encoder, switch, fader — each rendering its own state inside the box (ON/OFF with a glyph for buttons/switches, percentage for knobs/encoders/faders). The border uses the component-kind color; the label lives in the block's top title row and the single interior row holds state + the LED glyph (one state, not a duplicate textual LED state). LED-less components keep two-line text rendering; LEDs are never rendered as standalone cells. At cell widths narrower than the box content the cell either shrinks its content to fit inside a complete box or falls back to unboxed two-line rendering — it never emits partial border fragments.
11. **Class-based adaptive pane layout** — the main band is a full-height left big pane plus a right half that is one big pane or two stacked small panes (ADR 37); `App.layout: PaneLayout` (`src/panes.rs`) is the source of truth, the ratio lives in `PaneLayout.main_split_ratio` (default 0.5, clamped 0.3–0.7, mirrored to the legacy `viewer_split_ratio`), and `[`/`]` nudge the big boundary in exact 0.1 steps while `Alt+[`/`Alt+]` nudge the small-pane boundary.
12. **Semantic color-token layer** — every rendered color comes from `Theme` tokens in `src/theme.rs`; no hardcoded RGB outside tests. Built-in palettes `classic` (byte-identical to pre-theming colors), `terminal` (all `Reset`), and `mono` (grayscale, shift tokens pairwise distinct) are resolved by name and installed globally via `theme::init` at startup. Graph tokens cover node/port/cluster surfaces, edge kinds (`control`/`audio`/`midi`/`unknown`), the `graph_edge_error` highlight, the diff tokens `graph_edge_diff_added`/`graph_edge_diff_removed`, and the validation tokens `validation_error`/`validation_warning`/`validation_hint`/`validation_modal_border`/`validation_selected_bg`.
13. **XDG user config with injected validation** — `src/config.rs` discovers `droid-tui/config.toml` under `$XDG_CONFIG_HOME` (or `$HOME/.config`); name validation is injected as a canonicalizer function so the loader stays decoupled from the theme catalog. Missing file silently yields defaults; malformed TOML and unknown themes warn once on stderr and fall back to `classic`. `[labels] layers_enabled` (bool, default true) and `max_shift_layer` (u8, default 4, clamped 1..8 on load and on save) live alongside `theme`; disabled coerces `display_label` to layer 1 while preserving 2..N in `labels.toml`. `[latency] per_circuit` (map of lowercased circuit name → f32 `AVG` override, default empty = ramsize heuristic) feeds `latency::CostModel`, the shared cost provider for the latency ramp and the optimizer (design D2). Writes are atomic (temp-file + rename).
14. **Config load before the window opens** — `main()` loads settings and initializes the active theme before the window is created so warnings print to a clean console. The global theme lives behind a `Mutex<Option<&'static Theme>>` (not `OnceLock`) because test-ordering must not poison the palette across tests.
15. **Panel contains modules** — a controller panel whose components come from more than one circuit instance (detected via `HwComponent.module_instance()`, the leading digit run of the token id) is subdivided into per-instance module sub-blocks, each bordered and titled with the instance number (e.g. `P2B8 1`, `P2B8 2`); a single-instance panel renders as one flat grid and CV I/O never subdivides. Panel height is sized from the visible (LED-folded) component count so trailing rows like knobs are not clipped, and the published `component_rects` hit rects exactly match the rendered cell size (a prior scale-factor inflation spilled a hit rect into its neighbor's screen area, misresolving hover/selection).
16. **Signal-flow graph as a pane (`g g`)** — an optional view focused purely on signal topology, distinct from the controller-panel representation (the primary map to physical hardware). It opens as a big-class pane, keeps the header and status bars, owns mouse input inside its pane while focused (node dragging), and Esc closes the slot; `q`/Ctrl+C/`l` keep their global meaning.
17. **Cable attribution by section name, first-instance resolution** — the cable index records names, not instance indices, so repeated instances resolve to instance 0 for edge building; instance-accurate attribution is left to the topology-validation pass, keeping the convention consistent across the model.
18. **One-shot deterministic force-directed solver, not a simulation** — bounded refinement (≤ `SOLVE_ITERATIONS` 60 full, ≤ 40 local) until the energy threshold, then freeze; re-solve triggers are exactly two (patch load → full solve, node drag → damped local re-settle). Seed positions derive from the layered arrangement (topological depth + crossing-minimized within-layer order, no RNG); edges are sorted deterministically because the cable index is a `HashMap` with per-process-random iteration order and f32 spring-force accumulation is order-sensitive (design D9: same patch, same machine → identical layout).
19. **Grid-hashed repulsion** — repulsion is the O(n²) risk in force-directed layouts; uniform-grid cell hashing (cell = repulsion radius, rebuilt per iteration) restricts each node's repulsion to neighboring cells, keeping the 600-node case near-linear.
20. **Synchronous observer event bus** — `GraphRebuilt` / `NodeMoved` / `TopologyError` (and, since patch-validation and patch-diff, `ValidationCompleted` and `DiffComputed`) dispatched inline to `FnMut` subscribers in subscription order; no queueing or async, keeping the single-threaded event loop intact. It decouples re-solve triggers (patch load, node move) from both the solver and the renderer and gives topology errors a path to the status surface.
21. **Topology validation at graph build time** — the exactly-one-source rule runs as a build step: dangling sink → `Warning`, `n → 1` → `Error`, produced-but-unused cable → fine. Findings travel with the graph (never block building or viewing) and the renderer colors offending cables with the `graph_edge_error` token.
22. **Renderer publishes graph geometry per frame** — `graph_node_rects` and `graph_cluster_rects` are written by `ui.rs` each draw (mirroring `component_rects`) and consumed by `handler.rs` for node-drag hit-testing; `render_graph` splits `App` field borrows (`graph`, `graph_positions`, `graph_cluster_rects`, `graph_node_rects`) because rendering both reads and mutates the same struct.
23. **Per-patch label overlay (edit-in-place, no `.ini` mutation)** — `LabelStore` (`$XDG_CONFIG_HOME/droid-tui/labels.toml`, atomic tmp→rename, warn-once on corrupt TOML) keys buckets by canonicalized absolute patch path: `hw` per-`HwToken` per-`ShiftGroup` slot (`1..=max_shift_layer` uniform for all `B*`/`P*`/`S*`/`E*`/`I*`/`G*`/`O*`) and `circuits` per-`NodeId=(circuit,instance)`. `Patch::display_label` merges `store[layer]→store[1]→preamble[1]→derived` (empty `I4:` treated as absent) with `effective_shift` clamping and `layers_enabled` coercion; `circuit_label` is a single override for source header + graph node title in both FULL and FILTERED panes. `App.editing: Option<EditState>` holds `kind` HW/Circuit, `token`/`node`, `shift`, per-layer `drafts_by_layer` drafts and `draft`; overlay is the top z-layer eating all keys (priority overlay→picker→prefix→graph→source→panels), `e` enters for focused panel token / source header instance / `hovered_graph_node`, `1..N` cycles `N=max_shift_layer` preserving drafts, `Enter` saves + `recompute_influence` for `<token> / Group<N> → N ckts / M cables` status in `modifier_hue` (`graph_edge_error` red > modifier hue > `CableKind`), `Esc` cancels. No `.ini` mutation, no network, no async.
24. **Schema-authoritative validation (embedded schema, gating on Error)** — `src/schema.rs` embeds the vendored `ext/droid-lsp/droid-lsp/src/circuits.json` at build time (`include_str!`) as the single source of truth and exposes typed circuit lookups, prefix/count/start_at expansion, a jack table, and Levenshtein suggestion; `src/validation.rs` implements 9 checks ported 1:1 from `ext/droid-lsp/droid-lsp/src/diagnostics.ts` and returns `ValidationIssue{span,severity,code,message}` sorted by (line,col). `App::load_patch` runs validation on load and gates the patch on any `Error` finding (rejected → modal), while `Warning`/`Hint` findings still load and populate the list — so the app enforces a correctness floor without blocking useful inspection. `EntrySpan` captured by the parser routes each finding to its exact source location. A `Warning`/`Hint`-only load does not auto-open the modal (change `validation-modal-error-only`): it reports the count with a `press 'e' to view` hint in the status bar, keeping app chords (`g g`, `l`, `?`) live until the user asks for the list; the never-called `set_validation` helper was removed.
25. **In-process patch diff viewer** — `src/diff.rs` is a pure model (`DiffReport` of added/removed/changed cables + nodes) with no terminal dependency; `g d` opens the picker to choose the B patch, `load_diff_patch` computes the report once and emits `Event::DiffComputed`, `d` toggles the overlay, `Esc` clears the diff scope, and the graph colors cables/nodes by classification via `graph_edge_diff_added`/`graph_edge_diff_removed`. The diff is read-only and never mutates either patch.
26. **Learned wiring-outlier detection with preserved fallback** — `src/geometry.rs` hosts `WiringOutlierScorer`, a pure scorer over an embedded decision table (`tools/outlier_artifact.txt` via `include_str!`, schema.rs precedent) fitted offline by `tools/fit_outlier_model.py` on `corpus/features.csv` (28 rules, first-match-wins; gate precision ≥ 0.60 at recall ≥ 0.86 on holdout — fitted 0.824/1.000 vs baseline 8.0 rule 0.124/0.714). A table miss falls back to the preserved threshold rule (`euclidean > 8.0 && cable_hops == 0`, design D1); invariant guards (adjacent / co-located / via-cable) stay at the call site in `graph::validate_wiring_outliers` and never reach the scorer (design D5). The per-token influence second opinion (`patch::InfluenceStats`, embedded `tools/influence_stats.txt`) z-scores each token's `influence_subtree` size against per-kind corpus mean/std; tokens beyond the 3.0 band produce a `Warning` on the token's first root-var cable (design D4). Both channels reuse the existing `TopologyIssue`/`graph_edge_error` surfacing (ADR 21).
27. **Physical 1:1 layout as the main view (millimeter grid model + skeleton reference presentation)** — the wrapped-panel main view is replaced by a rack model in millimeters (`src/physical.rs`): one grid unit (mm), aspect-compensated mm→pixel mapping (columns/mm ≠ rows/mm so physical proportions survive the non-square cell aspect, D4), a viewport of pan offset + zoom (screen = mm × factor × zoom − offset, D5), and a data-driven per-controller geometry file with load-time validation and fallback (D6). The skeleton is a render *presentation* of the same layout, not a new surface (`s` toggles, D7); the rack is an ordered list of rows plus optional TE mount sections with auto-pack + per-module override (`[physical.rack]` config, D9/D10/D12); fold-bar dividers render at row boundaries in both presentations (D11). Zoom reuses the `+`/`-` scale presets `[0.75, 1.0, 1.5, 2.0]` with wrap-around (floor 0.75 keeps cells boxable); arrows/wheel pan only when the rack overflows, preserving their legacy navigation meaning otherwise. Module borders abut exactly at every supported zoom preset (edge-rounded mm→screen spans share boundary values — regression `adjacent_module_rects_never_overlap_across_zoom_presets`); each element renders its live state on its physical-view cell (buttons/switches glyph, knobs/encoders percentage, faders a vertical track proportional to value with an amber LED bar mirroring position, CV I/O direction); switch cells place per controller geometry and never collapse onto a neighboring control's cell when geometry lacks a matching switch cell; adjoined element-cell `component_rects` are clamped at draw time so distinct cells never overlap at any zoom preset (75 %–200 %).
28. **Signal-flow graph surface (egui canvas)** — the graph renders as an egui canvas inside its pane (or the desktop window opened at startup): nodes, directed cable edges, cluster containers, and labels are painted from the backend-neutral `SceneSpec` (src/graph_render.rs) under the pure `GraphCamera` (world→pixel `pixel = world × zoom − pan`, `pixel_to_world` inverse feeding `graph_node_rects` so drag/hover apparatus works unchanged). Canvas polish: middle-drag pan + cursor-anchored wheel zoom, marquee selection, a corner minimap with viewport indicator, and a hover tooltip showing the circuit name + latency readout. Every node/edge/label color derives from the active theme's semantic tokens via `Theme::egui_color` / `Theme::egui_from_rgb` (never hardcoded RGB) with the existing precedence (topology-error red > diff > latency ramp > cable kind) preserved. Node geometry is world-sized and projected through the camera (ADR 40): frames, corner radius, borders, ports, cable strokes, arrows, and cluster chrome scale with zoom under minimum render clamps, labels are fitted to their frame and dropped below a legibility threshold, and the fit camera frames the world bounds plus one node's extent.

29. **Graph layout rework (single-axis pipeline, pin anchors, cluster cohesion)** — the solver is re-seeded along one dominant left→right axis by topological layer instead of vertical cluster bands (D1), cable springs are raised (`SPRING_K` 0.05→0.15) and repulsion softened (`REPULSION_STRENGTH` 4000→1500) so edges read as the primary structure (D2), a `pinned: &[usize]` set acts as fixed solver anchors (D3 — `App.pinned: HashSet<NodeId>` persists across rebuilds, mapped to indices at solve time; the tip `graph.nodes[0]` is pinned by default, `p` toggles, drag auto-pins), banner groups get a weak centroid cohesion force and render as enclosing rectangles rather than layout stripes (D4), the camera fit is width-first aspect-preserving (D5). The `p` key on the graph surface now means pin/unpin (processing pause stays on `p` everywhere else); `+`/`-` cycle the persistent `GraphCamera` zoom presets and arrows pan the camera on overflow, mirroring the physical-view model. Manual placements survive (drag pin-places); pins are deterministic inputs (no RNG), so same patch + same machine → same layout. The optimal-node-arrangement change (design gv5) upgrades the seed to a layered (Sugiyama-style) arrangement: within-layer order comes from deterministic barycenter crossing-minimization sweeps (`CROSSING_SWEEPS` 8) instead of file order, coordinates land on the `GRID_SNAP` (10) grid with no jitter, the full solve is a bounded refinement (`SOLVE_ITERATIONS` 60) so the layered structure survives, and parallel edges between the same two circuits are normalized to one spring (a cable bundle is one connection).
30. **Select-state filtering (assumed select values, dim-vs-hide)** — `g s` opens a centered overlay listing the patch's discovered select signals (`patch::discover_select_signals`: Register/Cable kinds, inferred candidate values via `parse_candidate_value`, `1V` = 0.1); `[`/`]`/Enter cycle the selected signal's value, writing `App.select_state.state` and rebuilding the graph through `GraphOptions { state, hide_unselected }` (design C 1.1–4.1). Classification is per section (`classify_sections`/`classify_for_status`): `Selected` keeps full edges, `NotSelected` dims with `graph_node_dim` and drops controller register edges (except the shared pair reaching a controller node), `Unknown` (no select-param match) is always kept. `hide_unselected` (GraphOptions, off in the menu) additionally drops NotSelected circuit nodes. The state is deliberately in-memory per session — no persistence, no `.ini` mutation — and candidate values are evaluated left-to-right with no precedence via the new pure `src/expression.rs` evaluator (design C 1.1), which also serves any future `select`-param consumer.
31. **Upstream-dependency subgraph (`f` on the graph pane)** — `Graph::upstream_dependencies(root)` is a reversed-edge BFS over the full graph (cycle-safe) that terminates at controller and input-jack leaves; `App::apply_dependency_subset` builds a subset `Graph` from the resulting index lists (`internal_edges`), solves it as its own `layout::solve` (subset-relative pins from `App.pinned`), maps positions back into full-graph index space, and the renderer draws only the subset with a fresh camera fit. An active filter survives rebuilds (tension, select-state cycles) and clears when its root node disappears; `Esc` clears it before the pane `Esc` would close the view (design D 1.1–2.1).
- **Label guessing**: `Graph::guess_labels` assigns each circuit the nearest explicit upstream label — a deterministic BFS over producer edges that only traverses circuits carrying an explicit hardware label (`Patch::explicit_hw_label`), cycle-safe, so an unlabeled circuit inherits its closest labeled driver's name. `App::refresh_guessed_labels` caches the map on every graph build/rebuild and label save (cleared on patch load); graph node titles, viewer headers, and the sidebar resolve store→guess→raw.
32. **Deterministic column arrangement as the default graph layout (graph-column-layout)** — the graph opens in a column arrangement instead of the force convergence: circuit depth from the capped Bellman-Ford over circuit-only edges (`circuit_depth`/`depth_over`), dense-normalized columns `0..N-1` (`dense_columns`), controller/jack nodes in fixed outer columns (`assign_columns`), width-aware stacking from `estimated_widths` snapped to `GRID_SNAP` with no within-column overlap, and within-column ordering strict (file order) or barycenter (crossing-minimization sweeps), selected by `[layout] ordering`. Pinned nodes act as fixed-position anchors on the column path (`solve_columns_pinned`). The force solver is retained unchanged (tension, pins, drag re-settle) and reachable via the `h` toggle or `[layout] mode = "force"`; `App.solve_graph_positions` dispatches by mode.

33. **Panels always flow left to right (orientation toggle removed)** — the panel grid direction is fixed and the `o` portrait/landscape toggle plus the `App.orientation` field are gone. A second layout axis added nothing the physical 1:1 view and the class-layout panes did not already cover, and it doubled every panel-geometry test. (Partly superseded by ADR 38: the Panels view itself is now retired.)
34. **Held and latched modifier with a full-surface wash, and App-seeded label policy** — `hold_component` is the momentary mouse press (`Mouse Down` on a modifier-eligible cell, cleared on `Up`/`Leave`); `latched_component` is the latch (`m` on the hovered panel component, `Ctrl+Shift+Click`) and survives until `Esc`. Exactly one modifier is effective at a time (`active_modifier_var`); a second selection replaces the first and additive union stays aspirational. `recompute_influence` fills `modifier_influence` plus the cached `influence_subset`, and `Patch::influenced_hw_tokens` lists the cells a selection touches so the module UI and the source pane (raw and prettified) all dim the same set and wash the influenced ones in `modifier_hue`. HW labels resolve through the pure `Patch::display_label` against a `[labels]` policy now carried on `App` (seeded once by `seed_app`) instead of re-read from config per frame.
35. **Graph scenes paint in a pane and window input maps back through the pane origin** — `build_scene_spec(app, theme, pane)` takes the graph pane rect, and `graph_pane_rect(app, window)` derives it from `App::pane_geometry` — the class-layout source the `paint_panes` dispatch draws from and publishes as `pane_hit_rects` — not the legacy `tile_stack` slot mirror, so drawn geometry and hit geometry share one source (this fix is what lets `c` center the graph in its actual pane). The camera stays pane-relative, and the window path converts window-space pointer and wheel coordinates through `graph_pane_origin(app)` before hit-testing or zoom anchoring. `publish_window_canvas` skips publication while a graph pane is open, because writing the full-window size there would clobber the pane-local canvas that `c`/`Shift+c`, wheel zoom, and arrow-pan gating all read.
36. **One window-open path (`g w` removed)** — the `g w` toggle, `App.graph_window_enabled`, the `[gui] graph_window` config section, and the loop's toggle arm are gone. The window opens only through the startup request (`queue_startup_window_open` → `GraphWindowRequest::Open`), so no runtime path opens or closes it and `w` is unbound.

37. **Class-based pane layout replaces the tiled window manager (change `pane-class-layout`)** — the retired tiling model (a full-height left panel pane plus a right column of up to three stacked slots, `MAX_TILE_SLOTS`, `TILE_CAROUSEL`, the `\` left-pane quad split, the narrow-width collapse) is replaced by a class layout: every view has a `PaneClass` (`Big`/`Small`), the band is a left big pane plus a right half that shows one big pane or two stacked small panes (`has_small_view`), and views route to a pane of their class (`ViewType::class()` / `pick_pane_for`). `App.layout: PaneLayout` (`src/panes.rs`) is the source of truth; `tile_stack`/`FocusSlot`/the `showing_*` bools are compat mirrors re-derived by `sync_mirror`, and the quad state (`quad_active`/`quad_focus`/`left_split_active`) is retained but no longer painted or key-routed. Keys: `Tab`/`Shift+Tab` cycle focus (tree order, empty panes skipped), `r` rotates the focused pane through its class carousel, `z` maximizes (non-latching: clears on `z`, a focus change, and Esc-first), `Alt+b`/`Alt+s` swap same-class panes, and `Esc` closes the focused view (clearing maximize first) — the `\` split and the `g q` quad chord are gone. Geometry comes from `App::pane_geometry` (ADR 35).

38. **The physical module UI replaces the Panels view (change `module-ui-physical`)** — `ViewType::Panels` is gone (`ViewType` = Graph | SourceViewer | Physical | Optimizer) and `BIG_CAROUSEL` is `[Graph, Physical]`, so the physical view is the app's only hardware surface instead of there being two. Every element of a declared controller renders at its faceplate position with a type glyph, and unused elements are drawn dimmed and unlabelled because the geometry decides what exists, not the patch. LEDs fold into their element — B32/P2B8/P4B2 button faces, the M4 touch plate below each fader, an E4 ring of 32 registers, the P8S8 slider track, jack-side for master/G8/X7 — with an explicit patch pairing overriding the positional default; their brightness and colour come from the patch's LED registers (RGB devices render the patch colour, white-only devices brightness alone), the one deliberate carve-out from theme-token-only colouring. Master and master18 render as faceplates at chain position 0, replacing the CV I/O group. The view opens fitted to its pane width, ellipsizes labels and shows the full label on hover and in the status bar, and draws the shared pane frame titled `Module UI`. Every Panels interaction moved onto it (`j`/`k` and the arrows, `Enter`/`Space`, the wheel on knobs and faders, the `m` latch and modifier wash, the `e` label editor, shift `1`–`4`, the selected-circuit highlight), and `Esc` clears an active shift or modifier before it closes the pane. `RackLayout::pack` fills rows strictly top-to-bottom and always places a module wider than its row instead of skipping rows. A left-click on an element focuses it across surfaces instead of toggling state (changes `c4x`/`8ia`): `physical_spec` yields the true global `hw_components` index and anchors the rack at its pane origin, `paint_panes` republishes `component_rects` from the drawn cells each frame, and `handle_graph_window_frame` routes module-UI pointer hover/click; state toggle stays on `Enter`/`Space`.

39. **Graph minimap click-to-navigate (change `graph-minimap-click-navigation`)** — the renderer publishes the graph minimap's rect and its world→minimap transform (inner-panel origin plus scale factors) to `App` each frame, and a left-click on the minimap pans the camera so the clicked world point becomes the viewport centre at the current zoom. The click is consumed, so it never falls through to node selection, drag, or marquee; the rect is cleared when the graph fits and no minimap is drawn. Window-space clicks are converted through the pane origin and the published inner-panel origin rather than a hardcoded inset.

40. **Zoom-proportional graph node geometry (change `graph-zoom-node-scaling`)** — node bodies are sized in world units and projected through the camera (pixel size = world size × zoom), so zooming out shrinks the frames together with the spacing instead of collapsing the graph into a field of full-size overlapping boxes. A node's world width is the layout's own per-node width estimate (`layout::estimated_widths` — the same estimate the column arrangement reserves for it), so a drawn frame always fits its slot and the column arrangement never overlaps at any zoom. Corner radius, border width, port markers, cable strokes, arrows, and cluster padding/title scale with the same zoom under minimum render clamps; labels shrink to fit their frame, are ellipsized, and — together with port markers and cluster titles — are omitted below a legibility threshold. Node frames themselves are deliberately never clamped to a minimum size (that would reintroduce overlap), so at the zoom floor they scale to sub-pixel marks while the chrome keeps its minimum and the structure stays visible. The fit camera frames the world bounds expanded by one node's world extent on each axis, so a fit keeps whole node bodies inside the pane rather than only their centre points, and pointer hit-testing tests the same world-space extents (zoom-independent) with a minimum pixel hit size so very small nodes stay selectable. This supersedes ADR 28's fixed `GRAPH_WINDOW_NODE_W`/`_H` pixel frames.

41. **Module UI element click focuses across surfaces (select, not toggle)** — a left-click on a module-UI element is a *focus* gesture, not a state change: it focuses the pane, calls `select_component` (source-pane jump + influence recompute), and sets the status `Focused: <token>`; `Enter`/`Space` over the hovered cell keeps the state toggle (the old terminal `handle_mouse_event` toggle path is dead in the native window, so no live toggle behaviour was displaced). Three pieces make it work. (a) `physical_spec(app, pane)` maps each drawn cell back to its true global `patch.hw_components` index by token id — the physical chain clones components per module, so the module-local index is not the hit-test index — and folds the pane origin into the `ScreenMapping` offset; without that the rack drew and hit-tested at the window origin and only worked while the module UI sat in `BigLeft`. (b) `paint_panes` clears and republishes `component_rects` from the Physical pane's drawn cells each frame (the field had no writer in the native app, which is why the module UI was never clickable). (c) The graph side reuses the existing influence machinery instead of inventing a second highlight path — `recompute_influence` unions the element's own register entity (`extend_with_register_focus`: every `_REG:<token>` edge plus both endpoint `NodeId`s) into the influence subtree the renderer already consumes, so the register edge, its controller node and the reading/writing circuit light up alongside the downstream influence, and `center_graph_camera_on_nodes` pans the open graph pane onto those nodes. Selection emphasis reuses the existing hover backdrop (`CellSpec.highlighted` covers the hovered cell, the `selected_component` cell, and the `selected_circuit` cells) so the module UI keeps one selection language. A click never opens a closed pane — it stores the focus, and a pane opened later reflects it. Trade-off accepted: `selected_component` and `selected_circuit` stay independent, so the module UI can show the union of both highlights.

42. **Graph settle animation on open (change `graph-settle`)** — a freshly opened graph interpolates its drawn nodes from an 8 %-scale compact seed into the solved layout over 500 ms cubic ease-out, then freezes; the solved layout stays the source of truth and only display positions interpolate, so renderer and hit-testing read `graph_display_positions` and hover matches what is drawn. Rebuilds, restores, and drag re-settles stay instant and a node grab cancels the motion. Pure module (`src/graph_anim.rs`), no egui/winit dependency; the settle is the one deliberate exception to the no-animation design rule.

43. **Tree-derived guessed circuit labels with screen-space label sizing (change `label-guess-and-screen-scale`)** — `Graph::guess_labels` assigns each circuit its nearest explicit upstream label (deterministic BFS over producer edges, explicit-only via `Patch::explicit_hw_label`, cycle-safe); `App.guessed_labels` caches the map on every graph build/rebuild and label save, and graph titles, viewer headers, and the sidebar resolve store→guess→raw. Node titles render at a fixed 12 pt fitted to their frame with ellipsis and module-cell labels at a fixed 10 pt monospace across all zoom presets (font-constancy regression-guarded), so zooming never changes label legibility.

44. **Optimizer preview as latency-delta diff with retained focus (change `optimizer-click-focus`, as-built)** — the file-order per-edge latency baseline (`OptimizerDiffState{before_cable, before_latency}`, parallel to the deterministically-sorted edge vector with a cable-name guard) is captured on optimizer open; preview compares the rebuilt graph against it, colors worse-red/better-blue under the error/influence/disabled precedence, refits the camera, selects the first affected circuit for the cross-view jump, and hands focus back to the optimizer pane (a `select_circuit` focus steal broke `r` until this). Click row ≡ `Enter`; restore/close/patch-load clear the baseline. As-built supersedes the change's dual-SceneSpec proposal in `tasks.md`.
45. **Reorder-safe anchors, unconditional preview refit, arrange-cycle key (change `graph-arrange-cycle`)** — `solve_graph_positions` carries pinned anchors by `NodeId` (new index → id → old-graph position), so optimizer reorders never scramble placements; `optimizer_preview` refits unconditionally against the live pane rect (`refit_viewport`: live `pane_hit_rects` → published canvas → default, never skips); the graph-pane `a` key applies the active arrangement then advances the cycle `Column-Strict → Column-Barycenter → Force` (written back to `layout_mode`/`layout_ordering`, status names the applied arrangement, silent no-op with no graph). See `graph-arrange` spec.
46. **Exploded-label performance view (change `performance-view`)** — `p` on the Physical pane opens a pane-local performance view: compact centered rack (~1/4 pane area, user pan/zoom ignored) plus big side-bound callouts (`src/performance.rs`: quadrant side assignment, host-coordinate stacking, leader anchors; rects disjoint from rack and each other), joined to host cells by `performance_leader` leader lines; headlines resolve store → guessed → derived (DROID has no dynamic labels, so guessing is the headline content); activation animates live state in rack and callouts; `R` resets all element states (selection/focus/shift untouched); `Esc` exits. Other panes keep their `p` meaning.
47. **In-memory SysEx upload (change `midi-upload`)** — `src/sysex.rs` builds the send payload from the rendered in-memory patch (comment/whitespace/non-ASCII strip ported from `droidpatch`, `F0 00 66 66 50 … F7` framing); `U` opens a confirm modal (byte count + transport; `y` sends, `n`/`Esc` cancels silently); the send forks `amidi`/`sendmidi` (USB X7 autodetect + DIN, preflight probe, no-send path names what's missing) with an indeterminate waiting-bar progress state polled per event, a status verdict on completion, and child reaped/killed on quit. The bridge is one-way: nothing is ever read back. See `midi-upload` spec.

## 15. Constraints, Risks, and Technical Debt

- **`target/` partially tracked in git** (725+ files) — build artifacts committed at some point; `.gitignore` only covers beads/Dolt files. Hygiene debt; `git add -A` can accidentally sweep build output into commits.
- **`ext/droid-lsp` is a vendored git submodule** — the schema source of truth (`src/circuits.json`) and validation reference (`src/diagnostics.ts`) live in a large multi-project clone; the build depends on the submodule being initialized, so a fresh checkout must run `git submodule update --init`.
- **No README** — project has no user-facing documentation.
- **ARCHITECTURE.md / DESIGN.md** were placeholders until 2026-08-20; both now hold full generated content and are maintained incrementally.
- **Archived change `droid-patch-tui`** has 48 tasks never checked off in `tasks.md` (process debt; implementation is complete and tested).
- **Stale code comment in `graph.rs`** — the `Graph.validation` field's doc comment claims the slot is "always empty today" (reserved for task 2.2), but `validate_topology` already populates it at build time and the renderer already highlights offending cables.
- **Event bus has no production subscribers** — `open_graph`, drag-release, `validate_patch`, and `load_diff_patch` dispatch `GraphRebuilt` / `TopologyError` / `NodeMoved` / `ValidationCompleted` / `DiffComputed`, but no renderer/status consumer registers yet (design D6 extension point); topology findings therefore do not currently surface in the UI beyond the edge-error coloring, and validation/diff results reach the UI through direct `App` state rather than the bus.
- **Graph port markers are presence-only** — nodes show a left input port when they are edge sinks and a right output port when they are edge sources; exact per-parameter pairing is future refinement.
- **Validation modal and diff overlay are rich surfaces** — each is covered by unit/snapshot tests but not by full interactive end-to-end flows; the failure modal path (patch gated on Error) is exercised in tests but not smoked through a live window.
- **Hardware integration is one-way** — the app sends the in-memory patch via MIDI SysEx upload but reads nothing back: component state stays simulated, and firmware/SD-card flows remain future work.
- **Single-threaded redraw** — fine at current scale; no headless/scriptable mode.
- **Source pane scales with window width** — sidebar and minimap hide below their width thresholds to preserve a usable source area; very narrow windows show only source content.

- **Window-level app keys are not routed** — the native window reports a fixed `WindowGraphKey` set (`x`/`p`/`e`/`c`/`Shift+c`) plus mouse input, but app-level keys (`g` prefix, `q`, `Tab`, `Esc`) have no window path (bead droid_tui-80b); window-only surfaces cannot reach the picker, the pane carousel, or the view-closing keys.
- **Modifier wash re-derives per selection** — `recompute_influence` walks the cable index on every selection change and rebuilds the cached `influence_subset`; there is no incremental update and no cache across selections (one active modifier keeps the cost small today).
- **Element and circuit selection are independent** — `selected_component` (the module-UI element focus) and `selected_circuit` (the graph-node selection) are separate fields and neither clears the other, so the module UI can show the union of an element highlight and a circuit highlight; there is no single-selection invariant (changes `c4x`/`8ia`).

- **Pane-class migration debt** — `App` still carries the legacy `tile_stack`/`FocusSlot` mirror and the `showing_*` bools (re-derived from `layout` by `sync_mirror`, but still written directly by a few pre-migration call sites and reconciled back by `reconcile_from_mirror`). The retained quad state (`quad_active`/`quad_focus`), the `\` split (`left_split_ratio`/`left_split_active`/`toggle_left_split` plus its shadowed handler arm), and the `GRAPH_WINDOW_NODE_W/H` constants are removed, and the `keybinding` spec's split scenario now records the retirement as history — that half of the debt is resolved. The tile mirror itself is the remaining dead-ish weight, removable once the last call sites use `open_view`/`pane_geometry` directly.

## 18. Glossary / Acronyms

- **DROID**: Der Mann mit der Maschine — Eurorack modular-synthesizer controller hardware; patches are `.ini` files.
- **Hardware token**: address of a physical control in a patch, e.g. `B1.1` (button), `L1.2` (LED), `P1.1` (pot), `O1` (CV out), `I1` (CV in), `E1.1` (encoder), `S1.3` (switch).
- **Controller**: physical panel type — P2B8, Faderbank, Notebuttons, Encoder, Pot, Unusedfaders, etc.
- **Shift group**: a set of components whose behavior/labels change while a shift key (1–4) is held.
- **Source viewer**: embedded readonly source pane showing raw `.ini` lines or prettified circuit blocks, with sidebar, selection-driven highlighting, occurrence navigation, and optional minimap; opened with `g` then `v`.
- **Signal-flow graph view**: big-class pane opened with `g` then `g`; circuits as nodes, virtual `_cable` connections as directed edges, banner-group clusters as containers, laid out by the deterministic column arrangement by default (the force solver via `h` or `[layout] mode`); supports node dragging, topology-error edge highlighting, wiring-outlier detection, and diff coloring. Node frames are world-sized and zoom-proportional, with label level of detail at extreme zoom.
- **World-space graph geometry**: node bodies and their chrome are sized in world units and projected through the graph camera (`pixel = world × zoom − pan`), so a node's drawn size and its hit area both scale with zoom; a node's world width is the layout's per-node width estimate. See ADR 40.
- **Virtual cable**: a connection named with a leading underscore (e.g. `_PULSARCLOCK`) that a circuit produces via `output = _NAME` and others consume via parameters like `input = _NAME`; one source may feed many sinks, `n → 1` is invalid.
- **Cable index**: `Patch.cable_index` — map from cable name to producing circuits and ordered sink references, built at parse time.
- **Banner group**: the ordered circuit-section range owned by a `# ---- Name ----` comment banner (until the next banner or EOF); the implicit group before the first banner carries `banner: None`.
- **Cluster**: the graph's rendering of a banner group — a titled, bordered container around the member nodes' rects.
- **Force-directed layout**: the retained, non-default arrangement — a one-shot deterministic solver (spring attraction + grid-hashed repulsion + friction) that converges then freezes; reachable via `h` on the graph pane or `[layout] mode = "force"`; re-solved on patch load (full), node drag (local), or an arrangement switch. On the column arrangement the tension value is stored but has no effect.
- **Column arrangement**: the default graph arrangement — nodes in dense-normalized circuit-depth columns with fixed outer controller/jack columns, width-aware blocks, strict or barycenter within-column order (`[layout] ordering`), and pins as fixed anchors; no force relaxation (same inputs → identical positions).
- **Topology validation**: the exactly-one-source rule per cable — a dangling sink is a `Warning`, multiple sources are an `Error`; findings travel with the graph.
- **Schema-authoritative validation**: `src/validation.rs` validating a `Patch` against the embedded authoritative DROID circuit schema (`src/schema.rs`, compiled from `ext/droid-lsp/droid-lsp/src/circuits.json`) — 9 checks ported 1:1 from droid-lsp `diagnostics.ts`; `Error` findings gate the load, `Warning`/`Hint` still load.
- **EntrySpan**: the per-entry key/value byte spans recorded by the parser on `IniSection` (captured before lowercasing, alongside `header_span`/`raw_lines`); used to jump a validation finding to its exact source location.
- **Validation modal**: the centered full-screen overlay (opened with `e`) listing `validation_issues` sorted by (line,col) with severity badges E/W/H; `j`/`k` navigate, `Enter` jumps to source, `Esc` closes.
- **Patch diff**: in-process comparison of the loaded patch and a second B patch (`src/diff.rs`, `DiffReport`); opened with `g d`, toggled with `d`, colored on the graph via `graph_edge_diff_added`/`graph_edge_diff_removed`; read-only.
- **Rack geometry / wiring-outlier**: physical module slot layout (`src/geometry.rs`, loaded from `rack_geometry.json`) feeding `BindingFeatures` for the learned-outlier scorer; wiring-outlier classification is a learned decision table (`WiringOutlierScorer`) plus a per-token `influence_subtree` z-score second opinion (`InfluenceStats`), both surfacing `Warning`s through the `TopologyIssue` channel without gating patch loading.
- **Theme token**: a named color role in `src/theme.rs` (e.g. `knob`, `shift2`, `graph_edge_control`, `graph_edge_diff_added`, `validation_error`); rendering reads tokens, never raw colors.
- **config.toml**: user preferences file under `$XDG_CONFIG_HOME/droid-tui/` (schema: `theme` + `[labels] layers_enabled/max_shift_layer` + `[latency] per_circuit` + `[layout] mode/ordering` + `[physical]`/`[plugins]`).
- **labels.toml**: per-patch label store under `$XDG_CONFIG_HOME/droid-tui/` — `hw` per-`HwToken` per-`ShiftGroup` slot + `circuits` per-`NodeId`, keyed by canonicalized absolute patch path.
- **Label overlay**: centered single-field z-layer for HW per-shift / per-circuit labels; `e` enters, `1..N` cycles Group layer, `Enter` saves + `recompute_influence`, `Esc` cancels; hint/status in `modifier_hue` with `graph_edge_error` red precedence.
- **Prefix key**: an armed `g` waits up to 1 s for a follow-up key (`v` source viewer, `g` graph, `d` diff picker, `o` optimizer, `s` select state, `c` latency coloring); expiry is checked lazily on the next event.
- - **Held modifier**: the momentary modifier state a `Mouse Down` on a modifier-eligible cell starts, cleared on `Up`/`Leave`; stored in `App.hold_component`.
- **Latched modifier**: the modifier state `m` (hovered module-UI element) or `Ctrl+Shift+Click` starts and `Esc` clears; stored in `App.latched_component` and dropped on patch load. Exactly one modifier is effective at a time.
- **Modifier wash**: with a modifier held or latched, influenced cells render in `modifier_hue` and the rest dim, on the module UI and source surfaces. `Patch::influenced_hw_tokens` is the shared cell list and `App.influence_subset` caches the filtered graph.
- **Module UI**: the physical faceplate view (`ViewType::Physical`) — the app's only hardware surface since `module-ui-physical` retired the Panels view, opened at startup in the left big pane. See ADR 38.
- **Element focus**: the cross-surface selection a module-UI click produces — `selected_component` keeps the clicked cell highlighted on the faceplate, jumps the source pane to its occurrence, and lights the element's register entity (`_REG:<token>` edge + controller/circuit nodes) plus its influence subtree on the graph. A click selects; `Enter`/`Space` toggles state. See ADR 41.
- **Register focus**: `App::recompute_influence` unioning the selected element's own `_REG:<token>` register edge and both endpoint nodes into the influence subtree (`extend_with_register_focus`), so a register-bearing element with no root-var influence still highlights its graph entity.
- **Pane origin**: the top-left of the graph pane in window space. Window-space pointer and wheel input maps through it before hitting the pane-relative camera.
- **Viewer focus**: `ViewerFocus::Panels` (the module UI) or `ViewerFocus::Source`; controls whether module-UI or source-pane keys act. In the class layout, `App.layout.focus: PaneId` is the single-focus source of truth (`tile_stack.focus: FocusSlot` is a compat mirror) and `Tab`/`Shift+Tab` cycle it in tree order across the non-empty panes.
- **Tile stack**: `App.tile_stack` — the **compat mirror** of the class layout's open views (`slots: Vec<ViewType>` excluding the implicit module UI, `focus: FocusSlot`); re-derived from `App.layout` by `sync_mirror` and adopted back by `reconcile_from_mirror` for a few pre-migration call sites. It is **not** the source of truth (that is `App.layout: PaneLayout`); the old `MAX_TILE_SLOTS`/`TILE_CAROUSEL` slot caps are retired.
- **Class-based pane layout**: the main band model (`src/panes.rs`, `App.layout: PaneLayout`) — a full-height left big pane plus a right half that is one big pane (no small-class view open) or two stacked small panes; the source of truth for which view is open where, with the view lists, focus, maximize, and the two split ratios. Geometry comes from `App::pane_geometry`.
- **Pane class / pane id**: `PaneClass` is `Big` (full-height left pane, or the right pane when no small view is open) or `Small` (a quarter-height pane of the split right half); `PaneId` is `BigLeft` | `BigRight` | `SmallTop` | `SmallBottom`. `ViewType::class()` maps a view to the class it may occupy (graph/physical → big, source viewer/optimizer → small).
- **Event bus**: synchronous observer bus (`events.rs`) carrying `GraphRebuilt`, `NodeMoved`, `TopologyError`, `ValidationCompleted`, and `DiffComputed` events to subscribers.
- **egui / winit / wgpu**: immediate-mode UI, native window + event loop, GPU backend.
- **OpenSpec**: spec-driven change workflow (`openspec/changes/`, `openspec/specs/`).
- **beads (bd)**: Dolt-backed issue tracker used for task tracking.
- **Settle animation**: the 500 ms cubic ease-out interpolation of drawn graph nodes from a compact seed into the solved layout on a fresh graph open; display-only, cancelled by grabbing a node. See ADR 42.
- **Guessed label**: a circuit's inherited title — the nearest explicit upstream label found by `Graph::guess_labels` — used when the label store has no entry. Titles resolve store→guess→raw. See ADR 43.
- **Optimizer baseline**: the file-order per-edge latency snapshot (`OptimizerDiffState`) captured when the optimizer opens, against which each preview's rebuilt graph is compared for the worse-red/better-blue recolor and the first-affected-circuit focus. See ADR 44.
- **Performance view**: the exploded-label presentation (`p` on the Physical pane) — compact centered rack (~1/4 pane) with big side-bound callouts and leader lines; labels never enter the rack rect. `R` resets element states. See ADR 46.
- **Arrange key**: the graph-pane `a` binding — applies the active arrangement, refits, and cycles `Column-Strict → Column-Barycenter → Force`. See ADR 45.
- **SysEx upload**: sending the in-memory patch to DROID hardware (`U` → confirm → background `amidi`/`sendmidi` send with waiting bar and verdict). One-way only. See ADR 47.
