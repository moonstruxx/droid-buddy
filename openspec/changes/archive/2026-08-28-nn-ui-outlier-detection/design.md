# Design — 2026-08-28-nn-ui-outlier-detection

## Context

See proposal.md — Why. The current wiring-outlier decision is a two-line rule in `src/graph.rs` (`WIRING_DISTANCE_THRESHOLD = 8.0` over `BindingFeatures`) that scores precision 0.15 / recall 0.86 on the existing 4023-row labeled corpus (`corpus/features.csv`, generated by `tools/build_features.py`). `BindingFeatures` (src/geometry.rs) already carries the full feature vector: source/sink kind, coordinates, euclidean/manhattan distance, same-controller/same-rack, adjacent, cable_hops. The corpus rows share that exact shape. The invariant guard clauses already exist at the call site (adjacent / co-located skip).

Constraints shaping the approach: single-crate monolith, no runtime dependencies, no network, no async, deterministic everywhere (project D9), embedded-static-data precedent (`schema.rs::include_str!` of the vendored circuits.json).

## Goals / Non-Goals

**Goals:**
- Replace the 8.0 threshold rule with a compact learned decision artifact that beats it on the labeled corpus (gate: precision ≥ 0.60 at recall ≥ 0.86 on holdout).
- Keep the decision in-process, deterministic, dependency-free (embedded table + pure Rust scorer).
- Preserve every existing invariant: adjacent, co-located `L→B`, and via-cable bindings are never flagged.
- Surface a second, independent opinion (per-token influence z-score) through the same existing warning channel.

**Non-Goals:**
- No linfa/ONNX runtime scoring (documented future path).
- No render-buffer outlier detection (roadmap signal 2), no interaction telemetry (signal 3).
- No new runtime dependency, no schema change to `features.csv`, no `.ini` mutation.

## Decisions

### D1: Decision table as the artifact (not a tree, not weights)
Fit a **bounded-depth decision table** (≤ few KB) offline and embed it as a static string. Rationale: interpretable, trivially auditable, no float drift across platforms, and it degrades gracefully — a missing row falls back to the current threshold rule. Alternatives considered: logistic-regression weights (float-sensitive, harder to audit), an isolation forest (linfa dependency, violates non-goals), a hand-tuned rule patch (already proven inadequate at precision 0.15). The table's fallback row keeps the deterministic contract: same patch → same verdict on every machine.

### D2: Fit offline in Python, score in Rust
`tools/fit_outlier_model.py` (new, stdlib-only: csv/statistics) fits the table on the rebalanced `corpus/features.csv`, writes a holdout precision/recall report, and emits the artifact file consumed by `include_str!`. Rationale: the fit is a build-time/tooling concern; the runtime sees only a static string — the same embed pattern as `schema.rs`. The scorer in `src/geometry.rs` mirrors the feature computation already there, so fit-time and score-time feature math cannot diverge (the fit script replicates the geometry logic, as `build_features.py` already does).

### D3: Rebalanced label pool
`tools/build_features.py` currently samples BAD from a 7-entry pool (6 E-sourced, 1 B-sourced). Rebalance to cover near-distance false-positive terrain (cross-controller at moderate distance), non-E sources, and mid-range distances — the region where the 8.0 rule floods. Keep `random.Random(SEED)` determinism and regenerate `corpus/features.csv` in the same run. Rationale: a model trained on the current pool overfits the generator and cannot fix the precision collapse the exploration measured.

### D4: Per-token influence z-score as second opinion
Bake corpus per-token-kind mean/std of `influence_subtree` size into the binary (same artifact style as D1); flag tokens beyond a calibrated z-score band as a `TopologyIssue` Warning. Rationale: it is independent of the distance/cable features, catches a different failure class (implausible influence fan-out), and reuses the existing `graph_edge_error` surfacing with no new UI work. Alternative considered: a combined multi-signal model — rejected for this change (corpus for interaction/render signals does not exist; YAGNI).

### D5: Invariants stay at the call site, not in the model
The adjacent/co-located/via-cable guard clauses remain explicit in `src/graph.rs` before the scorer is consulted. Rationale: these are hard guarantees (never flag), while the learned artifact is a soft classifier — separating them keeps the model from learning to violate a physical invariant.

## Risks / Trade-offs

- [Artifact overfits the synthetic generator] → holdout split + precision/recall gate in `fit_outlier_model.py`; rebalance (D3) specifically removes the E-only bias.
- [Real-world outliers differ from synthetic BAD bindings] → the fallback row (D1) preserves today's recall floor; the z-score second opinion (D4) covers a disjoint signal.
- [Corpus regenerated under the same SEED still shifts labels] → CSV schema is unchanged; git tracks the diff so label drift is reviewable in PR.
- [Decision table rows miss a feature combination] → miss falls back to the threshold rule (D1), never to silence.
- [Fit is a new tooling surface] → stdlib-only Python, run deterministically, documented in tasks; no new CI step beyond the existing corpus regeneration workflow.

## Migration Plan

1. Regenerate the corpus with the rebalanced pool (D3) — `tools/build_features.py`, committed CSV diff reviewed.
2. Fit the artifact and evaluate against the gate (D2) — artifact file lands in `tools/` output.
3. Land the Rust scorer + embed + call-site delegation (D1/D5) behind the existing warning channel.
4. Add the z-score second opinion (D4).
5. Tests prove precision/recall and invariants (task 3.1).

Rollback: revert to the threshold rule is a one-line call-site change (the scorer returns fallback when the table misses); the old rule stays documented in git history.
